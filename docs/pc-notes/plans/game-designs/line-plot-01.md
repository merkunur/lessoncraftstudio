## §1 — Concept / world
A warm seaside line-plot game. The child MEASURES each object (its body IS its length) against a unit ruler — left end pinned at 0, a CLEAN one-tick whole-unit read (NO numeral printed under the object's right end — the child reads the POSITION, keeping the measure non-vestigial; the full numeric labels live on the PLOT). Then plots: the X is hung at the POSITION on a number line matching the measured length. The line plot keeps EVERY whole-unit position present-and-LABELED **including ZERO-COUNT interior positions** (the anti-bar-graph weapon). The bin of un-measured objects is OPAQUE/un-countable (Game-54 kill). A non-numeric, un-countable abundance vessel.

## §3 — THE ARCHITECTURE REWORK (the heart; the deepest flaw + fix)
**The critic's deepest catch — the VISUAL-REGION-COUNT cheat (Game-54 count-visible reborn at the READ step), and the ensemble CONFLATED two cheats.** A "position-requiring" read like "how many are LONGER than 6?" is answerable by **counting the X-marks in the right spatial region** (treating each X as a generic countable object past a gridline) — WITHOUT connecting each X to its measured VALUE. Region-counting on a correctly-ordered number line **gives the right answer**, so it hides as distribution-reading, and the TALLEST_STACK_SOLVER (which models the mode) is BLIND to it. **And the obvious fix is HALF a fix:** "position-requiring" is NOT one bucket — `longer-than`/`shorter-than`/`between` are **REGION-REDUCIBLE** (region-count and value-read are extensionally IDENTICAL on an ordered plot → you can NEVER make a solver fail on those types by tuning data; it's a question-TYPE problem). The M2 not-a-bar-graph proof does NOT cover this (a region-count USES the ordered scale → blind to the structural mutation). Two different cheats the ensemble merged.

**THE FIX — the VALUE_PERMUTE_INVARIANCE read taxonomy:**
1. **The verifier primitive `VALUE_PERMUTE_INVARIANCE`** — for each read TYPE, permute which VALUE each X encodes while keeping the marks' left-right ORDER fixed; if the oracle answer is INVARIANT → the read is **region-reducible → Tier-1 scaffold-only**; if it MOVES → **value-irreducible → Tier-2 load-bearing**. This is the single mechanical test that sorts the whole taxonomy (and any future read type).
2. **Three tiers, gated by tier (not a flat "position-requiring" flag):** **Tier-0** (bar-graph-passable: most-common / how-many-at-N) ≤1/session. **Tier-1** (region-reducible: longer-than / shorter-than / between) ≤1/session, scaffold-only. **Tier-2 (value-irreducible — DOMINATES, ≥3/session):** **longest-minus-shortest** (read the VALUEs at the extremes + subtract) · **how-many-more-at-NAMED-A-than-NAMED-B** (locate two values BY LABEL, not a region) · **place-missing / fix-misplaced-X** (read the X's claimed value vs the object's measured length) · **identify-the-value-at-a-described-X** (NEW atomic decode: "the X furthest right — what length did that object measure?").
3. **Bind measure→read** (the generate-clause was vestigial): the load-bearing reads ALWAYS interrogate the plot the child JUST BUILT this session (NEVER a stranger's pre-built plot as load-bearing); the `describeDistribution()` text is FIRST-PERSON ("you measured two objects at 5 cm…"); one per-session measurement-callback ("you measured the shell as 7 — point to its X → now, how many are longer than YOUR shell?") binds my-measurement → this-X → this-read.

## §4 — Anti-cheat architecture (the gate)
- **VISUAL-REGION-COUNT (the deepest cheat) — killed** by §3: `READ_VALUE_IRREDUCIBLE ≥3` + `region_reducible_reads ≤1` (classified by `VALUE_PERMUTE_INVARIANCE`) + a **session-granularity `VISUAL_REGION_COUNT_SOLVER`** (counts marks in a spatial region, ignores labels/values; it correctly STILL passes the Tier-1 scaffold reads — that's WHY they're demoted — and MUST fall below the oracle by the Tier-2 fraction across the session).
- **TALLEST-STACK / COUNT-OBJECTS / SKIP-MEASURE / POSITION-IGNORANT — killed:** mode non-extreme (`MODE_NOT_THE_ANSWER` on load-bearing rounds; most-common EXCLUDED as a control) + `TALLEST_STACK_SOLVER session-accuracy ≤ 1/#read-types` (per-type logged); opaque bin (`COUNT_OBJECTS_SOLVER` fails); the X born from the child's `measure()` (`SKIP_MEASURE_SOLVER` rejected — `plot()` needs `measureState`; a mis-measure → mis-placed X → wrong; `MEASURE_LOAD_BEARING`); snap-to-tick exact-position (`POSITION_IGNORANT_SOLVER` fails; `POSITION_ENCODES_VALUE`). BIAS/FIRST/RANDOM baselines fail.
- **NUMERAL-MATCHING at placement — killed:** `AUTHORED_DISTRIBUTION_HAS_INTERIOR_GAP` (≥1 zero-count interior position flanked by non-zero) + ≥1 placement round targets a value ADJACENT to a gap (no neighbor to copy → the child must reason about ORDER, not match a numeral). + no-numeral-under-the-measuring-object's-right-end (the measure reads position, not a give-away).
- **Structural asserts:** `ANSWER_DERIVED_NOT_STORED` (answer = `oracle(objects.length, question)`; the M2 non-mode-mutation = the not-a-bar-graph proof), `VESSEL_NOT_A_TALLY` + `NO_REMAINING_COUNT_LEAK` (no "X of Y" / depleting countable affordance leaks the session length), ≥7 variety (≥4 question types incl. ≥3 Tier-2; **≥3 distinct distribution ARCHETYPES** — tight-cluster+outlier / bimodal / right-skew, not 3 draws of one shape). ORACLE passes 100%.
- **Wrong-tap re-show — no-reveal:** placement error → highlight the object-length↔matching-tick; read error → dim ≤threshold + pulse the right region (Tier-1) / re-highlight the two named values (Tier-2); never states the number.

## Cohort doctrine this game adds
**The READ-TAXONOMY / VALUE-PERMUTE-INVARIANCE lesson — PROGRAM-WIDE.** When a data / graph / measurement-display game lumps its "load-bearing" reads into one bucket ("position-requiring", "uses the scale"), AUDIT each read TYPE for whether it is **REGION-REDUCIBLE** (the answer is a spatial sweep that COINCIDES with the value-read on an ordered display — the two algorithms are extensionally IDENTICAL, so the cheat is UN-fixable by tuning data; it's a question-TYPE problem) or **VALUE-IRREDUCIBLE** (the answer requires locating NAMED values / reading the value AT a position — a spatial region-count gives garbage). The Game-54 count-visible-objects cheat hides in the region-reducible reads at the READ step, and a "derived-not-stored / not-a-bar-graph" structural proof does NOT cover it (a region-count USES the ordered scale → blind to the structural mutation — these are two different cheats; do not conflate them). **The mechanical sorter: the `VALUE_PERMUTE_INVARIANCE` test — permute which VALUE each mark encodes while keeping the marks' spatial ORDER fixed; INVARIANT oracle answer → region-reducible → scaffold-only; the answer MOVES → value-irreducible → the real assessment.** The fix: classify reads by this test, make the value-irreducible tier DOMINATE the assessment (≥3/session), demote the region-reducible reads to ≤1 scaffold, and assert a region-count solver at SESSION granularity (it correctly STILL passes the scaffold reads — that is WHY they're scaffold — and must fail the session because the value-irreducible tier dominates). Generalizes to EVERY data/graph/measurement game in the catalog: "uses the scale" is not enough — the assessment must require reading the VALUE the position encodes, not sweeping a spatial region the ordered scale makes coincide with the answer. (Companion: bind GENERATE→READ — if the child measured the data, the marks are THEIR measurements [first-person), not generic objects to count; a read over a stranger's pre-built plot re-opens the count-visible cheat.)
