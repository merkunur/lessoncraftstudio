## A bank fact the design missed (measured 2026-09-21, scratch `probe2.js`): `tree` ≡ `arrow`
`arrow` is `tree` turned 270° (same silhouette as a point set under `rot270` and `mirA`; the TILINGS differ, so the seams differ). Every other pair of figures, minis and subs is pairwise non-congruent under the 8 lattice transforms. Consequences, each built in: F2 never draws both (one shadow class); F3 caps a page at `ceil(items / shapes)` cards per shape class (2 per shape over 6 cards); F4 keeps both figures (their seams differ, each row is its own puzzle) but never two rows whose shadows AS DRAWN coincide; the first F2 render (`G1-354-null-d2-en.png` before the fix) showed the same shadow twice, turned, which is how the fact surfaced. The base's `BASE_POOL` (2 of 5 with seams) is untouched. A data-gate rule for it is a follow-up for the figures gate (the qa gate asserts it on every render).
