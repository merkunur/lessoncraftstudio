# METHOD — Find the Differences (the template for every future expansion)

Operator OBS (2026-10-09): *"document the methods you use for creating these worksheets in detail because they will also serve as templates for future expansions."* This file is that record for `find-the-differences` (K-395 + 10 faces). Sections 1–4 are final (the engines); 5–9 are completed as the batch ships. Every claim here was measured on 2026-10-09 unless marked (build).

## 1 What a page is
Two pictures of the SAME scene; the second carries N crafted differences; the child circles them (paper), or taps them (screen); the answer key is picture 2 with coral rings. N is printed in the title where the face is count-led (3 / 5 / 7 / 10) and IS the number on the page (gated). Every deck of the family ships PDF + screen + answer key (the family is in `INTERACTIVE_PRINTABLE_FAMILIES`).

## 2 Where the pictures come from — and only from
The image library's B&W line drawings (`scripts/worksheet-gen/cache/themes/<dir>/<noun>@3x.webp`), already reviewed as Color by Number scenes (`data/cbn/lineart-scenes.js`: 100 SCENES = a ground line + props + a hero; 100 SECOND = one hero on a themed ground). Nothing is drawn by hand. Colour pages use the crayons the operator reviewed on the Color by Number answer keys (`data/cbn/lineart-colours.js` via `lib/cbn-render.js`).

**To add a scene:** add it to `lineart-scenes.js` (or a new `data/fd/scenes-extra.js` with the same shape: `{id, theme, hy, lines, items:[{src,x,y,h,…}], fixed}`), OPEN every drawing it uses on a contact sheet (`scratchpad/props-sheet.js` pattern: `node … "<dir>/<noun>" …` → PNG → read it), run the builder (§3), read the scene's sheet (§4), record refusals in `data/fd/review.js`.

**To add a prop** (for ADD / SWAP / densifying): open its picture, then add it to `data/fd/props.js PROPS` (`place` sky|ground, `h` in units, `colour` plan largest-part-first, `alt` swap partners of the same kind and size) and to the themes' lists in `THEME_PROPS`. A prop is never added unseen: `tools/fd-build.js` refuses a src missing from PROPS.

## 3 The engine (how a difference is made)
- `lib/fd-scene.js buildLayers(spec)` composes the background (ground lines → sky / ground / pond regions coloured by the scene's fixed points) and EVERY drawing alone (`lib/cbn-lineart.js compose` + `segmentInk`), so each drawing is a layer `{idx, src, bbox, regions[{d, colour}], ink, asym, inkUnits}`. Colours: a drawing standing exactly as in the reviewed Color by Number key inherits each region's crayon by sampling the painted key at the region's deepest point (`cbnSampler`); any other drawing follows its plan (`HERO[id]` / `BG[src]` / `PROPS[src].colour`) by part rank, small pieces taking their big neighbour's crayon, pieces under 3 units white.
- A difference is ONE op on ONE layer (`applyOps`): `remove` · `add{layer}` · `swap{layer}` (same kind, same place, same size) · `mirror` (about the drawing's own centre; refused when the silhouette's mirror IoU shows `asym < 0.12` — a sun or a cloud mirrored reads as the same drawing) · `move{dx}` · `scale{s}` (about the bottom-centre; 1.22 / 0.8 hero, 1.35 / 0.72 prop) · `detail{layer}` (one INNER part's outline erased so it merges with its neighbour: a window pane, a spot — never a part that touches the paper) · `colour{region, colour}` (one part to a contrasting crayon; colour pages only). Layers are drawn back to front with opaque fills, so a moved hero occludes what is behind it exactly as the composed scene did.
- `tools/fd-build.js` writes `data/fd/<id>.json` (not committed; rebuilds byte-identically) with every CANDIDATE op that passed the **raster gate**: left and right rendered by sharp at 1 px per unit, subtracted, the changed pixels dilated by 5 and counted as components — `remove / add / swap / detail / colour` must be exactly ONE component with min side ≥ 16 units and area ≥ 260 units²; `mirror / move / scale` may be several components (the whole drawing moved) but the drawing's new place must stay inside the frame and must not overlap another drawing it did not already touch; every change box inset ≥ 8 from the frame. Each candidate records `bbox` (the drawing's place in picture 2), `diff` (the change box), `area`, `mode` (`any` | `colour`).
- `--rich` writes `<id>-rich.json`: the scene densified with up to 9 theme props at free spots (sky and ground alternating, placed BEFORE the hero so the hero stays in front; colours inherited only for the reviewed drawings; a scene that cannot take 3 extras gets no rich copy). Measured: a reviewed 4–5-drawing scene separates 3–4 rings; densified scenes (9–10 drawings) carry 5 and 7; ten needs ≥ 12 drawings or the stacked layout (px/unit 1.1) — (build) records what the 10-face finally used.
- `lib/fd-compose.js pickOps(scene, cfg, rng)` picks a page: one op per drawing; no kind more than a third of the page; rings (the change box inflated by 10 units) separated by ≥ `minSepPx` (24 printed px); far moves (change box > 1.8 × the drawing) excluded; spread over the quadrants (n ≥ 4 → ≥ 3 quadrants; n ≤ 3 → all different); `needColour` for the colour face; up to 60 shuffled restarts, then a REFUSAL (the face takes the next scene). Hotspots = the rings (`data-lcs-fd-diff`) + a decoy on every unchanged drawing.
- `lib/fd-browser-diff.js browserDiff(opts)` runs INSIDE the rendered page (`verify()`): both panel SVGs are drawn on canvases at the printed scale (hotspots and rings stripped), subtracted, dilated 3 px, counted; every visible change must sit inside exactly one difference hotspot, every difference hotspot must hold a change, no decoy may touch a change, hotspots ≥ 24 px apart. Poisoned 2026-10-09: a stamp removed, an undeclared change, a stamp without a change — each caught; the correct page passes.

## 4 The human read (never skipped)
`node tools/fd-sheets.js [--only=…] [--mode=colour]` → `%TEMP%\spl\fd-sheets\<mode>\<id>.png`: the base scene, then every candidate's right-hand panel with its ring, captioned with the kind and the measured area. Read at least the scenes a face will pin, in BOTH modes, and the rich copies. Refuse a scene or a candidate in `data/fd/review.js` when the change reads wrong to a six-year-old (a bird in the pond, a prop in the sky's wrong band, a scene whose extras look dumped). The read of 2026-10-09 (farm-cow, garden-cat, pond-duck, forest-fox, garden-bird, winter-snowman, sea-fish, town-bus, farm-cow-rich): colours match the reviewed keys; refused classes found and fixed at the ENGINE: mirrored near-symmetric props (now `asym`), a hero jumping its own width (now excluded), a detail op opening a part to the paper (now inner parts only), the colour op wiped by a second op on the same drawing (now one op per drawing).

## 9 Traps paid for (running list)
- The CBN colour keys are the SCENE ids: a densified scene must carry `base:<id>` and inherit only identical drawings.
- A mirrored sun passes a pixel-diff gate; the honest test is the asymmetry of the SILHOUETTE (`asym` ≥ 0.12).
- Reviewed scenes hold 4-5 drawings: 7 and 10 differences need the densified `-rich` copies, and 10 needs TWO pairs.
- `tools/fd-build.js` placed the standing chick in the sky (a prop placement rule read the wrong band): 137 rich records had to be rebuilt — every pin measured on the old data was provisional, and four moved.
- **The rebuild changed every pool: measure again, never trust a design-time pin.** base lost its hero (19 % → `heroFront`), the beach pair stopped composing 5 at the G2 floor, the bunny's tulip changed on 88 % of pages, the rooster's props never fell in one quadrant.
- `lib/b7-common.js bankModule()` takes the module's FIRST export as the locale map.
- A mode whose count comes from the rng (how-many) must draw it BEFORE the composer, in the plan, so the oracle's replay sees the same draw.
- The screen's runtime answer map reads the page's `data-lcs-fd-diff` stamps (the chips, the word rows); the robot's oracle recomposes — both are needed, and the print page carries neither.
- A WHOLE-drawing change (a mirrored hedgehog, a shrunk sun) is many pixel patches inside one box: the browser diff must run at the builder's scale (1 px per unit, dilation 5) and merge intersecting patches, or a correct page reads "4 differences, the page says 3".
- `renderPanel`'s `viewBox` is `[x, y, w, h]`; the window placer's box is corners — passing corners made row 1 half as tall and row 3 run off the page.
- A random 3 × 3 cell on a big ring lands the ring on the window's edge (164 of 200 tries): pick the cell INSIDE the valid origin range, never clamp after the fact.
- A change touching the scene's rim can never keep its air inside a window that sits 8 units inside the frame: filter the rim OUT of the pairs pool (20 units) — every scene refused until it was.
- A sweep that judges a face's windows AFTER counting the page as ok reports 236 units in band for a face that composes on 0: judge everything the page needs before `ok++`.
- The gate's `scale` for `evalSource` is CSS px → canvas px; a close-up window's units are its viewBox width, not 600.
- **The robot gate on the GENERATED decks (`qa/verify-interactive.js <pool>`) is not redundant with the family gate**: it measured decoys of 43 × 85 px and 34 px chips at a 360 viewport — the runtime scales the whole page CROP (~735 px) to the viewport, so a 44 px target needs ≥ 90 page px (decoys ≥ 92 units; chips and word rows 96 px). The family gate measured hotspots in page px against 86 and passed them all.
- The pairs face's oracle read `panels[row]` — one scene, three rows: rows 1 and 2 were "false" and the robot never reached the celebration. The row's ring is `rings[wins[row].op]`: replay `placeWindows` after `composeAll` on the same rng (the plan carries `window`).
- A comment appended to a one-line `{ ... }` block swallows the rest of the line (twice in one day: a bank's `'mirror-pair'` pin vanished, a gate's poison line parsed as `finally` unexpected). Comments go on their own line; the bank now has a rule "every mode has a pinned unit".
- `manifest.printable_only` stays `true` on every worksheet-gen deck (the Level Set convention); what makes a deck interactive is `manifest.interactive.kind` + `answer-key.pdf` in the ZIP; the bundle's items live in deck.html (`DECK_BUNDLE.items`, answers in `answers[]`), the manifest carries the kind only; the SEO description lives in deck.html's `<meta name="description">` — `tools/check-b7-zips.js` reads all three there.
- **A hypernym and its hyponym on one word strip = two right answers.** The es + pt panels read a tulip changed beside a daisy drawn as 'flower' (and the same for bird / hummingbird): a child who ticks 'flower' is right by their own reading. Rule (bank `WORD_FAMILY` + `clashKeys`): on the word faces the GENERIC member of a family with two members in the picture is never changed and never listed, and an add / swap never brings in a key whose family the picture already holds (two tulips make 'the tulip is new' name two things). Withholding BOTH members starved the faces (1 scene in band of 171); withholding the generic one alone keeps the specific word unambiguous.
- **The word faces moved from plain to RICH scenes** (design §3 F6/F10 said plain): once the generic word is withheld a plain scene holds 4 usable nouns for 3-4 changes, so sun / cloud changed on 90-100 % of seeds (measured at 60 then 400 seeds). The strip is CAPPED at `WORD_CAP = 6` (every changed noun + seeded decoys), which is what the design feared a rich scene would break. Pins: what-changed `kangaroo-rich` (400/400, hero 34 %), write `elephant-rich` (hero 34 %, quadrants 25/25/25/25) — a giraffe scene that was in band at 60 seeds read bird 87 % / cloud 86 % at 400: **pin on the 400-seed run, never the 60-seed sweep.**
- **The write face needs room for a TWO-line change-word strip**: adding the seventh change word ('changed', the swap kind) wrapped the strip and put the stack at 705 px (> 677). Pictures 280 px + rows 40 px. Other locales wrap regardless (de 'verschwunden', 'gespiegelt').
- **Three apparatus strings the panels caught**: the colour and mirror faces print a ledger of tick boxes the EN instruction never named; the pairs face said 'circle the one THING' while the face admits `remove` (the thing is an empty place → 'the one place'); the EN title was the only one in the catalog spelling 'Colour' (the EN market types 'color'; 20 titles say Color). A draft string lives in `types[id]` AND the bank block — edit BOTH (the parity gate caught the fr scene string; `check-b7-string-parity` compares the bank to the built i18n).
- **Two panels, two countries, the same defects** — the es-MX and pt-BR panels filed the swap-into-an-existing-noun and the pond-bank defects independently, both from READING THE RENDER against the model. Brief every panel as an auditor of the English source.
- **The six tap strings live in TWO places and the generator reads only one.** The panel draft puts them in the bank block (`data/b7/locales/find-the-differences.<loc>.json → tap`), but `cli.js` and `b7-sweep-renders.js` read `i18n/interactive-instructions.json`; de and fr generated 0 FD decks ("no interactive instruction find-the-differences.fd-tap for de") until `apply-b7-locale.js` also wrote them there. That file is CRLF with a ONE-space indent — write it back in its own format or the diff is the whole 4,700-line file.
- `gen-b7-waves.js` must pin a UNIT per spec (`unitOverrides`, a pair face as 'a|b') and set `interactive: true` — the b6 clone knew only themes; a pair face inherits the base's `unit` through the spread, so `units` must win.
