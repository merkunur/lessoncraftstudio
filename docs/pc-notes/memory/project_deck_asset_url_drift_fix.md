**Root cause (empirically confirmed):** ~8,831 non-EN published decks (de 1965 / pt 2234 / fr 1858 / it 1296 / es 1362 / ~29 each da/fi/sv / 28 nl / 1 no; en 0) had DB columns `pdf_url`/`answer_key_url` carrying the LEGACY English exercise-mode filename (`…-make-whole-…-printable.pdf`) while the deck `slug` + on-disk dir + actual files use the LOCALIZED mode (`…-complete-…`). A 2026-06-20 script (`fix-deck-pdf-filenames.py`) renamed the on-disk FILES to canonical `<slug>-printable.pdf` but NEVER updated the DB columns. Deck cards render `deck.pdfUrl` straight from the DB column → 404. Landing pages reconstruct `deckAssets(slug).pdf` → 200 (that's why "landing links work, card links 404, different slug"). Plus 50 es `chart-count` decks (`contar-en-grafico-*`) with the §22.4-class theme-emit bug: DB slug = correct theme (`frutas`) but URL columns embed the wrong `accesorios` directory.

Operator ruled ACCEPT (no UX change). Also NOT a bug: `apparier-les-ombres-complete-…` slug — shadow-match app legitimately has a make-whole/complete mode (slug = `<type>-<mode>-<theme>`).

**Key facts:** 45,309 published decks (~90k PDFs). On-disk residue = 0 (every `<slug>-printable.pdf`/`-answer-key.pdf`/`thumbnail.png` exists). Sitemap shards emit NO pdf URLs (PDFs noindex §17.8.20); GSC's pdf 404s come from deck-CARD links + historically-indexed `make-whole` URLs. NO rendering surface uses the raw `htmlUrl` column — Play links/sitemap/iframes all derive from slug.

**FIX = derive asset URLs from slug, not the DB columns** (drift-proof). Helper `canonicalDeckAssets(d)` in `frontend/lib/seo/landing-content.ts` (next to `deckAssets`). Applied at 9 surfaces: `topic/[slug]/page.tsx`, `topic/[slug]/[secondary]/page.tsx`, `learn/_shared.tsx` (card DTOs, spread); `components/catalog/VarietyStrip.tsx`, `lib/exercise-mode-universe.ts`, `lib/breadth-grid-selection.ts`, `worksheets/page.tsx` (thumbnail); `api/collections/[id]/route.ts` (thumb+pdf).

**ADDENDUM 2026-07-05 — legacy ENGLISH-SLUG PDF *URL* redirect fix (the OTHER half; DONE + deployed + verified).** Operator: "thousands of broken pdf links" with examples. Distinct from Parts 1-4 (those fixed the DB *columns* / live on-page links, which are now slug-derived → 200). These broken URLs are the **legacy English-slug URLs still in Google's index / backlinks / embeds** left by the native-slug migration: each re-slugged deck has an English-named **directory symlink** (`buchstabensalat-easy-formen-fcbc -> buchstabensalat-leicht-formen-fcbc-v1`) but the PDFs inside are **native-prefixed** (`…-leicht-…-printable.pdf`). Live behavior before fix: `<alias>/<alias>-printable.pdf` → **301 to ITSELF (infinite loop)**; bare `<alias>/printable.pdf` → **404**. Root cause: the two nginx make-whole PDF rules reconstruct the canonical filename from `$2` = the URL dir segment (= the OLD English slug for an aliased deck), so the reconstructed name doesn't exist → loop/404; they never resolve the symlink to its native basename, and the `$deck_redirect` map (`gen-old-slug-redirects.js`) had **only page keys, no asset keys**. Scale: **8,957 aliased decks** (de 1967 / pt 2286 / fr 1859 / es 1370 / it 1296 / en 63 / nl 28 / sv·da·fi 29 / no 1).

**FIX (2 files, commit `229cbfa0`):** (1) extended `scripts/publish-cli/gen-old-slug-redirects.js` to also emit PDF asset redirects (both `<alias>-<kind>.pdf` and bare `<kind>.pdf` forms → canonical `<native>/<native>-<kind>.pdf`; printable always, answer-key verify-before-point via `fs.existsSync`) into the SAME `/opt/lessoncraftstudio/old-slug-redirects.map` (`$uri`-keyed, feeds the existing `$deck_redirect`); map grew 17,914 → 53,740 lines. (2) NEW idempotent marker-guarded `scripts/publish-cli/patch-nginx-pdf-deck-redirect.py` injects `if ($deck_redirect) { return 301 $deck_redirect; }` as the first line of the **4 deck-PDF location blocks** (regex matches only openers ending `.pdf$ {`/`.pdf)$ {` — excludes the png/jpg/…/pdf catch-all which ends `svg))$ {`), so a mapped alias PDF `$uri` 301s to native BEFORE the buggy make-whole logic; non-aliased decks (empty `$deck_redirect`) unchanged. **map_hash sizing:** the tripled map needed `map_hash_bucket_size` bumped **256→512** (with `map_hash_max_size 262144`) at the TOP of `/etc/nginx/sites-enabled/lessoncraftstudio` (lines 1-2, pre-existing from the 2026-07-03 bot-limits work) to clear the `could not build optimal map_hash` warn — bucket_size was the lever, not max_size. These nginx.conf/site-config sizing edits are server-side-only (not in git, not in any patcher) → re-apply if the site config is ever rebuilt.
