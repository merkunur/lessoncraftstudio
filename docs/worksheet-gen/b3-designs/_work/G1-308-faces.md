## The five faces

### G1-338 — Read and Circle — PARAM (F1, RF.1.4)
- **Row:** `{...base.d2, verbs:['circle'], cues:['unique','all'], minVerbs:1, maxPerVerb:6, maxPerCue:6, maxPerPair:6, ordMax:0, nounsMin:6, nounsMax:6, maxCount:3}`.
- **Child:** the FRAME rung — every row says "Circle …"; only the noun phrase carries meaning. Six nouns over eight tiles (`[3,1,1,1,1,1]` → 5 unique + 1 all; `[2,2,1,1,1,1]` → 4 unique + 2 all) = **8 rings over 8 tiles on every page** (gate-asserted per render: the union of targets is the whole strip).
- **Knob:** `maxPerPair` — the base composer's "(action, cue kind) distinct across rows" rule makes a one-verb page impossible (two pairs, six rows); the design's F1 is PARAM only with this one additive resolved key (default 1 = the base rule; stamped `data-lcs-maxperpair` only when declared). `nounsMin` is 6, not the base's 5, because 5 nouns seat at most 5 disjoint circle rows.
- **verify():** the base branch (every action ∈ config verbs = `circle`; cues ⊆ unique/all; targets disjoint + re-derived; pairs ≤ maxPerPair). **Node gate:** every row's action `circle`, cue kind ∈ {unique, all}, 8 rings over 8 tiles, every sentence re-filled from the bank; sweep: verbs = {circle}, cues ⊇ {unique, all}.
- **Poisons owned:** PF1 (a row's targets emptied → "targets re-derive to N" / 7 rings over 8 tiles).
- **PNG:** `scripts/worksheet-gen/out/dev/G1-338-animals-d2-en.png` (gate: `out/dev/g1308-gate/G1-338-animals-d2-en{,-longchrome,-worstchrome}.png`). Read: jaguar/duck/bat/bat/rabbit/iguana/rabbit/donkey; "Circle the jaguar … all the bats … all the rabbits … the iguana" — six rows, every tile ringed once; rows 100 (en) / 89 (733) / 85 (710); nothing under the footer.

### G1-339 — Read and Do: Two-Step Instructions — CODE `steps:2` (F2, RF.1.4)
- **Row:** `{...base.d2, steps:2, rows:4, rowMin:128, minVerbs:4, maxPerCue:3}`.
- **Child:** HOLDS two actions from one sentence: "Circle the zebra and underline the second donkey." Each row = two clauses from the base's own candidate list, joined by the bank's `and` literal (clause 1 minus its full stop + " and " + clause 2 with its first letter lowered — or the verb's optional panel-authored `frame2`), **two DIFFERENT verbs, different nouns, targets disjoint within and across rows**, the whole sentence ≤ 96 chars (a longer pair is SKIPPED by the composer, never trimmed). A `write` step puts the answer box on its row. 4 rows × 2 = **8 items** (inside the G1 [6,12] band — the guard counts rows × steps).
- **Stamps:** root `data-lcs-steps="2" data-lcs-and data-lcs-cap data-lcs-maxpernoun` + the base's; rows `data-lcs-action="two-step" data-lcs-cue="steps"`, `data-lcs-targets` = the union, `data-lcs-text` = the joined sentence; two hidden `<span data-lcs-step="1|2" data-lcs-action/-cue/-noun/-noun2/-targets (+-k)>` per row.
- **verify() (`VERIFY_STEPS`):** the shared strip checks; per row exactly 2 steps, different actions, no noun in both clauses, per-step targets re-derived by `DERIVE_WANT` (the base's §2 rules), no tile marked twice in a row or on the page, row targets = the union, the "and" literal present, ≤ cap, done box, write step ⇒ answer box = the count / no printed answer / no second write with the same count; page: (action, cue kind) pairs distinct across the 8 steps, ≤ maxPerVerb per verb, ≤ maxPerCue per cue kind, ≤ maxPerNoun per noun, ≥ minVerbs verbs. **Node gate:** every row re-JOINED from the bank (`rejoin`) and diffed against `data-lcs-text`; marks ≤ tiles; sweep: every verb asked over the full 20-seed sweep (`line` surfaces on ~1 page in 12 — quick mode tolerates one missing non-write verb), write steps present with ≥ 2 distinct answers.
- **Poisons owned:** P8 (step 2's action := step 1's → "both clauses"), PF2a (step 2's targets := step 1's tile → "marked twice in one row"), PF2b (" and " → " then " → the re-join + the literal check).
- **PNG:** `out/dev/G1-339-animals-d2-en.png`. Read: dog/seagull/dog/dog/panda/donkey/leopard/seagull; four two-clause rows ("Write how many leopards there are and put a check mark under the last picture." with its answer box, "Put a check mark under the leopard and circle the panda.", "Circle the third dog and underline the donkey.", "Underline the second dog and cross out the first picture."); seven distinct tiles marked, none twice; rows 146 (en) / 138 (733) / 132 (710).

### G1-341 — Read and Check: True or False — CODE `mode:'truth'` (F4, RF.1.4)
- **Row:** `{...base.d2, mode:'truth', rows:6, cues:['count','first','last','ordinal'], truePerPage:3, maxPerCue:3, maxPerNoun:2, statementCap:80, chipsW:250}`.
- **Child:** VERIFIES a declarative against the strip and rings `true` or `false`: "The second picture is the orangutan." / "There are exactly two swans in the row." / "There are fewer than four pigs in the row." / "The row starts with the swan." Exactly 3 true + 3 false per page; a false statement is false by COUNT (a wrong number on a strip noun — `more/fewer than N` stays within 2 of the real count, `exactly N` never asks above 4) or by POSITION (a strip noun that is not at that place) and **always names a noun ON the strip** (P5). Statements come from `bank.truth.frames` (13 EN frames: 4 count with `rel`, 2 first, 2 last, 3 ordinal k 2..4, rightof/leftof for d3) filled with the `unique` form + the number WORD; ≤ 2 rows per frame, ≤ 3 per cue kind, ≥ 3 cue kinds per page.
- **Layout:** strip unchanged; rows `[badge 30][10][statement 1fr][10][truthChips 250]`, no done box; the chip column measured **250** exactly (`true` 90 + `false` 110 + gap 10 … inside 250 with room for pt `verdadeiro/falso` 239); statement column 363 → the 80-char cap wraps to ≤ 2 lines (measured `clientHeight` ≤ 50 on every render).
- **Stamps:** root `data-lcs-mode="truth" data-lcs-trueper data-lcs-cues data-lcs-cap data-lcs-yes data-lcs-no data-lcs-maxpercue data-lcs-maxpernoun` + strip; rows `data-lcs-action="truth"`, `data-lcs-cue` (`count | first | last | ordinal:k`), `-noun -noun2`, `data-lcs-truth="1|0" data-lcs-false-by="count|position|" data-lcs-nval data-lcs-rel data-lcs-frame`; chips `data-lcs-truth-chip="yes|no"`.
- **verify() (`VERIFY_TRUTH`):** the shared strip checks; per row the statement lints, ≤ cap, distinct, no done/answer box, no targets, `truth` re-derived from strip + cue + noun + nval/rel + k and diffed against the stamp, every named noun on the strip, false-by consistent, cue ∈ config, ≤ maxPerCue / maxPerNoun; chips exactly two, DOM order + geometry yes | no, texts = the stamped yes/no, no glyph, h ≥ 44, inside the row, styled identically (no verdict by palette); page 3/3. **Node gate:** every statement re-filled from `frames[data-lcs-frame]` with the stamped n/noun (`refillTruth`) and diffed; chips = bank `yes|no`; 3 true; sweep: every config cue asked (k 2,3,4 all seen).

## Deviations from §3 (each with the measurement)
1. **F2 has 4 rows (8 clauses), not 5 rows (10 clauses).** Ten single-target steps over eight tiles need a perfect tiling with ≤ 2 `write` steps; measured with the real composer on 6 themes × 20 seeds: 5 rows composed **0/60** under the base caps, **0/60** with maxPerVerb/maxPerCue/maxPerNoun 3 (+ pair repeats), **0/60** at maxPerVerb 4. Four rows compose **120/120** at `maxPerCue:3` (81/120 at the base's 2 — eight steps over seven cue kinds need a third `unique`, and `line` never surfaced at 2). The design's d1 ("6 × 4 pictures") is likewise infeasible as tabled and is unreachable anyway (the emitter ships one config). Row floor 128 (4 × 128 + 24 + 146 + 12 = 694 ≤ 710); rows measure 146 / 138 / 132.
2. **F1 needs one additive key, `maxPerPair`** — "PARAM, no new build code" cannot hold: the base composer's (action, cue kind)-distinct rule leaves a one-verb page two rows. The knob defaults to the base rule and is stamped only when declared (the base's HTML is byte-identical). `maxPerNoun` (F2's per-page noun cap, default 2) is the same shape.
3. **F3 drops `line` and `write` from the verb set.** `line` composes only under the `unique` cue and `write` carries the `count` cue — with the positional cue set either verb has NO legal sentence and the base's own check throws "verb has no legal sentence … refused" (measured before the cut). Four tile verbs remain, floor ≥ 3 held on every render.
4. **F2's second clause is the base frame with its first letter lowered** (`toLocaleLowerCase(loc)`), or a per-verb optional `frame2` the panel may author when a locale's second-clause shape differs (separable verbs, V2). The design named the `and` literal but no second-clause frame; the lowering touches only the imperative verb's initial (a noun never opens a frame — gate rule) and is re-done identically by the gate's `rejoin`.
5. **F4 truth frames grew two fields** — `rel` on count frames (the design's cue enum had no way to say "more than") and whole-literal `ordinal` frames per k (the design's d2 cue list names `ordinal`, the bank had no such frame). The false-statement space is bounded: `exactly N` false never above 4, `more/fewer than N` within 2 of the real count ("fewer than four pigs" over one pig was measured and rejected as a trick).
6. **F5 n ∈ 2..4, not 1..3.** Every draw frame is PLURAL; the first render printed "Draw one small camels" (measured). A singular frame needs an indefinite-singular form per noun the bank does not carry — open item for the panels; the spec guard refuses `nMin < 2`. fi draw + count frames must take `{part}` (numeral + partitive singular), gated.
7. **{n} prints as the number WORD** in EN (`numbers` map; the base record's item 5 left numeral vs word to the panels — for a reading face I authored the word). A locale without the map prints the numeral; the gate accepts either and re-fills the same way.
8. **F5's draw box flexes** (floor 140, the design's fixed 300 × 140): under the shipped 1-line chrome a fixed box left a 60 px hole under every sentence. `drawBox` itself is untouched (G2-318 / K-322); `drawCards` emits the same look with `flex:1 1 140px; min-height:140px`.
9. **The stack budgets 710, not 722** (the base record's measured worst chrome, deviation 2 there): F1/F3/F4 keep the base's row floor 85 (708), F2 128 (694), F5 cards (710 − 28)/3 = 227 → inner 199 ≥ 49 + 8 + 140.
10. **d1 / d3 variants of the faces are not built** (the emitter ships ONE config for all three levels); the code accepts them where the design lists them (`rightof/leftof` truth frames for F4 d3, `leftof` + ordMax for F3, `steps` guard on rows × steps).
