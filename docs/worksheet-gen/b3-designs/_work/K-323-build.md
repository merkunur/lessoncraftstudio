## Deviations from the design file (each with the measurement)
1. **Bank file + export names.** The design writes `data/b3/about-me.js` / `ABOUT_ME` / `ABOUT_ME_PICTURES`; the brief and `b3-common.bank('all-about-me', loc)` need the family key as the file name → `data/b3/all-about-me.js`, `ALL_ABOUT_ME` (first export, the locale map `bankModule` reads) + `ALL_ABOUT_ME_PICTURES` (second export). The bank also carries `whoHasMore.question` beside `me / friend` (the F5 layout prints a question line above the pills; the §5 shape lists only the pill literals).
2. **`nameBanner` / `drawBox` do not exist on disk** (G2-318 and G1-308 have not been built; `grep` over `templates/components-b3/` = 0). A same-name export from two family files makes the namespace THROW for every b3 family (K-320 precedent, `lineUpStrip`), so the base exports them TYPE-SCOPED as `aboutMeBanner({label, laneW=440, glyphH=40, h=84, labelPx=20})` (= G2-318's `name:null` eyebrow mode + the four additive options, paw OFF) and `aboutMeDrawBox({w, h, label, key, flex})` (= G1-308's `drawBox` + the `label` option). Fold into the owners' components when they land. The face components (`optionTiles favouriteRow familyFrames faceLabels canRow nameBoxes`) are NOT exported — nothing on the base consumes them (K-319 convention).
3. **`blankNumeralBox` is K-320's and it stamps `data-lcs-answer=""`.** The design's `blankNumeralBox({w,h,key})` stamps `data-lcs-<key>` ONLY and its gate rule reads "no `data-lcs-answer` attribute anywhere on the type". The brief forbids redefining a sibling's export, so the age box is `blankNumeralBox({w:64,h:64,answer:'',attrs:'data-lcs-age'})` and the rule is enforced as **every `data-lcs-answer` on the page is the EMPTY string** (verify + the node check). `answerBox` without an answer prints `"undefined"` and still FAILS (P13); no consumer outside the components reads the attribute (`grep -rn lcs-answer emit/ render/ lib/` = 0).
4. **d1 is a stretched portrait, not a 438 px stack under 340 px of blank page.** The design's d1 (banner 96 + 12 + a 330 row) is 438 px; the body measures **799** under en chrome (the K-319 build's 778 had a shorter instruction), leaving ~360 px of nothing below the frames — the "sparse" class. Nearest faithful build: rows `96px minmax(330px,1fr)`, the portrait `stretch:true` (`height:100%`, min 330, the zone flexes with the 16 inset kept) and the family box `flex:1` → a full-body self-portrait 330x691 + a 330x580 family box under en chrome, 330x592 / 330x481 under the fi chrome. The gate asserts `>= 330` for the stretched frame and `=== size` (square) for d2/d3. If the reviewer prefers the square, set `portraitStretch:false` and rows `96px 330px` — the guards accept both.
5. **The body is not a flat 722; the d3 stack is re-budgeted to 688.** Measured in the real render: en → 799; a 70-char de title (3 lines, head 112) + 150-char instruction → **733**; a 70-char fi title of long words (4 lines, head 145) → **700**. The design's d3 stack 712 (favourites row 220) overflows the fi case by 12, so d3 uses `minmax(196px,1fr)` (windows `min-height` = the row floor, zones >= 126) → 688 <= 700; d2 stays at the design's 628 with `minmax(220px,1fr)`. The first build pinned the windows at `min-height:220` and, at the 208 px fi row, they spilled 12 px into the sentence lane while every gate stayed green (the overflow lint sees the page box, the footer lint sees the footer, and a pairwise overlap test reads 0 px because the spill exactly consumed the 12 px gap); found by reading `K-323-gate-d3-en-longchrome-fi.png`; verify now asserts every frame stays inside its grid row (plus no two frames overlap) and PO is that page.
6. **`.ws-lane` inner width is 639 / 324 / 336 (padding 12 16 + border 2 at 675 / 360 / 372), never 643** — the README correction applied: the age row is measured against `lane.width - 36` (211 of 324 at d2), the banner (a plain div, padding 10 16, no border) keeps the design's inner 643 = 191 cap + 12 + 440.
7. **The photo corners are four 24 px SVGs pinned to the zone's corners**, not one overlay sized to the zone: an overlay sized to the zone's MIN height left the bottom pair mid-zone on the stretched d1 (seen in the first d1 render); verify asserts all four sit on the zone and the pair spread >= zone height - 30.
8. **The toy list holds 10, not 12**: `scooter` and `crayons` exceed the 96 px ceiling in the real fonts (measured above); the design's "8-12 per category" holds. `egg` is out for its picture (deviation-free, a curation call recorded in the bank header).
