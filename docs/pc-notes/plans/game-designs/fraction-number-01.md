## §1 — Concept / world
**The Shard-Smiths of Glimmer Hollow.** Pip, an apprentice glass-smith, mends moonpanes (whole panes of stained glass) from identical unit-shards kept in **shard-drawers** labeled by SMALLNESS (the eighth-drawer holds the TINIEST shards — a pane split into eight makes eight slivers). A fraction a/b = "fetch a shards from the b-drawer." The drawer-label is a **smallness DIAL** (bigger b → tinier shard) — but per the rework, the dial TEACHES (the reveal/confirmation), it does not ASSESS (the symbol must drive the judgment first). Non-numeric abundance vessel: the Hollow's windows light up warmly as panes mend (never a count). `ctx.correct()` auto-advances.

## §2 — The standard + the load-bearing cognition
**3.NF.A.1 (Grade 3, SOLE primary)** — a fraction a/b is a NUMBER: 1/b is one of b EQUAL parts of a whole; a/b is a copies of 1/b. **also_teaches 3.NF.A.3d** (UNIT-fraction size comparison ONLY — 1/b vs 1/d). DEFER number-line (3.NF.A.2) + general comparison/equivalence (3.NF.A.3a-c) to siblings. **Cognition (pedagogy ruling, AS RE-CENTERED by the critic):** THE load-bearing assessment = the **DENOMINATOR-as-piece-SIZE inference** (more equal parts → each part SMALLER), the inverse relation that defeats the whole-number-override ("1/8 > 1/4 because 8 > 4") and that E14 can't own — assessed **SYMBOL-FIRST** (the denominator drives the judgment BEFORE the size is rendered). The NUMERATOR-as-COUNT + build/name are scaffold (the count is a pre-K skill; build/name are HANDED). **Numbers:** denominators {2,3,4,6,8} (the CCSS Grade-3 set), numerators a≤b, b/b=1 capstone, EXCLUDE a/b>1, set-model ≤25% variety. Equal-parts validity + same-whole both assessed. **FENCES:** E14 shape-partition (must require denominator→piece-size reasoning + a/b count, not "tap the shape showing fourths"), whole-number counting (the count is always of UNIT pieces), number-line (none), general a/b-vs-c/d comparison/equivalence (none — unit-fraction 1/b vs 1/d only), continuous "shade the fraction" (BANNED — discrete pieces). Numbers/symbols = real DOM/SVG `<text>`.

## §3 — THE ARCHITECTURE REWORK (the heart; the deepest flaw + fix)
**The critic's catch — the discrete-tiles / smallness-dial / no-continuous-field fix killed the GENERIC solvers (area-eyeball / count-no-size / different-whole), but it did so by RENDERING THE ANSWER INTO THE TILE AFFORDANCES — moving the leak from "continuous-fill" to "tile geometry + label + slot-key," a channel the field-linting gate is BLIND to. Across ALL FOUR original modes the denominator→piece-size cognition is performed in ZERO of them:**
- **(A) LABEL-MATCH (build/name — a Game-75 lexical-tell cousin):** recipe "3/8" + tiles labeled "1/8"/"1/4"/"1/2" → the child matches the digit "8" to the tile labeled "1/8", places 3 (count = pre-K). The answer-tile's label is literally IN the recipe; the piece-size cognition is never computed. name = OCR + count. **Both contribute ~0 bits of magnitude evidence.**
- **(A-deeper) SLOT-FIT (the size-keyed slot is a SECOND answer-leak):** even UNLABELED, a 1/8 tile only seats in a 1/8 slot → "build 3/8" is solvable by shape-fit trial-and-error (the affordance solves the problem — the Game-75 structure-handed cheat in pure form).
- **(B) PERCEPTUAL-SIZE (which-is-smaller — a Game-74 perceptual-eyeball cousin):** the 1/8 tile is DRAWN slimmer → the child taps the visibly-smaller tile by SIGHT (a toddler clears it); the denominator "8 vs 4" is decorative, never consulted. The drawn size re-introduces a continuous perceptual signal the field-lint doesn't catch.
- **(f) PATTERN-ECHO (how-many-1/b-fill-the-whole):** the answer is ALWAYS b, printed on every tile → read the denominator off any tile, echo it. 100%, zero piece reasoning, ungated.
**The verdict: the "smallness dial" is a TEACHING AID masquerading as an ASSESSMENT — a perceptual/structural crutch standing in for the cognition; the denominator→piece-size inference is HANDED, EYEBALLED, or ECHOED, never PERFORMED.**

**THE FIX — re-center onto the cognition where the SYMBOL drives the judgment and the rendered SIZE is WITHHELD until after the commit (the design STAYS flagship; the visual model stays as the REVEAL/confirmation — developmentally honest for a visual-model standard — but becomes the OUTPUT, not the input):**
- **GRADED CORE 1 — PREDICT-THEN-REVEAL piece-size.** Show two denominators (6, 8) as NUMBERS / partition-counts; the child taps "which makes the SMALLER piece" BEFORE any tile renders; THEN the tiles draw to CONFIRM. The prediction is symbol-driven (digit → partition → size); the reveal teaches. The whole-number-override child predicts WRONG.
- **GRADED CORE 2 — HIDDEN-SIZE ORDERING.** Give chips {1/2, 1/3, 1/6, 1/8} as LABELS ONLY (no size drawn); the child orders them smallest-piece → largest. The inverse relation is load-bearing; an override child orders 1/8 as largest (mis-orders). `ORDER_INVERSION` assert.
- **DEMOTE to scaffold (un-scored / low-weight):** build-a/b, name-fraction, which-is-smaller (size-drawn) — kept as the tactile teaching loop + the smallness-dial training, but they carry NO assessment weight (they're handed/eyeballed). Mastery = predict-then-reveal + hidden-size ordering. **Strip "1/b" labels off the answer/palette tiles; de-key the slots (same outer footprint, OR the child SETS the partition count so the slot-size is their OUTPUT not a given); fix how-many-fill (mix NON-unit targets so the answer ≠ b — "how many 1/4 fill a half?" = 2 — + strip the denominator labels off the filling tiles).**

## §4 — Anti-cheat architecture (the measured gate)
NEW `verify-fraction-number-core.js` (window-shim; drives the REAL core; integer-only payload — `{whole, b, a, mode}` → pieceSize = whole/b DERIVED; NO fraction-label field, NO continuous-fill field). Solvers — ALL must FAIL:
- **`LABEL_MATCH_SOLVER`** (NEW) — match the recipe denominator digit to a tile label → must FAIL (answer tiles UNLABELED; the recipe renders the denominator as a partition action, not a matchable "1/b" string).
- **`SLOT_FIT_SOLVER`** (NEW) — solve by physical seating alone, ignore the recipe → must FAIL (slots NOT size-keyed by the answer; the child sets the partition count → slot-size is their output).
- **`PERCEPTUAL_SIZE_SOLVER`** (NEW) — judge by rendered tile width, ignore digits → must FAIL on the graded rounds (the size is WITHHELD at decision time — predict-then-reveal / hidden-size ordering).
- **`PATTERN_ECHO_SOLVER`** (NEW) — read the denominator off a tile + echo it for how-many-fill → must FAIL (non-unit targets where answer ≠ b; denominator labels stripped off filling tiles).
- **`WHOLE_NUMBER_OVERRIDE_SOLVER`** (judges by raw digits) → must FAIL on the predict + ordering rounds (`ORDER_INVERSION`: it mis-orders 1/8 vs 1/4) — `PIECE_SIZE_LOAD_BEARING` REDEFINED to count ONLY rounds where the rendered size is WITHHELD at decision time (≥N).
- **`AREA_EYEBALL` / `COUNT_NO_SIZE` / `DIFFERENT_WHOLE` / RANDOM** — all FAIL (the original starve-the-payload defenses retained for the scaffold modes).
- Structural asserts: `PIECE_SIZE_LOAD_BEARING ≥N` (size-withheld-at-decision rounds), `ORDER_INVERSION` (override mis-orders), `SYMBOL_DRIVES_NOT_RENDER` (the graded rounds' answer is decidable from the denominators alone, BEFORE any size renders), `DISCRETE_NOT_CONTINUOUS` (no continuous field), `EQUAL_PARTS_SAME_WHOLE_REQUIRED`, `ANSWER_DERIVED_NOT_STORED` (mutate a/b/whole + the same-total-area-different-(a,b) witness {12,4,2}≈{12,6,3}), ≥7 variety.
- **Wrong-answer re-show (no-reveal):** predict wrong → the tiles draw side-by-side AFTER the commit ("more parts → smaller each — 8 cuts make tinier slivers than 4"), teaching from the now-revealed model, never pre-stating the answer; mis-order → the pieces animate into size-order with the count of cuts pulsing. Single-commit teaching.

## Cohort doctrine this game adds
**The AFFORDANCE-LEAK / RENDER-THE-ANSWER-INTO-THE-MODEL lesson — PROGRAM-WIDE.** For a "manipulate-the-concrete-model" game (place a fraction tile, fill a vessel, build an array, set a clock-hand) where the concrete MODEL EMBODIES the answer (the tile-SIZE IS the fraction; the fill-HEIGHT IS the volume; the array-SHAPE IS the product), **the very affordance that makes the concept tactile also HANDS the answer** — through the model's GEOMETRY (a size-keyed slot solves by shape-fit), its LABEL (the "1/8" tile-label matches the "3/8" recipe), or its rendered SIZE (the eye reads the smaller tile). A measured gate that LINTS the payload for forbidden FIELDS (no continuous-fill, no stored-label) is BLIND to this channel — it checks for fields that don't exist while the answer flows through the affordances that DO. The TELL: the anti-cheat work "killed the generic solvers" but did so by moving the leak from one representation to another (continuous-fill → tile-geometry); the concrete model becomes a TEACHING AID masquerading as an ASSESSMENT, and the target inference is HANDED / EYEBALLED / ECHOED, never PERFORMED. **THE FIX: the concept-SYMBOL must be the INPUT to the judgment, with the concrete MODEL WITHHELD until AFTER the commit (PREDICT-THEN-REVEAL: reason from the symbol → commit → the model draws to CONFIRM) — the model becomes the OUTPUT/confirmation, not the input. Add solvers that have the FULL affordance (labels + rendered sizes + slot-fit) and must STILL score at chance on the graded rounds; only a solver that reasons symbol→model passes. Redefine the load-bearing assert to count ONLY rounds where the model is withheld at decision time.** Developmentally honest for visual-model standards (the model stays — as the reveal). Generalizes to EVERY concrete-manipulative game: the affordance teaches; assessment requires symbol-first prediction with the model as confirmation. **This is the SAME failure FAMILY as Game-74 (the concrete representation can't carry the cognition) — 74 was the CONTINUOUS case (a continuous gesture is observationally unassessable → produce-the-symbol); 76 is the DISCRETE case (a discrete affordance renders the answer into its geometry/label → symbol-first-predict-then-reveal). Both re-center off the concrete model onto symbol reasoning.** The four+ roads to a re-centered/scoped flagship: 72 contestable-gold→human-panel, 73 content-yield→mid-size, 74 continuous-unassessable→produce-the-symbol, 75 lexical-tell→keyword-stripped-inference, 76 affordance-leak→symbol-first-predict-then-reveal. **Meta-pattern (surface to operator): every recent premium-concrete flagship hits "the affordance that embodies the concept also hands it" — the concrete model is the TEACHING, symbol-first reasoning is the ASSESSMENT; the critic keeps forcing that split.**
