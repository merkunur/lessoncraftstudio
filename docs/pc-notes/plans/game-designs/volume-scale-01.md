## §3 — THE ARCHITECTURE REWORK (the heart; the deepest flaw + fix)
**The critic's catch — the obvious fix (numeral-target / no-readout / non-unit-interval / varied-geometry) kills the discrete cheats, but the CHOSEN CORE INTERACTION is OBSERVATIONALLY UNASSESSABLE.** Tap-the-scale-HEIGHT maps a continuous gesture onto a proportional scale, so a child can **PROPORTIONALLY EYEBALL** — read ONLY the endpoints (the max label + 0), estimate the FRACTION (target 245, max 250 → ~98% → tap near the top), and SNAP-to-nearest-tick LAUNDERS the eyeball into an exact pass — **never reading the interior interval or interpolating** (the volume analog of Game-71's region-reducible read). **The proof it's un-fixable on this mode: a graduation-reader and a proportional-eyeballer produce the IDENTICAL observable (a position → a value)** — an information-theoretic identity, so NO measured gate solver can ever separate them. And the **tolerance contradiction** clinches it: tolerance must be ≥ half-a-minor-tick so a correct reader who snaps always passes (a fair READING task), but that same floor is the CEILING on how much tolerance can defeat the eyeball (tightening below it makes it a MOTOR-PRECISION task that punishes the readers you want to reward) — the two constraints MEET → **set-to-target cannot carry the assessment.**

**THE FIX — RE-CENTER the GRADED assessment onto the modes where the cheat-strategy and the skill-strategy produce DIFFERENT observables (and the design STAYS flagship — "read & compare across seven beautiful vessels," not "tap to fill"):**
- **GRADED CORE 1 — READ-AND-NAME (the flagship core; eyeball-proof IFF distractors constrained).** Vessel pre-filled; the child READS the scale and taps the matching numeral from 3-4 choices. Eyeball-proof ONLY because the **distractors are WITHIN K minor-ticks of the true value AND proportionally inseparable** (true 245 → choices {235, 240, **245**, 250}, all at nearly the SAME column-fraction) so coarse fraction-reading can't sort them — ONLY interval-counting/interpolation between adjacent labels separates them. **Without the within-K-ticks constraint, read-and-name is just the eyeball cheat in a multiple-choice costume — this is the single most important fix.** The child must PRODUCE THE SYMBOL (the number), which only reading yields.
- **GRADED CORE 2 — COMPARE / the TWINS (the height≠volume assessment proper).** Two different-shaped vessels, each its OWN scale; the child picks the greater BY READING. Eyeball-proof ONLY via an **ANTI-MONOTONIC quota**: ≥N rounds where height-order ≠ value-order AND fraction-order ≠ value-order (the shorter column is the greater volume AND the greater fraction; make the fractions close + the maxes very different so ONLY the absolute read discriminates). "Often taller-is-less" is NOT a gate — it's a structural quota.
- **SCAFFOLD (NON-GRADED) — SET-TO-TARGET (tap-the-height) + COMBINE.** Kept as the delightful tactile teaching loop (manipulate to learn the scale), but **carries NO assessment weight** (it's unassessable). Mastery is computed from read-and-name + compare only.

## §4 — Anti-cheat architecture (the measured gate)
NEW `verify-volume-scale-core.js` (window-shim; drives the REAL core; the `array-core`/`verify-array-core` idiom; `trueFillPx = pxBottom − (volume/maxVolume)·extent` computed ONLY at grade-time, NEVER stored). Solvers — ALL must FAIL:
- **`PROPORTIONAL_EYEBALL_SOLVER`** (NEW) — fill at `(target/max)·extent`, snapped. On set-to-target it CAN'T reach 0 (observational identity) → so set-to-target is non-graded; on the GRADED modes it must fail under a hard ceiling (<15%) via NON_LANDMARK ∩ BETWEEN_LABEL.
- **`ENDPOINT_ONLY_SOLVER`** (NEW) — reads only the two extreme labels, ignores interior marks → must FAIL (proves interior-mark reading is required).
- **`NAME_PROPORTIONAL_SOLVER`** (NEW — the key one) — picks the read-and-name choice nearest the eyeballed fraction → must FAIL via `NAME_DISTRACTORS_WITHIN_K_TICKS` + `NAME_DISTRACTORS_NOT_PROPORTIONALLY_SEPARABLE` (all choices ≈ same column-fraction, differ only by sub-readable amounts needing mark-counting).
- **`COMPARE_HEIGHT_SOLVER` + `COMPARE_FRACTION_SOLVER`** (NEW) — must BOTH FAIL on the `COMPARE_ANTI_MONOTONIC` quota (height-order ≠ value-order AND fraction-order ≠ value-order).
- **`SR_READOUT_SOLVER`** (NEW) — steps the slider reading `aria-valuetext` as a number → must FAIL via `SR_VALUETEXT_HAS_NO_RAW_VALUE` (the SR announcement is MARK-RELATIVE — "between the 200 and 250 marks, near 250 / tick 9 above the 200 mark" — NEVER the resolvable current value; closes the a11y readout hole that the visual design bans but the slider reintroduced).
- **`RETRY_HILLCLIMB_SOLVER`** (NEW) — commit→see-result→adjust→recommit → must FAIL via **single-commit grading** (or attempt-cap + per-round start-fill randomization) so brute-force hill-climbing can't bypass the read.
- **`TICK_COUNT_SOLVER`** (non-unit interval → Nth tick ≠ value N) + **`READOUT_SOLVER`** (no live current-fill number; the only numbers are the static scale labels + the target tag) + **`FIXED_HEIGHT_SOLVER`** (varied geometry → `VALUE_HEIGHT_DECORRELATED`, same value = different pixel) + **RANDOM/EXTREME** (under `TOLERANCE_TIGHT`) — all FAIL.
- Structural asserts: `NON_UNIT_INTERVAL ≥N`, `BETWEEN_LABEL ≥N`, `NON_LANDMARK_FRACTION` (target fraction avoids {0,¼,⅓,½,⅔,¾,1} by ε AND not on a labeled mark), `NAME_DISTRACTORS_WITHIN_K_TICKS`, `COMPARE_ANTI_MONOTONIC ≥quota`, `SR_VALUETEXT_HAS_NO_RAW_VALUE`, single-commit, `TOLERANCE_TIGHT` (½-minor-tick ≤ tolerance, AND P(random)<0.15, AND oracle passes — all simultaneously), `ANSWER_DERIVED_NOT_STORED` (mutate max/interval/target/geometry → answer moves; same-value-different-geometry witness), ≥7 variety, `NO_LABEL_HIGHLIGHT_ON_LAND` (the landed mark is never highlighted/announced — static labels only; reading a label the meniscus lands on is legit, app-highlighting it is the leak).
- **Wrong-answer re-show (no-reveal):** points at the bounding NUMBERED marks + the interval ("the marks count by 5 — start at 40, count up: 40, 45 — where does the tea reach?"), never states the value; for height≠volume errors "look at the NUMBERS on each scale, not how high the tea is." Single-commit → the re-show teaches BEFORE the next attempt, not a hill-climb.

## Cohort doctrine this game adds
**The OBSERVATIONALLY-UNASSESSABLE-MECHANIC / RE-CENTER-ON-PRODUCE-THE-SYMBOL lesson — PROGRAM-WIDE.** A mechanic that maps a CONTINUOUS GESTURE onto a PROPORTIONAL SCALE (set-the-slider / drag-to-the-value / fill-to-the-amount / set-the-clock-hand / place-on-the-number-line) is **OBSERVATIONALLY UNASSESSABLE for the target reading-skill**: a skilled reader and a proportional-EYEBALLER (read only the endpoints, estimate the fraction) produce the **IDENTICAL observable** (a position → a value), so NO measured gate solver can separate them — an information-theoretic identity, NOT a patchable cheat. The TELL is a **tolerance contradiction**: the tolerance floor needed for a FAIR reading task (a correct reader who snaps must pass) equals the ceiling on how much tolerance can defeat the eyeball (tighter = a motor-precision task punishing the readers you want) — when the floor meets the ceiling, the mode cannot carry the assessment. **THE FIX — re-center the GRADED assessment onto modes where the cheat-strategy and the skill-strategy produce DIFFERENT observables: (1) PRODUCE-THE-SYMBOL (read-and-NAME: the child outputs the NUMBER, eyeball-proof ONLY if the distractors are within-K-units AND proportionally-inseparable so coarse fraction-reading can't sort them — else it's the eyeball cheat in a multiple-choice costume); (2) a RELATIONAL judgment under an ANTI-CORRELATED trap (compare under an anti-monotonic quota where height-order ≠ value-order AND fraction-order ≠ value-order). The continuous-SET mode survives as un-graded tactile SCAFFOLD — kept for delight + teaching, stripped of assessment weight.** Generalizes to EVERY set/drag/fill/place mechanic: the SET direction is eyeball-able + weakly assessable; the READ/NAME direction (produce the symbol) is the assessable one. (Companion: an a11y SLIDER reintroduces the exact READOUT the visual design bans — `aria-valuetext` must be MARK-RELATIVE, never the resolvable running value; and SNAP-to-tick + per-attempt feedback enable RETRY-HILLCLIMBING → single-commit grading. Lineage: Game-71's region-reducible read is the volume-eyeball's ancestor; distinct from Game-72 [contestable-gold validity] + Game-73 [content-yield ceiling] — this is a THIRD failure class: the mechanic's observable can't carry the cognition, fixed by changing the OUTPUT the child produces, not the content.)
