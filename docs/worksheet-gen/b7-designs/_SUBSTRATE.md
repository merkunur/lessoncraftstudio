## The two art engines (new; the ONLY picture source of this batch — read the headers)
- **`lib/fd-scene.js`** — a layered scene from a Color by Number scene spec (`data/cbn/lineart-scenes.js` SCENES 100 + SECOND 100; frame 600 × 560 picture units): `buildLayers(spec)` composes the ground lines and EVERY drawing alone (`lib/cbn-lineart.js compose + segmentInk`), colours inherited from the operator-reviewed painted key (`cbnSampler`), so each drawing is a layer `{idx, src, bbox, regions:[{d, colour, …}], ink, asym, inkUnits, hero}`; `applyOps(scene, ops)` + `renderPanel(scene, ops, {mode:'line'|'colour', width, rings, hotspots, frame})` draw a panel as SVG (`data-lcs-prim="fd-panel"`, layers stamped `data-lcs-fd-layer`, rings `data-lcs-fd-ring`, hotspots `<rect data-lcs-fd-hotspot data-lcs-fd-diff>`). Ops: `remove · mirror · move{dx,dy} · scale{s} · swap{layer} · add{layer} · detail{layer} · colour{region, colour}` — one op per drawing.
- **`tools/fd-build.js` → `data/fd/<id>.json`** (generated, gitignored, rebuilds byte-identically; ~2 MB per scene): `{id, theme, names, hy, bg, items, cands}` where every candidate op passed the RASTER GATE (left/right rendered by sharp at 1 px/unit, pixels subtracted, dilated 5, components: one component for remove/add/swap/detail/colour; mirror/move/scale = the whole drawing — `asym ≥ 0.12` for a mirror, no new overlap with another drawing, inside the frame) and carries `bbox` (the RING / tap target: the thing's place in picture 2), `diff` (the changed pixels' box), `area` (changed units²), `mode` (`any` | `colour`). Measured on farm-cow: 26 candidates (remove 3, mirror 2 of 4 drawings — the sun and the cloud refused as symmetric, scale 5, move 6, colour 3, swap 1 sun→moon, detail 1 barn window, add 3 bird/cloud/hay). The sheets: `tools/fd-sheets.js [--mode=colour]` → `%TEMP%\spl\fd-sheets\<mode>\<id>.png`.
- **`lib/htd-steps.js`** — a drawing lesson from ONE library drawing's own ink: `buildSteps(src, {steps})` → `{bbox, full, steps:[{d, share, kind:'outline'|'structure'|'features'|'details'}], shapes:[{kind:'ellipse'|'box'|null, cx, cy, rx, ry, angle, box, coverage}], stats}`. Step 1 = the drawing's OUTER line (ink within 11 px of the paper); the inner strokes are classed by the part they define (structure ≥ 3 % of the body · features ≥ 0.4 % · thick details (pupils) · thin details (whiskers, texture)), ordered big → small then top → bottom, cut into equal-ink groups that never split a class or a pair of features at one height; union of steps == the ink (pixel-exact, `stats.missing = extra = 0`). `stepSvg(S, k, {width, shapes, lastInInk})` (previous steps in ink, this step in coral), `fullSvg(S, {width})`. **Measured (cat / rabbit / fire truck / owl): 4–5 steps, outline share 0.25–0.53, 0 missing.**
- **`tools/htd-build.js` → `data/htd/<slug>.json`** for every hero drawing of the 200 scenes (`slug` = the src folded to kebab, e.g. `animals-bw-3-cat-2`; `sceneId` = the design id, e.g. `cat`); `data/htd/review.js` (committed) = `REFUSED` + `OVERRIDES` (steps count) after the human read of `tools/htd-sheets.js` (`%TEMP%\spl\htd-sheets\sheet-NN-*.png`, 4 drawings per sheet: every step, the full drawing, the shapes guide).
- Panel geometry: a 600 × 560 scene at 320 px wide prints at 0.53 px/unit (a 7-unit stroke ≈ 3.7 px, a 260-unit hero ≈ 140 px). The design files quote every size in PRINTED px; the engine's `MIN_SIDE 16 units` ≈ 8.5 px at that scale — a face declares its own floor in px and the type refuses candidates below it.

## Interactive layer for find-the-differences (reuse exactly; nothing new in `render/` or `emit/`)
`render/render-instance.js` captures `type.interactive = {kind:'tap-select', item:'[data-lcs-fd-hotspot]', answerAttr:'data-lcs-fd-diff', labelAttr:'data-lcs-label', metaAttrs:[…], instructionKey, oracle(items, loc, ctx)}` when the wave says `"interactive": true`: the screen page is the `ctx.interactive` render (bigger panels, no writing rows), items = the hotspot rects (% of the cropped page), answer = the attribute's presence; `emit/interactive-runtime.js` JS_SELECT renders the taps (≥ 4 targets, both kinds, every target ≥ 44 px at 360 wide — `qa/verify-interactive.js playSelect` is the robot: right taps celebrate, a wrong tap goes red, a missed difference is marked); the answer key = the `ctx.answerKey` render (rings). The tap instruction ×11 lives in `i18n/interactive-instructions.json`. Hub: `frontend/config/interactive-exercise-types.ts` gets an additive `INTERACTIVE_PRINTABLE_FAMILIES` set (a printable family whose EVERY deck ships a key + screen), honoured by `isInteractiveType` and by `scripts/audit-worksheet-formats.js` / `scripts/verify-hub-type-rows.js` (deployed BEFORE the first publish).
