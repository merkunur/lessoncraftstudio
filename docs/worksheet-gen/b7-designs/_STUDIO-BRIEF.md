## The eleven faces — the variation doctrine (each rule cost a real defect in an earlier batch)
1. **A theme/picture swap is never a face.** A face must change what the child DOES or LEARNS.
2. **A face must differ from the base in its RESOLVED config at the shipped level** (`tools/gate-variation-distinct.js --batch=b7`).
3. **Demand-weighted, honest ceiling.** Design exactly ten; a face a locale cannot carry is REFUSED there, recorded, never faked.
4. **Each face owns a distinct QUERY FACE** (a count, a colour mode, a mirror, a word bank, a step order…) so landings do not cannibalise: the base owns the bare head; never two faces whose titles differ only by an adjective.
5. **PARAM before CODE.** Say which each face is; a CODE face = a named additive `mode` knob on `build()` + a `verify()` branch, stamped ONLY when declared so the base stays byte-identical.
6. **A guard is keyed on the CONFIG, never on the level index.**
7. **Quote numbers from the resolved config, the engine data or the render**, never from a base table.
8. **The description window is two-sided** (120–170 chars; the meta = "Free printable {TITLE} … {LEVEL}. {MIDDLE}. …"); the instruction must say what is different about THIS page.
9. **The instruction is the child's sentence** — one imperative a 5–8-year-old understands, naming only apparatus ON the page.
10. **Boundary first.** The type file opens with a load-bearing Boundary paragraph (the ids in `_SUBSTRATE.md`), and every face is checked against it.
11. **Find-the-differences specifics:** every difference is an engine op with a gated `bbox`; the page composer picks ops whose rings are ≥ 24 printed px apart, spread over the picture (never all in one quadrant, never on the frame), at most one per drawing; the difference count printed in the title IS the count on the page; the screen's decoy targets are the UNCHANGED drawings; the ring on the key circles the thing's place in picture 2. The colour face uses the painted scenes (`mode:'colour'`) and must include ≥ 1 colour-change op.
12. **How-to-draw specifics:** steps come from `data/htd/<slug>.json` (4–6; `kind` outline / structure / features / details); a face may show ALL steps, SOME steps, the shapes guide, the full drawing as a trace, the full drawing with parts erased (a `remove-step` = the drawing without one step's lines), a shuffled strip; the practice area is an empty box whose proportions are the drawing's `bbox`; never fewer than one big drawing area per page; the new lines of a step are coral, earlier lines ink, the final step in ink.
