## 2. Concept & creative hook
A fox makes a necklace to match its best friend's — not the same colors, the same **how-many**. But the beads **won't hold still**: the friend tucks the necklace away the moment you've counted it, gives it a playful shake so the beads bunch up, spills them into a scattered pile. The fox's delight (and the child's lesson): *the number is the one thing that doesn't change when everything else does.* You counted seven; bunched or spread or hidden — still seven.
- **Count-then-hide is the SPINE (the rework):** every round, the friend's necklace is counted ONE-TO-ONE and then **disturbed or tucked away** before the child produces or re-counts. The child never matches a static visible set (that would be Twinsies); they hold a **count that survived the set changing.** "The number outlives the arrangement" is the felt core.
- **One bead = one number word, physically (the mechanic):** the count exists ONLY as the integer emitted by guarded `thread()` events. A bead is threaded one at a time (the next "ready" bead glows at the cord's next slot; it pre-glows DURING the current seat so an honest fast-counter feels FLUID, never the `_busy`-lock sluggishness — seat animation <150ms); each thread lands one bead + speaks one number word + ticks the count by one. There is **no count channel separate from threading** (no rote "count" button to tap). Colors are deliberate **NOISE** (the model is one color; the child threads another) — color-copying provably can't win.
- **Conservation is the affirming TEXTURE, demonstrated never tested (the pedagogy lock):** when a necklace is re-counted after a shake, the game **AFFIRMS the same cardinal** ("you counted it a different way — still seven!"). The count **NEVER actually changes** in a conservation round (fix: the rolled-away bead is a SEPARATE completeness-repair round, not a covert "did it change?" judgment). The child is never asked "is it still the same?" — they just count, and the affirmation models invariance.
- **Anti-frustration UX rule (locked):** the disturbance is ALWAYS **narrated + story-caused BEFORE it happens** ("watch — the fox gives the necklace a shake!") — never a silent post-completion disturbance (which would feel like whack-a-mole / losing progress). The child watches a TRICK, never loses work. (Screenshot check in the approval cadence.)
- **Anti-generic statement:** NOT a count-the-beads drill with a string skin — (a) the number outlives the arrangement (count-then-hide; the count is a stable property, not a static match); (b) one-to-one is a gate-provable physical mechanic (one bead ↔ one word ↔ +1; no rote channel); (c) color is noise (count-only grading); (d) conservation is demonstrated-not-tested; (e) a board ships only if a **color-copy solver**, a **rote-recite-decoupled solver**, a **bulk/subitize solver**, a **model-subitize solver**, a **keypad-exhaustion solver**, and a **cache-the-count (no-re-enumerate) solver** ALL fail the gate while a genuine one-to-one+cardinality solver passes (§8).

## 3. Core loop & the ≥7 distinct experiences
**Loop (the foundational act):** the friend reveals its necklace → **count the model:** the child taps each model bead one-to-one (it dims/ticks; the target is revealed ONLY after every model node is touched — model-subitize is impossible on N≥6) → the friend **tucks the necklace away / shakes it** (narrated first) → **thread your own:** the child threads beads one at a time (each = one number word, the count ticks) to the remembered count → the necklaces are compared **by COUNT only** (color/arrangement-blind) → on count-equality the necklace clasps with a shimmer, the two foxes touch noses, both necklaces glow in unison → `ctx.correct()`. **Wrong = the clasp gently won't close** (binary, directionless — NO "one more"/"too many" magnitude leak); the friend warmly says "let's count again together," and the re-count is the repair.

**The ≥7 distinct experiences — HONEST re-count (the critic cut the padding): distinct = a different CHILD-ACT, NOT the same count with beads moved or sound off.** The audio-toggle "quiet round" was cut (it was experience 1 with a setting); the conservation re-skins were merged. The genuinely distinct acts:
| # | Experience (the distinct ACT / reasoning) | Render / act | Why it's distinct & non-guessable |
|---|---|---|---|
| 1 ★ | **Count-and-thread (the invariance spine)** | count the friend's necklace one-to-one → it tucks away/bunches → thread your own to the remembered count | the number OUTLIVES the model vanishing — distinct from Twinsies (static visible match); one-to-one is the assessed mechanic |
| 2 ★ | **Re-count the rearranged necklace** (conservation, demonstrated) | your finished necklace is SHAKEN (bunched/spread, line preserved) → re-count one-to-one → the game AFFIRMS the same cardinal | invariance under spacing; the count NEVER changes; affirmed, never judged (one dedicated conservation experience, not a lane) |
| 3 ★ | **Track-while-counting the scatter** (the hard one-to-one) | a lineless scattered pile → count with mark-as-you-go tracking (each counted bead relocates so the uncounted pile shrinks) | establishing a count under disorder — skip/double are the live risks; a genuinely harder one-to-one act than the orderly thread |
| 4 ★ | **Find-and-fix the skip/double** (one-to-one error detection) | a necklace was threaded with an error — a grey SKIPPED bead among the lit ones, or a DOUBLE | the skip/double error made visible + repaired (completeness: "did you get them ALL?") — diagnosis, not production |
| 5 ★ | **Cardinality-confirm** (name how many) | after a one-to-one count, the friend asks "how many?" → the child names the total — **the answer is READ FROM the actual count (`_spoken`), tapping the final cardinal the count produced, NOT a free keypad** | isolates B.4.b (the last word stands for the whole); de-brute-forced — no ≤10 keypad to exhaust |
| 6 ★ | **Thread-to-a-heard-number** (auditory cardinal) | the fox SAYS "make seven" (no model) → thread one-to-one to the heard number | production from a VERBAL given (distinct given-modality) — the one-to-one act with the cardinal supplied by ear, not by counting a model |
| 7 ★ | **Repair-the-friend's-necklace** (compare-and-fix the OTHER) | the friend's necklace doesn't match the target count (over/under by a one-to-one slip) → the child counts BOTH and fixes the FRIEND's to match | reconcile two counts + repair someone else's (distinct from #4's self-completeness: it's matching one count to a reference) |

- **Honest framing:** seven distinct child-acts (count-and-thread / re-count-the-rearranged / track-the-scatter / find-the-skip / cardinality-confirm / thread-to-a-heard-number / repair-the-other). The audio-fade idea survives as a **progression WITHIN rounds** (the TTS gently quiets as the child gains fluency), NOT a standalone experience. The 5/10 Rekenrek color structure is woven as a **cardinality AID** (5-and-some-more subitizing support), NEVER a pattern to copy. The variety gate asserts distinct by **child-act** and REJECTS "same count, beads moved / sound off" as a distinctness source (§8, §A.13.60); #6/#7 flagged for playtest-confirmation (if either collapses, replace per the standing backlog discipline). The keypad-numeral input is NOT used for #5 (de-brute-forced).
- **Free slice = count-and-thread (1) + re-count-the-rearranged (2) + cardinality-confirm (5)** — proves one-to-one + cardinality + the invariance spine.

## 4. Win-states & juice (no competition)
No timer/score/streak/countdown/**fail-state**/attempts-counter/"X of Y". **Per-bead thread:** the bead arcs onto the cord, the cord flexes, a soft click + a rising pip + `ctx.speak()` the number word (the count is audible + musical; a non-reader HEARS it climb). **The clasp payoff (signature):** on count-equality the two cord-ends swim together + clasp with a shimmer; the friend's necklace and the child's chime in UNISON; the two foxes touch noses, both glowing the same warm pulse — *"we're singing the same number."* **Non-numeric vessel = a friendship-branch of finished necklaces** (`GameCollection`) — each completed necklace hangs on the branch (tap to replay its count-chime); the branch fills with warmth, no "3 of 7." **Negative signal = ABSENCE + an undirected re-count invite ONLY:** wrong count → the clasp gently doesn't close, "let's count again together" (NO direction/magnitude — no "one more"/"too many"; the re-count is the repair). **`ctx.wrong()` is a soft, information-free state.** **Conservation affirmation** ("counted a different way — still seven!") is the warm teaching texture. **Erase is free** (tap a threaded bead → it leaves, the count ticks DOWN via the same single-event discipline). **The anti-frustration rule:** every disturbance is narrated/story-caused BEFORE it happens — the child watches a trick, never loses progress. Full-pass keepsake = the filled friendship-branch → cross-game `GameCollection`. CSS/SVG/WebAudio; reduced-motion; mute-safe (the visual tick + pip + aria-live carry the count when muted).

## 5. Pedagogy
- **K.CC.B.4 instantiation:** B.4.a one-to-one is the MECHANIC (each thread binds one bead to one successive number name — the synchrony, not a post-hoc total); B.4.b cardinality is the GRADE (count-equality to the target; the last word tells how many); conservation (B.4.b) is the demonstrated SIGNATURE (the count outlives the arrangement).
- **THE KEYSTONE RULES (non-guessability):** (i) **COUNT-ONLY GRADING** — correctness = count-equality; NEVER color order, never arrangement (kills color-copy AND delivers conservation by acceptance). (ii) **ONE-TO-ONE IS PHYSICAL + GATE-PROVABLE** — the count advances ONLY inside the guarded `thread()` (rAF `_busy` lock → bulk impossible; `_consumed` Set → double-count impossible; no rote count channel → recite-decoupled impossible); invariant `_count === placed.length === _spoken` always. (iii) **COUNT-THEN-HIDE THE MODEL** — the model is counted one-to-one then disturbed/hidden before the child produces/re-counts (kills model-subitize on N≥6; makes the number outlive the arrangement; distinguishes from Twinsies). (iv) **CONSERVATION DEMONSTRATED, NEVER TESTED** — the count never actually changes in a conservation round; the game affirms the cardinal; no win-condition branches on whether the count changed (the rolled-away bead is a separate completeness-repair round). (v) **CARDINALITY READ FROM THE ACTUAL COUNT** — #5 names the total from `_spoken`, never a free keypad (no exhaustion brute-force).
- **Number ranges + rigor (pedagogy):** core ceiling **10**; **weight rounds to N≥6** (the one-to-one error — skip/double — spikes beyond the subitizing limit, where one-to-one is genuinely load-bearing); a few ≤5 rounds for the no-shame on-ramp (subitizing is legitimate cardinality there). The 5/10 Rekenrek structure aids cardinality (5-and-some-more) but is never a pattern to copy. 6-8 distinct-target rounds. **K.NBT.A.1 ten-and-ones (11-20, two-bar) is a documented FUTURE extension, NOT core** — and the ONLY thing that would justify a longer cord.
- **Subitize-and-stop:** legitimate cardinality for N≤5 (accepted); BOUNDED by weighting to N≥6 where it can't substitute for one-to-one; and the model-count is itself enforced one-to-one (model-subitize impossible on the reading side).
- **Conservation developmental caution:** true operational conservation is ~age 6-7 — so the game MODELS invariance (through what it accepts + affirms), it never TESTS it as a pass/fail gate. Conservation is ONE dedicated experience + ambient affirming framing, not 2-of-7 of the skill budget.
- **No-shame:** the clasp-won't-close is neutral + directionless; the re-count is the repair; the disturbance is always a narrated trick, never a silent loss.

## 6. Interaction & UX
- **Runtime: the guarded `thread()` event (the one primitive).** Tap the "ready" bead (glowing at the cord's next slot) → `thread()` advances the count by exactly one (the SOLE count-mutating function), pushes the bead to `placed[]`, speaks the number word (`_NUMBER_WORD_HELPERS`), ticks the readout, flexes the cord. The next ready-bead PRE-GLOWS during the current seat (<150ms) so an honest fast-counter feels fluid while a single-frame bulk burst still gets rejected (`_busy` admits ≤1/frame). `_consumed` Set → each palette bead threads once. **No count channel exists outside `thread()`/`unthread()`** (reflection-assertable). Drag-onto-cord is an enhancement on the SAME `thread()` path — **desktop/wider + single-bend layout only; disabled on mobile** (a serpentine-curve drag is a mis-snap generator).
- **State separation (anti-cheat):** the model beads carry `aria-label="bead"` (NOT their ordinal) so a DOM solver must COUNT the nodes; the count is `_count` (derived, never an engine-fed digit); `getRenderableState()`/`_gateState()` expose the process trace (`events`, `count`, `placed`, `spoken`, `target` test-only) so the measured solvers can be proven.
- **Count-then-hide flow (the spine):** `stage:'count-model'` (tap each model bead one-to-one; target revealed only after all touched) → narrated disturbance (`stage` transition, no auto-advance) → `stage:'produce'`/`'recount'`. The model, once counted, is HIDDEN or shown only as a small **non-interactive reference chip** — NEVER a full second necklace the child can mis-tap or subitize.
- **The continuous one-bead-at-a-time feel (finger-robust @280px):** SVG cord (`viewBox` + `width:100%`, `t∈[0,1]` via `path.getPointAtLength`); beads = visual `<circle>` + an invisible hit-halo sized from the LIVE css width so the effective target stays **≥44px**; `setPointerCapture`; rAF-throttled; `touch-action:none`. Ceiling-10 → a single row or a gentle single-bend cord holds 10 beads ≥44px at 280px (NO serpentine — dropped as premature).
- **Cardinality-confirm (#5) interaction:** the necklace plays back its count (each bead chimes its number in order); the final cardinal is held up big; the child taps THAT (the value the count produced) — the response is read from `_spoken`, never free-typed. No keypad.
- **Mobile @280px (truth-tested):** vertical stack — fox + prompt / **the child's working cord is the hero ≥44px-interactive surface** / the model as a small reference chip (or hidden) — **NEVER two full long necklaces simultaneously** / palette (`flex-wrap`, ≥44px beads) / the count readout (real-DOM numeral + a pip row, the produced count) / the friendship-branch vessel (a thin strip). Pass `audit-game-mobile.js` 280–768 empty (cord + empty palette + 0 readout) + filled (10 beads + clasp): assert ≥44px targets, no overlap, no over-wide element, AND a **latency assertion** (the honest fast-counter's seat<150ms with pre-glow overlap, so gated threading isn't sluggish).
- **Accessibility:** TTS speaks each number word as each bead threads (`_NUMBER_WORD_HELPERS`); `ctx.announce()` mirrors every state ("you made seven!" / "the fox shook the necklace — let's count again" / "still seven!"); the count is conveyed non-visually (spoken words + pip count + a `role=status` readout with the produced integer) — color is NOT assessed so accessibility is easy; keyboard path = palette beads are buttons (Enter threads), threaded beads roving-tabindex (Delete unthreads); ≥44px; reduced-motion (instant seats, the one-to-one TIMING preserved because it's event-driven) + mute-safe.

## 8. Runtime mapping + MEASURED build-gate + PER-LOCALE
- **Round descriptor (DATA; stores the target COUNT + arrangement — NEVER an on-screen answer digit):** `{ id, type (the §3 experience), targetCount (1-10; weighted ≥6), modelArrangement:{spacing:'even'|'bunched'|'spread'|'scatter', palette (NOISE colors), seed}, disturbance?:{kind:'hide'|'bunch'|'spread'|'scatter', narratedBefore:true}, error?:{kind:'skip'|'double', at} (find-and-fix #4 / repair #7), heardTarget?:boolean (#6 thread-to-a-heard-number), paletteSupply (≥ target + slack) }`. `targetCount` is the assessed cardinal — NEVER rendered as a numeral or spoken before the child counts; the model SHOWS that many beads (counting them is the task). - **`verify-bead-string-core.js` (MEASURED — drives the REAL core; HALTS build):**
  1. **COLOR-COPY solver must FAIL:** reproduces the model's color order with the WRONG count → count≠target → reject; AND a right-count-WRONG-color-order solver → **PASSES** (proving color is irrelevant + conservation real). If the wrong-order-correct-count solver fails, the game is checking order = patterning-drift = gate FAIL.
  2. **ROTE-RECITE-DECOUPLED solver must FAIL:** reflection asserts NO count-mutating method exists besides `thread`/`unthread`; reciting/calling-nothing leaves `count===0` → never reaches target.

  4. **TRIAL-AND-ERROR solver must FAIL the process-trace:** the cardinal must be reached by a MONOTONE count of clean bead-events, not converged-to via add/remove.
  5. **MODEL-SUBITIZE solver must FAIL (fix):** on N≥6, the target cannot be obtained without N one-to-one touch/enumeration events on the MODEL (model-count is gated/counted, OR the model is hidden before the palette is live).
