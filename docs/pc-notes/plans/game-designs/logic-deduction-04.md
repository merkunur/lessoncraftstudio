## Concept & creative hook
A child rarely holds authority over a confident grown-up. Here they do. **Judge Tess** (ancient kind tortoise, oversized powdered wig) presides over **Numbers Court**; witnesses make math claims (true or sneaky-false); Tess reads each RELATIONALLY, turns to the child — **"What do you say, Judge?"** — the child is addressed as "Judge" the whole game.
- **The "=" is a brass SEE-SAW FULCRUM (the load-bearing move):** each expression in a PAN; "=" means the beam is LEVEL — both pans hold the same amount, never "→ the answer comes next." The misconception is killed by the geometry.
- **The trick gets the silly moment, NEVER the child:** a caught false claim → the WITNESS does a sheepish delighted double-take ("Well caught, Judge!"). Defending a TRUE claim that nervous Pip doubted = apex empowerment (the child taught a character).
- **Anti-generic:** NOT a true/false arithmetic quiz in a tortoise skin — (a) the courtroom verb IS the standard's verb (a judge judges claims; the rare case where the skin is the pedagogy); (b) BOTH verdicts demand a justify the child can't bluff; (c) a board ships only if a gauntlet of dumb non-relational solvers all FAIL it.

## Core loop & the 7 distinct experiences
**Loop (two-stage via shell `stage`, + a periodic Stage-3 repair):** Tess reads the claim RELATIONALLY ("five plus two — is that the SAME AS two plus five?"); the beam does NOT move (pitfall #2 — never give the answer away). **Stage 0 RULE:** tap TRUE ("It's fair!") / FALSE ("Catch it!"). **Correct verdict →** reveal **Stage 1 JUSTIFY** (no `ctx.correct()` yet): FALSE→tap the heavier pan/discrepancy token; TRUE→deposit each expression's counters into its pan, beam settles LEVEL only when the deposits are correct. **Correct justify** → on most rounds `ctx.correct()` ONCE → witness reaction + vessel beat → auto-advance; **on ~30–40% of FALSE rounds → reveal Stage 3 "Now Fix It" (the repair, absorbed from #29) instead of advancing** (see below).

**Stage 3 — "Now Fix It" (periodic repair; the generative tier, merged from Game #29):** AFTER the child has caught a FALSE claim AND proven it (Stage 1), Tess invites *"Can you make it fair, Judge?"* → one element of the false equation becomes a swappable slot; the child places the value/operand that **levels the beam** → then `ctx.correct()` fires. Repair is a **DEEPENING, never a gate** — the deck is fully playable/completable if a child never triggers it.
- **GOLD-only (the relational keep-condition):** repair fires ONLY on the non-standard GOLD forms — answer-on-left `c=a+b` (8=6+□), both-sides `a+b=c+d` (4+3=5+□), `a=b−c` (5=8−□). **NEVER on canonical `a+b=c`** (repair-on-standard = compute-the-sum, the very misconception). Relational-by-construction → a compute-left-to-right repair lands WRONG.
- **Anti-brute-force = REGENERATE-ON-WRONG (the one genuinely-new fix, critic #1):** a wrong repair commit → Tess *"hmm, still not level — here's a fresh one, Judge"* (warm, no fail-state) → a NEW false round of the SAME form, new numbers. Grinding one beam is impossible; every commit is a fresh reasoned read. **Tray of 5–6 tiles** (chance ≤ ~1/5); the deck advances on correct placements only.
- **Magnitude-bracketing distractors (2nd new fix, critic #5):** the repair tray's decoys STRADDLE the target (target `□=3` → offer `2` and `4`) so the qualitative tilt's *sign* ("the box side is light") can't pick the answer — the child must reason the actual quantity. Closes the direction-without-magnitude shortcut.
- **Inherited free from this game's existing spine (do NOT re-bake):** no-live-tilt beam (pitfall #2 — repair commit-reveals, never steers); 40–60% TRUE rounds already kill the "always-broken" heuristic (repair fires only on a SUBSET of the false minority); operand-bound deposits already kill copy-shortcuts; the re-teach "this much AND this much — are they the same?" names *same-amount*, never "bigger" (reused verbatim). **Framed relationally — "what makes the right pan the same as the left" — never "find the missing addend" (no 1.OA.D.8 claim; that is Game 5's lane).**
- **Wrong verdict (fix #1, headline):** the beam stays STILL and LEVEL — NO directional info; Tess "are you SURE, Judge? Look again." 2nd wrong → guided both-pans re-teach ("this much AND this much — are they the same? let's fill them together") forcing evaluation of BOTH pans. **The truth-revealing beam motion is the REWARD for being right, never the HINT for being wrong.** No buzzer at the child, ever. (This closes the free-answer-key leak that had turned the backbone into a 2-try binary.)

**Fix #2 — the justify forces QUANTITY evaluation, not ritual (baked in):**
- Counters are **operand-bound**: tapping `4` deposits exactly 4, `+3` deposits exactly 3 — the child CANNOT free-pour to force a visual match (kills count-to-equal). Only freedom = whether to deposit; the count is bound to the symbol (also satisfies force-a-symbol-touch).
- `beam.settle()` callable ONLY when `leftPan.count===sum(leftExpr) && rightPan.count===sum(rightExpr) && leftPan.count===rightPan.count` — all DERIVED. The beam confirms the CHILD's correct work, never does the comparing → TRUE-justify is equal-rigor to FALSE-justify, not a rote two-tap.
- **Commutativity justify pairs QUANTITIES, never glyphs:** the child re-orders the left pan's deposited piles into the right pan's arrangement ("same amounts, swapped") — symbol-glyph-matching is structurally impossible.

## Pedagogy
- **Concept of the SYMBOL "=", not arithmetic.** Misconception cured: reading "=" operationally ("do it, answer comes next") vs relationally ("both sides the same amount"). Instantiated 3 ways: (1) "=" sits on a balance fulcrum; (2) Tess ALWAYS says "is the same as," never "makes/gives"; (3) every justify forces evaluating BOTH pans.
- **GOLD-dominant forms (the heart):** ≥60% GOLD — a+b=c+d (no "answer side"), c=a+b (reversed; attacks "answer can't come first"), a+b=b+a (commutative; relational reader rules TRUE WITHOUT computing — diagnoses + teaches the structural insight). STRONG subtraction ≥~20% (7=8-1, 9-2=3+4). USEFUL EDGE 6=6 sparingly. **Canonical a+b=c CAPPED ≤15%** (an arithmetic-fact check the operational reader handles perfectly — harmful if dominant). 40-60% TRUE; ≥1 commutative-TRUE always present.
- **Both verdicts justify UNCONDITIONALLY** (one-sided proof is ~75% gameable; the operand-bound deposit makes TRUE-justify a genuine read-both-sides act, killing compute-left-only).
- **4 balance pitfalls honored:** (1) COUNTING balance not weighing (identical unit counters, integers, no half-tips); (2) the animation never does the thinking — child READS→RULES→JUSTIFIES; the beam settles to CONFIRM only AFTER a correct justify, and the wrong-verdict beam stays STILL (fix #1); (3) NO unknowns/add-to-balance (sibling territory); (4) the symmetric beam breaks "answer on the right" (8=6+2 looks as natural as 6+2=8).
- **Picture scaffold + FADE:** faithful unit counters in each pan early (count ALWAYS matches the numeral, never a mismatched "trick"), faded to symbols-only across the pass (goal = ruling symbolically); even in picture rounds the justify forces a symbol-touch.
- **Numbers:** default within 10 (facts near-automatic → effort goes to balance, not adding); within 20 stretch; two-digit ONLY in the compare act (#4), no addition.
- **No-shame re-teach:** "this much AND this much — are they the same?" + fill/pair both pans (forcing evaluation of the skipped RIGHT side — the compute-left-only cure) + name commutativity ("same numbers, just swapped — still the same amount").

## Interaction & UX
- `engine-judge-balance.js`: builds each row from a STRUCTURED expression (never hand-written); every numeral/op/"=" is its own tappable `<span>` (data-val/data-role). "=" renders as the FULCRUM (triangle ▲ under a horizontal beam, left expr in the left pan, right in the right pan, the literal "=" centred on the beam) → "two pans on a balance," never "left → result."
- Stages via shell `stage`: stage 0 verdict (beam static) → correct verdict reveals stage 1 justify (no `ctx.correct()`) → correct justify fires `ctx.correct()` ONCE **EXCEPT on the ~30–40% of FALSE GOLD rounds that reveal stage 2 "Now Fix It" (the repair): the child places the level-restoring tile into the swap-slot → `ctx.correct()` then.** **Wrong verdict → beam STILL + non-directional "are you sure?"; 2nd wrong → guided both-pans re-teach. Wrong REPAIR commit → beam STILL + Tess "still not level — here's a fresh one" → REGENERATE a new FALSE round of the same GOLD form (never re-serve the same beam); 5–6-tile tray, decoys straddle the target (magnitude-bracketed).**
- Truth + proof DERIVED at runtime: `evalSide()` walks each token stream → L,R → `isTrue=(rel holds)` → `heavier=sign(L-R)` → `correctRel`. No stored truth flag.
- TTS reads RELATIONALLY ("five plus two — is that the SAME AS two plus five?"), never "makes…".
- **Mobile @280-768 (fix #5 — the equation stays HORIZONTAL; the vertical-stacking see-saw is REJECTED because it severs the left-right equation reading 1.OA.D.7 assumes):** below 520px SHRINK the see-saw chrome, NOT the equation axis — left pan | fulcrum | right pan stay horizontally adjacent; if a pan's expr can't fit, its operands wrap WITHIN the pan (the wrap point is inside a pan, NEVER at the "="). ## Runtime mapping + MEASURED build-gate + PER-LOCALE
- **Round descriptor (DATA; engine never holds a localized sentence):** `{ type:'judge|spot-false|sort|choose-rel|wobble-meter|commutativity-construct|build-the-balance', expr:{left:[{t,op}...], right:[...]}, rel:'=', witness, promptKey, choices?:[expr] }`. Truth + proof DERIVED; NO trusted `isTrue` field.
- **`verify-judge-balance-core.js` (MEASURED — generates the real round set + drives the real engine; HALTS build):**
  - **THE DUMB-SOLVER GAUNTLET (the headline — analog of Game 5's counting-solver / Game 6's four solvers — now covering BOTH stages, fix #6):**
    - **Verdict-stage dumb solvers — must score ≤ 0.50** (≤ the base rate any constant-guesser gets from the 40-60% true ratio): `compute-left-only` (FAILS on commutative + reversed — the core proof), `pick-bigger-side`, `always-true`, `always-false`, `pick-canonical-order`.
    - **Justify-stage EXPLOIT solvers — must score ≤ 0.35** (target real leaks, must be visibly destroyed): `always-fill-both-pans` (the rote TRUE-justify cheat — FAILS only because deposits are operand-bound per fix #2; this solver PROVES the leak is closed), `always-tap-bigger-pan` (correct on FALSE-justify but wrong on every TRUE round — scored over the full mix → ≤0.35), `glyph-match-pairing` (FAILS because the justify pairs quantities/re-orders piles, fix #2).
    - **Stage-3 REPAIR EXPLOIT solvers (merged from #29; cover the repair stage) — must be visibly destroyed:** `brute-force-within-round` (commits tiles in sequence until the beam settles → **MUST FAIL: assert median repair-placements-to-success ≥ tray/2** across repair rounds — proves regenerate-on-wrong + a ≤1/5 tray make guessing no faster than reasoning; THIS is the adversary the standalone #29 gate MIS-MODELED, the headline merge-fix); `sign-only` (picks the larger/smaller tile from the tilt's sign alone → **MUST FAIL** because the decoys straddle the target, magnitude-bracketed); `copy-a-visible-token` (writes the most salient other-side number into the slot → **MUST score 0** — the repair forms are GOLD non-standard, non-copyable).
    - **`always-balance` honest oracle — must PASS** (incl. the repair stage: the level-restoring tile).
  - **Derived-not-trusted:** the gate computes `isTrue` + proof-target by its OWN arithmetic; assert descriptors carry no trusted `isTrue` (or it must equal the derived value — mismatch FAILS the build).
  - **Form-distribution:** ≥60% GOLD; ≤15% canonical a+b=c; 40-60% TRUE; ≥1 commutative-TRUE; subtraction ≥~20%.
  - **Ranges:** all 1.OA ≤20 (default ≤10); two-digit ONLY in `choose-rel` (≤99) with NO `+`/`−` in either side (assert compare rounds contain no operation).
