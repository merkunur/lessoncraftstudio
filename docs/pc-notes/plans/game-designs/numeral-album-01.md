> 6-expert ensemble (2 designers + math-pedagogy + web → creative-director synthesis → adversarial premium critic). **The pedagogy authority ruled the catalog mechanic the most dangerous empty-pass in early-number design:** "assemble 1-5 in order into numbered frames" is **symbol-matching** (drag a printed "3" to a printed "3" — zero quantity) + ordering; a non-counter passes 100% by glyph-pairing. REJECTED. Rebuilt as **quantity→numeral PRODUCTION.** Critic then returned **NEEDS-REWORK** (7) — **the 0-9 digit palette was the symbol-matcher in a new costume** (it moves the printed glyph from before-counting to after-counting; counting 3 then tapping the palette "3" is SELECT not PRODUCE, and a 10-key palette + no-fail + infinite retries is brute-forceable in ≤10 taps). **The fix (one move resolves five holes): the COUNT-ENACTED production control** — the child taps each treasure object once (the one-to-one count; the counter ticks), and the press MINTS the numeral from that count (no glyph menu to select/match/brute-force; the only path is counting every object; brute-force overshoots, not exhausts; one element → 280px-safe; the forge becomes load-bearing — each counted object is drawn INTO the forming foil numeral, so the "3" is made of the three things). ## 2. Concept & creative hook
Rivet the raccoon runs a cluttered, cozy **junk-shop FORGE** behind a velvet curtain. Foil packs don't hold finished cards — they hold a spill of **TREASURE** (acorns, buttons, fireflies, marbles). Tear a pack and the loot **tumbles across the workbench** with a clatter. To turn loose treasure into a finished, foil-edged COLLECTOR CARD, the child must **count it and forge its numeral** — and *the press only works because they counted.* The agency hook: **you don't collect the cards, you FORGE them out of counted treasure, one honest numeral at a time.**
- **THE COUNT-ENACTED PRODUCTION (the critical rework — no glyph palette):** the child **taps each treasure object once** to count it (one-to-one; a re-tap is a no-op; the running count shows: 1… 2… 3…). As each object is counted, it is **drawn INTO the forming foil numeral on the card** — so the "3" is literally **built from the three things** (the numeral↔quantity bond made visible; the forge is load-bearing, not décor). When every object is counted, the child pulls the **STAMP LEVER** → the press *CLUNK*s, the foil numeral presses up (the count's written sign), and the card **flies to the album.** **There is NO 0-9 glyph menu** — the numeral is MANUFACTURED by the count, so there is nothing to select, match, or brute-force. (The rejected 0-9 palette was the symbol-matcher in a new costume + a 10-way exhaustion cheat.)
- **Why this is genuinely PRODUCE + non-brute-forceable:** the only way to mint the right numeral is to **count every object once** (a no-count commit → the wrong count → the wrong numeral; a brute-forcer tapping random objects → overshoots/undershoots, never lands; tapping ALL objects IS counting them — the skill). The press mints the count the CHILD produced.
- **THE CARD OF NOTHING (the 0-case, REQUIRED + hardened):** sometimes a pack tears and **nothing spills** — an empty bench. Same mechanic: there's nothing to count → the counter stays at **0** → pull the lever → the press mints a beautiful **"0"** card (a wreath around a clean zero — Rivet's rarest, "nobody else has a zero!"). Produced by the SAME count-enacted mechanic (no special key), interleaved unpredictably (never a fixed slot), framed as felt absence ("there's nothing — and nothing still has a name").
- **The collect-trade set-completion (the standard + the thrill are the same act):** a binder **PAGE** ("The Acorn Hoard," "The Firefly Jar") wants a SPREAD of distinct amounts (NON-ASCENDING — anti-ordering); the child fills it by counting each pack + forging its numeral. The page **gilds** when complete; the album is the keepsake (`GameCollection`). Completing the set REQUIRES producing varied numeral↔quantity links.
- **Anti-generic statement:** NOT a count-and-write worksheet + a raccoon — (a) the numeral is MANUFACTURED by the count (no glyph menu; the "3" is made of the three things — the theme is cognitive-load-bearing); (b) gate-proven non-brute-forceable (count-coupled production; no symbol to select/match/exhaust); (c) the 0-case as a celebrated card; (d) the collect-trade set-completion; (e) a board ships only if a **symbol-matcher solver**, a **palette-recognizer solver**, and a **brute-force (no-count) solver** ALL fail while a **count→produce solver** passes (§8).

## 3. Core loop & the ≥7 distinct experiences
**Loop (`stage`: tear → count → forge → album):** tear the foil pack (treasure tumbles) → **count each object once** (tap each; the counter ticks; each object drawn into the forming numeral) → pull the **stamp lever** → the press mints the numeral (the count's sign) → the card flies to the binder page → repeat until the page is full → the page gilds, `ctx.correct()`. **No fail, no timer, no score, no Check button.** A wrong forge (commit before all counted) → the press wheezes, no card, **the treasure stays on the bench** + Rivet: "not hot enough yet — count 'em again" (the re-count re-presents the set in a NEW arrangement, so spam-memory doesn't carry). The assessment signal = **first-attempt-correct** (internal, never shown).

**The ≥7 distinct experiences — HONEST re-derivation (the critic's catch: teens = a magnitude-knob, reverse = a different standard — both blocklisted from the act-count): distinct = the CHILD'S ACT, NOT a bigger number / different treasure / modality.** Each carries a declared **`act_type`** (gate-keyed with a blocklist, §8):
| # | Experience (the distinct ACT, `act_type`) | Render / act | Why it's distinct & instantiates A.3 |
|---|---|---|---|
| 1 ★ | **Count-and-mint** (`count-mint` — the core; scatter/row/ten-frame + teens are the INTERNAL knob) | count each object once → the count mints the numeral | the count-enacted production (the numeral manufactured by counting); the arrangement + the 0-20 range (incl. teens) ride WITHIN this act, NOT separate experiences |
| 2 ★ | **The 0-case** (`zero` — mint a numeral for ABSENCE) | empty pack → nothing to count → counter 0 → mint "0" | producing a numeral for the absence of quantity — the standard's named special case; conceptually distinct |
| 3 ★ | **The Parade** (`parade` — transient-sequential count) | treasure marches INTO the forge one at a time + DISAPPEARS → count the parade (working-memory; can't re-count a static set; a visual transient per object → mute-safe) → mint | a working-memory sequential count (vs a static set) — a genuinely distinct counting act |
| 4 ★ | **Count-the-subset** (`subset` — attribute-filtered count) | a mixed pack (3 acorns + 2 caps); the recipe wants only the ACORNS → count just that kind → mint | selective-attention count (count a subset) — a distinct reasoning |
| 5 ★ | **Verify-fix-a-claim** (`verify` — judge the numeral↔quantity bond) | Rivet minted a card "6" on a picture of 5 things → the child catches it + re-counts + re-mints the TRUE numeral | the PURE symbolization judgment (does this numeral represent this quantity?) — directly confronts the symbol-matcher reflex |
| 6 ★ | **Build-then-mint** (`build-mint` — produce a set, then its numeral) | the recipe asks for a card; the child ASSEMBLES a quantity (drags N treasure into the pack) → counts → mints its numeral | production from a self-made set (the child makes the quantity, then represents it) — flagged for playtest |
| 7 ◦ | **Reverse: numeral→quantity** (`reverse` — the SECONDARY K.CC.B.5, honestly labeled) | a customer's ticket shows "7" (a numeral) → the child produces 7 objects (count out that many into a pouch) | the bidirectional bond, run backward — **honestly K.CC.B.5, ≤1/set, NOT counted as a distinct A.3 act** (the gate blocklists it from the A.3 act-count) |

- **Honest framing (the §A.13.60 fix + the critic's blocklist):** **5 firm A.3-distinct child-acts (1-5)** + build-then-mint (6, borderline, playtest-flagged) + the reverse (7, the ≤1/set secondary-B.5, honestly labeled). The variety gate keys on `act_type` with a **BLOCKLIST**: "differs only in number magnitude" (teens), "differs only in modality," "differs only in standard" (reverse) do NOT count as a distinct A.3 act. Scatter/row/ten-frame + teens + the contexts ride WITHIN #1. Order-only reshuffle.
- **Free slice = count-and-mint (1) + the 0-case (2) + verify-fix (5)** — proves the count-enacted production + the absence-numeral + the symbolization judgment.

## 4. Win-states & juice (no competition)
No timer/score/streak/countdown/**fail-state**/attempts-counter/"X of Y". **THE FORGE (signature, load-bearing — the theme does cognitive work):** as the child counts each object, it's **drawn into the forming foil numeral** (the "3" built from the three things) + a soft *clunk* per count + `ctx.speak()` the number word ("…three!"); pull the lever → *CLUNK-SHHK*, the numeral presses up, the card flies to the album (FLIP). **THE CARD-OF-NOTHING reveal:** empty pack → mint "0" → "No treasure at all — that's zero! Zero is a number too" (the rare wreath card). **Non-numeric vessel = the BINDER filling** (`GameCollection`) — each minted card drops onto the page (a real thumbnail, the empty slots a physical gap); the page gilds when full; a shelf of completed-hoard spines grows. No "8/8", no bar. **Negative signal = no-shame re-count ONLY:** a wrong forge → the press wheezes, NO card, **the treasure stays on the bench**, Rivet nudges "count 'em again" + a finger-bounce highlights each object as `ctx.speak()` counts along; the re-count re-presents the set in a NEW arrangement (anti-spam). Never a buzzer/removal. **`ctx.wrong()` is a soft "not yet."** `ctx.correct()` fires on the FULL page → auto-advance. Full-pass keepsake = the gilded binder → cross-game `GameCollection`. CSS/SVG/WebAudio; reduced-motion (the forge/flight are instant); mute-safe (the parade's visual pulse + the minted numeral carry it).

## 5. Pedagogy
- **K.CC.A.3 instantiation:** the child REPRESENTS a counted quantity WITH a written numeral — and the numeral is MANUFACTURED by the child's one-to-one count (the count-enacted production), so the count→numeral symbolization is the child's act + made visible (the "3" built from the three things). The kept card is the permanent numeral↔quantity pairing.
- **THE KEYSTONE RULES (non-guessability):** (i) **THE NUMERAL IS MANUFACTURED BY COUNTING (no glyph menu)** — there is NO 0-9 palette to select/match/brute-force; the only path to the right numeral is counting every object (`printedNumeralsOnPage` is 0 throughout — no answer-glyph EVER exists for a symbol-matcher or palette-recognizer to read). (ii) **COUNT-COUPLED ⇒ NON-BRUTE-FORCEABLE** — a no-count commit mints the wrong count; brute-force overshoots/undershoots; the assessment is first-attempt-correct (internal) + the re-count re-arranges the set (anti-spam-memory). (iii) **DIFFERENT SURFACES** — the quantity (treasure) and the numeral (minted on the card) are different surfaces; the answer-numeral is never pre-rendered. (iv) **0-CASE via the SAME mechanic** (count nothing → mint "0"; leading-zero guard "03"≠3). (v) **NON-MONOTONIC page quantities** (anti-ordering — you can't sequence your way through).
- **PRODUCE vs SELECT vs TRACE (the pedagogy bar):** the count-enacted minting IS the PRODUCE bar (the quantity enacts the numeral — no option-set; the critic ratified "quantity enacts the numeral = genuinely PRODUCE"). A 0-9 SELECT palette survives ONLY as an explicit accessibility-floor toggle (for a child who'd rather type), never the premium default. Numeral-tracing is NOT A.3 (handwriting).
- **Direction:** quantity→numeral is the A.3 CORE (the spine + the gate target); the reverse (numeral→quantity) is K.CC.B.5, the ≤1/set honestly-secondary reinforcement, never dominant, blocklisted from the A.3 act-count.
- **Number ranges (pedagogy):** **0-10 core** (scatter≤6 / row≤9 forces one-to-one counting); **11-20 teens optional-advanced** (the ten-frame scaffolds the two-digit numeral — count a full ten + ones → mint "14"; NOT place-value understanding; never weight toward teens; teens are a magnitude-variety WITHIN count-and-mint, not a distinct act). The 0-case required. Page = 4-6 distinct, non-ascending quantities, ≥1 zero.
- **Distinctness from the free numeral activity:** the free tile is SELECT/read-the-numeral (recognition, quantity-light); this PRODUCES the numeral from a counted quantity (gate-proven non-brute-forceable) + the collect-trade set-completion. If the game could be completed without counting, it's the free tile — REJECTED.
- **No-shame:** a wrong forge mints no card + keeps the treasure + a guided re-count (the re-count IS the counting strategy); the 0-card is celebrated; the forge is the intrinsic reward. **§20.8 demonstrate-don't-touch:** the catalog symbol-match TOUCHED numerals without instantiating A.3; the count-enacted forge ENACTS the symbol-referent link — the gate (symbol-matcher + palette-recognizer + brute-force solvers all fail) is the structural proof.

## 6. Interaction & UX
- **Runtime: the count-enacted minting (the one primitive).** `numeral-album-core.js` holds `{ page:{frames:[{count, arrangement, kind?}]}, counted (the Set of object-ids the child has tapped this frame), committed }`. Mutators: `tapObject(id)` (one-to-one count; re-tap a no-op; the running count = `counted.size`), `pullLever()` → mints IFF `counted.size === frame.count` (every object counted; for the 0-case, `counted.size===0` on an empty frame). `numeralRepresents(count)` renders `String(count)` (leading-zero guard: "0" valid only alone; teens render two digits). **No pair/select API; no 0-9 palette; no pre-rendered answer-numeral** — the numeral exists only AFTER the count-enacted mint. The counted objects are drawn into the forming numeral (the load-bearing visual).
- **State separation (anti-cheat):** `snapshot()` exposes `{ frame, countedSize, committed, minted }`; `facts()` exposes per-frame `{ count, arrangement, renderedSetCardinality (===count), printedNumeralsOnPage (===0 pre-mint), firstAttemptCorrect }` for the gate.
- **The count interaction:** tap each treasure object (≥44px hit-halo; the object dims/checks + flies into the forming numeral + speaks the count); a re-tap is inert. The **stamp lever** (≥44px) commits. Tap-to-count is the 280px-robust primitive (no drag needed); a deliberate-recount on a wrong forge re-arranges the set.
- **Teens (the ten-frame):** for counts 10-20 the treasure arrives in a **ten-frame carton** (a full 10 + loose ones) so the count stays tidy + countable at 280px; counting it mints the two-digit numeral (the ten + ones drawn into "1" and "4").
- **Mobile @280px (truth-tested — the count-enacted control is ONE element, no 11-key palette):** **sequential surfaces, NOT co-resident** — the **count surface** (the bench: the treasure to tap-count + the lever) and the **album** (the result view, advanced to after minting) are separate stages, so the teen ten-frame + the lever fit without competing with the full album. No 0-9 palette → no 11-key-row overflow. `audit-game-mobile.js` 280-768 empty + filled (the teen ten-frame of ~15-20 on the bench + the lever; the album page): assert ≥44px object-halos + lever, no overflow/clip/overlap, the count surface + album never co-resident at 280px.
- **Accessibility:** TTS speaks the count per tap + "you forged three for three acorns" (`_NUMBER_WORD_HELPERS`); `ctx.announce()` mirrors the count, the mint, the page-fill; keyboard path = each object is a button (Enter counts it), the lever is a button (no pointer needed); ≥44px; reduced-motion (instant mint/flight); mute-safe (the parade's visual pulse + the minted numeral carry it); not color-only (the count + the minted numeral are real text/structure).
