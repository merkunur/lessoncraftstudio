## Deviations from the design file (each with the measurement)
1. **Set A carries 12 items, not 8; sets B/C exist but are refused.** The design's ladder needs 10 rows at d3 and a fresh sample per seed at d2, but "set A: 8 with disjoint parts" leaves d3 nothing to sample and makes every d2 page the same 8 items. Rule: a set's parts are all distinct (2N for N items, validator rule 4 — poison P4 still fails), a set below 8 is REFUSED (reported), the exemplar must reach 8 (else the locale fails) and 10 for d3 (else d3 is reported refused on that set). en: A 12 (of the 13 disjoint max — pancake cannot join A because cheesecake owns `cake`; the three `cake` compounds can occupy at most two sets), B 4, C 1 → one shippable set. The panels should aim at two sets of ≥ 10.
2. **`opaque:[…]` at bank level (ADDITION 2).** The design places `opaque:true` on items inside the sets; an opaque item inside a base set now FAILS (poison PU) because the base is meaning synthesis and the sets are what the fan ships. F2/F4 draw from `units ∪ opaque ∪ onePart`.
3. **`pic:{theme,noun}` pins on parts (ADDITION 3).** The §5 shape has no pin; without one `pictureFor` picks any candidate, so a key with one dishonest candidate (chair → deckchair, basket → eggs, shelf → grey disc, star → outline, pan → pot, flower → sunflower-lookalike) would leak. The pin is optional; the gate's OPENED record locks BOTH ways: a pin must be a colour candidate opened as honest, an unpinned key must have ONLY honest candidates.
4. **Rule 6 (foils) reads "declare the split", not "no split".** The design's own example `carpet {looksLike:['car','pet']}` contradicts its rule "not x + link + y for any two pictured words" only when both parts are pictured; `pet` is not, so `carpet` passes either way. Implemented: a foil is never a pool whole and never CONTAINS one; a foil that DOES split into two pictured words must declare exactly that split in `looksLike` (auditable, poison P6b), and `looksLike` must join to the foil.
5. **The body is not 760, and d1/d2/d3 are not budgeted to one number.** Measured bodies: en 778, de 4-line title 700, fi 3-line title 733 (the README 722 is neither). Rows are `minmax(0,1fr)` grid tracks with the content centred; the fixed parts are the lane SVG (76/64/50) and, at d1, the 64 + 2 + 20 picture-and-word column; gaps 8 (design 12/12/10); inline `.ws-lane` padding `6px 14px` (d1/d2) and `4px 14px` (d3) instead of the design's 8/14. d1 pictures are 64, not 68: 68 + 22 + 12 + 4 = 106 per row × 6 + 40 gaps + 120 bank = 796 > 722; with 64 the d1 page is exactly full at a 700 body (90 px rows, 0 slack) and has 2 px per side at 722. Both chrome fixtures are gate assertions (each ≤ 740, the deepest ≤ 705 — a fixture that proves nothing is a fail).
6. **`minLinked` at d2/d3 resolves to 0 where the locale has no link.** Config 2 / 4 as the design; `build()` resolves `links.some(l => l) ? d.minLinked : 0` and stamps the resolved value (`data-lcs-min-linked`); guards key on the resolved value (en = 0).
7. **Lane capacity is measured, not the design's "≈ 21 px per glyph" estimate.** The spec's guard uses 0.75·glyphH per glyph (= 21 at glyphH 28, from the platform's letter-strokes model: 18.1–20.9 px per glyph for 10–14-letter words); the gate measures the real school-hand width of every stamped whole (`textGlyphs` × the lane's scale) and asserts ×1.5 ≤ lane − 16. The 14-letter cap stands exactly (`Kleiderschrank` 381 ≤ 394, `varvassandaalit` 412 > 394).
8. **The row's part-word column can narrow the lane.** A wide d1 part word (fi/de) widens its picture column; `build()` shrinks the lane accordingly and refuses when it drops below the capacity need (never below 60); verify() asserts the real lane ≤ the stamp. en never triggers it (widest d1 part `basket` ≈ 54 px < 64).
9. **The d1 bank is exempt from "no text node equals any stamped whole".** The design prints the wholes in the d1 bank AND forbids the whole as text; implemented: outside the bank, no text node equals a whole; the bank must be exactly the set of wholes, in `collation.js` order, and the rows are re-shuffled until their order differs from it.
10. **Stamps carry the words as well as the keys** (`data-lcs-a-word`, `-b-word`, `-a-stem`): the design stamps only keys, but verify() runs in the page and cannot reach the bank, so the whole is re-derivable only from stamped literals. The node cross-check then checks every literal against the bank VERBATIM (poison G1).
11. **The gate's `TOTAL` is 28, not the design's 11 + 10 list**: several design poisons are two-sided (bank rule + spec refusal), and the face-only ones (F1 box width, F2 seam tick, F3 derangement, F4 foil chips, F5 ghost opacity — design gate rules 3/4/5/6/9) are Phase 2.
12. **`data-lcs-face="base"` on the root** as the design says (G1-305/G1-306 precedent); K-319's `data-lcs-layout` ruling was about a tile attribute collision that does not exist here — Phase 2 should still key the faces on `data-lcs-layout` if a tile ever needs `data-lcs-face`.
13. **verify()'s row floor is 6** (the design's d1 = 6 rows) although the G23 density token says items [8,16]; the design's ladder wins for the scaffold level.
14. **`refuse.F5` stays false in en with only ONE hub ≥ 4** (fish 6; sun/rain/cake = 3): the design ships F5 en on "≥ 2 hubs of ≥ 4" — measured false; the validator REPORTS it (not a fail) so the panel/emitter rules `lanes:3` or refuses.
