## §1 — Concept / world
Pim the otter printer at Ferrybend Print Shop. The child holds ONE reused **step-stamp** carved with the constant step (+5/+10/+100) and prints a row of impressions down a **BLANK paper scroll** (no gridlines, no neighbor labels — the blank paper kills interpolation; the reused stamp = "the same jump, again"). To print the next impression the child computes last + step and **BUILDS the number on a place-value number-builder** (3-column ▲/▼ digit steppers — produce, not pick), then **PRESSES the stamp** (the deliberate commit). Felt magnitude = an ink-streak (firewalled non-tally, §4). Warm, no-shame: a wrong press → Pim re-shows the +N on a KNOWN neighbor (word-free), never reveals the answer, never a beep/score.

## §2 — The standard + the load-bearing cognition
**2.NBT.A.2 (sole primary)** — count within 1000; skip-count by 5s/10s/100s. **`also_teaches: []`** (the honest outcome — 3.OA.A.1 multiplication / 2.OA.C.3 parity / 2.NBT.A.1 decompose ALL fenced, each owned by another game). Strand = Base Ten. **Cognition:** continue a CONSTANT-STEP sequence (each term = prev ± step) by ADDING the step + (for by-10/by-100) SEE the place-value digit-move (by-10: tens advances, ones fixed; by-100: hundreds advances). **Band:** ~45% multiple-start / ~55% non-multiple-start (non-multiple — 3,8,13 / 7,17,27 / 40,140,240 — is in-grade AND the central anti-cheat: no chant visits them, and the fixed non-zero ones-digit makes digit-cycling give a constant wrong answer); MANDATE hundred-crossings (forward AND backward, §4); ceiling 1000 inclusive; backward ~25% (floor 0). **Fences:** NO equal-groups/products, parity, decompose-into-bundles, count-by-1, number-line-LOCATE, read-off-a-labeled-track.

## §3 — THE ARCHITECTURE REWORK (the heart; the deepest flaw + fix)
**The critic's deepest catch — the deliberate-commit was COSMETIC; the produce-builder traded MC-elimination for a CHEAPER hill-climb.** On a no-fail board the search space is NOT 1000 — the game DISPLAYS `landing(k−1)` and the stamp DISPLAYS the step, so the answer is a **1-2-tap nudge** off a number the game handed the child. A child sets the builder to (visible-last + step) and presses — reaching the answer by SEARCH/local-increment, never computing `landing(k−1)`, and every locked pattern-solver is BLIND (it's not a pattern — it's a nudge off the on-screen anchor). A skippable re-show is not a cost. (The Game-46 nudge-to-green + Game-48 enumerator reborn at the input-surface layer; the very fix for MC-elimination created it.)

**THE FIX — four composing locks (operator-confirmed the friction trade):**
1. **The immediate predecessor is NEVER a free on-screen anchor.** Next-term rounds are **DOUBLE-BLANK** (`…, ?, ?` — the child produces both in order; the first produced term is the child's OWN computed answer, held in working memory, the only anchor for the second). Internal blanks are **first-class TWO-STEP-GAP middles** (7,__,__,37 — interpolate gives 22, neither answer; the common-difference (37−7)/3 route IS the skill); **single-step middles BARRED** (avg(left,right)===landing, interpolate-trivial). Drop the old `count(middle) ≤ count(next)` cap (it conflated the two middle types). Cap by-5 single-next-term (the most searchable) to a minority.
2. **`ctx.correct()` fires ONLY from the stamp-PRESS handler, NEVER from a builder ▲/▼ change** — integration assert: set the builder to the correct value WITHOUT pressing → `correct()` must NOT have fired (the single most important integration test; without it the press is decorative and the anti-search story collapses).
3. **Wrong press = an UN-SKIPPABLE state transition (operator-chosen belt-and-suspenders):** the builder **CLEARS to zero** AND Pim's word-free **+N teaching beat** shows; the child taps "I see it" before the stamp re-arms. Warm (help, not penalty — no score/X/timer) but a forced transition the search loop cannot skip → computing-then-pressing is strictly faster than search-then-press.
4. **`GRADE_DISCRIMINATES`** — the grade rejects target±1 AND target±step (a +1 nudge off the visible last-term overshoots/undershoots → wrong press → cost).

## §4 — Anti-cheat architecture (the gate; tested against the cost-bearing state machine)
- **SPIN-TO-ACCEPT / BUILDER-SEARCH (the deepest cheat) — killed** by §3: `BUILDER_SEARCH_SOLVER` / `SPIN_TO_ACCEPT_SOLVER` ("start at the largest visible number, increment toward green, accept on first match") MUST FAIL **tested against the REAL cost-bearing state machine** (press-only commit + clear-on-wrong + the forced interstitial as state transitions it can't skip), NOT a frictionless accept.
- **DIGIT-PATTERN / ROTE-CHANT / INTERPOLATE — killed:** non-multiple starts (no chant) + cross-hundred (`DIGIT_PATTERN_NEQ_ANSWER`) + double-blank/two-step-gap (no clean neighbor to average). `DIGIT_PATTERN_SOLVER`/`ROTE_SEQUENCE_SOLVER`/`INTERPOLATE_NEIGHBORS_SOLVER`/FIRST/RANDOM all FAIL.
- **PLACE-VALUE-DIGIT-INCREMENT vs MAGNITUDE (the honest ceiling):** a child can learn by-10 as "tens digit +1" and cross-hundred as a SECOND carry-rule — cross-hundred does NOT fully isolate magnitude from learnable carry-competence. **MANDATE backward-cross-hundred** (105→95: "tens +1" fails, you must BORROW a hundred — no naive forward-carry analog) as the anti-mechanical-carry round. Honest note: mechanical place-value carry IS part of 2.NBT.A.2 at Grade 2; the game cannot fully isolate magnitude from carry — a stated ceiling, not a defect.
- **COUNT-VISIBLE-OBJECTS / streak leak — killed:** impressions are number-cards (single `<text>` glyph-string), never countable items. The ink-streak encodes **step-CLASS (exactly 3 discrete, viewport-safe lengths, IDENTICAL across all impressions in a round, NON-cumulative, NON-positional)**, NOT step-value-to-scale (a 10× by-100 streak would clip 280px AND afford ratio-measurement) — `VESSEL_NOT_A_TALLY` + the streak-step-CLASS assert.
- **IDENTIFY-step** (discrimination — exempt from produce-not-pick): ≥3 chips (+5/+10/+100 ALWAYS present, never 1-in-2) + the same un-skippable wrong-tap re-show (guess-both isn't free).
- **Structural asserts:** `ANSWER_DERIVED_NOT_STORED` (landing(k)=start+k*step; mutate start→answer shifts Δ; mutate step→shifts by unknownIndex; no stored landing/answer field), `NUMERAL_SET_INSUFFICIENT` (answer term never displayed; only start..landing(k−1) shown, unknown `?`), `STEP_MAGNITUDE_LOAD_BEARING`, `NON_MULTIPLE_START_ROUNDS_PRESENT ≥N`, `WITHIN_1000_BAND` incl. cross-a-hundred, ≥7 variety.
- **Word-free re-show:** the now-load-bearing interstitial uses ONLY visual numerals (advancing-digit highlight + a `+N` numeral badge, the digit animating) — zero number-words, so the numerals-only locale deferral (§7) stays clean.

## Cohort doctrine this game adds
**The INPUT-SURFACE-AFFORDANCE-ON-A-NO-FAIL-BOARD lesson — PROGRAM-WIDE.** The choice of answer-INPUT surface is itself an anti-cheat decision, and the fix for one input cheat can CREATE a worse one: a produce-BUILDER (chosen to kill multiple-choice elimination) is a SEARCHABLE CONTINUUM, and on a no-fail board the search space is NOT the full range but the TINY neighborhood the game HANDS the child (visible last-term + visible step → a 1-2-tap nudge). A "deliberate commit" alone is COSMETIC (a skippable re-show is not a cost). **The fix is THREE composing locks: (1) never leave the answer's immediate predecessor as a free on-screen anchor — double-blank / force a working-memory hold so the child computes the anchor too; (2) the commit fires ONLY from a deliberate action, NEVER from an input-change — INTEGRATION-ASSERT that setting the input to the answer without committing does not fire `correct()`; (3) a wrong commit costs an UN-SKIPPABLE state transition (clear-to-zero + a forced teaching beat) so search is strictly slower than computing — and the `*_SEARCH_SOLVER` must be tested against THAT cost-bearing state machine, not a frictionless accept; plus the grade rejects near-misses (target±1, target±step).** Generalizes to EVERY produce-input game on a no-fail board (number-builders, keypads, steppers, dials, free-text): a no-fail board makes any low-friction produce-surface search-able. (The Game-46 nudge-to-green / Game-48 enumerator lineage, generalized from a single game to the input-surface-design layer — and the operator-acknowledged truth that a fully frictionless no-fail board and a search-proof produce-surface cannot coexist; the minimum viable friction is a warm forced teaching beat.)
