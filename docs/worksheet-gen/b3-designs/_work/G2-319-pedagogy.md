Numbers are MEASURED 2026-09-14 unless marked *est.* Sources: `data/b2/sentences.js` (names x11, frames), `image-cache/resolve.js labelSafeNouns` + `lib/b2-common.js entriesFor`, the pictures themselves (contact sheet of 20, Read tool), `types/g1/G1-157`, `G1-158`, `types/g3/G3-348/349/351/353`, `types/k/K-068`, `types/_shared/picture-equation.js crossoutGroup` (the coral-X idiom), `templates/components.js answerBox:105`, `frontend/config/topics-taxonomy.json`, `frontend/content/seo-landing/{en,de}.json`, `frontend/lib/seo/strand-names.ts`, `scripts/seo-landing/gen-b2var-landings.js LEVEL_KEYS:112`, `_PANEL-FINDINGS.md` 19 + 15. Scratch (read-only, type-scoped): `g2319-solver.js`, `g2319-constructive.js`, `g2319-3attr.js` (solver statistics), `g2319-contact.png`.

**Boundary (load-bearing).** The whole visual-logic family (K-068, G1-157/158, G3-348/349/351/353, the `sudoku` app: 100 landings per locale, strand "Logical reasoning (readiness)") is NON-VERBAL: the constraint lives in the picture arrangement. **This type is DEDUCTION FROM CLUES**: named children, a native SENTENCE per clue, an elimination grid the child marks, one answer per child. Verify() is an exhaustive solver: exactly ONE assignment satisfies every clue, every clue is necessary, and the solution is reachable by single-cell elimination. Nothing here is a Latin square, a matrix, a Venn ring or a line-up.

**Five load-bearing measurements.**
1. **Names carry NO gender field** (`sentences.js`: 8 per locale, keys `nounCase endSpace names colorWords nounForms fixLabels frames`; `nameGender` absent x11). The lists alternate girl/boy by convention (en Mia Ben Emma Leo ...), which no code may rely on. Existing `{name}` frames use names ONLY as nominative subjects (fi: 10 frames, all nominative). So every clue frame must be gender-free and, in fi, the name's case forms are stored literals.
2. **Pictures within one theme are confusable** (contact sheet): pets fish ~ goldfish, turtle ~ tortoise, hamster ~ gerbil ~ chinchilla ~ mouse; fruits orange ~ clementine, peach ~ nectarine ~ apricot; toys car ~ truck. `labelSafeNouns` (pets 19, fruits 28, toys 30, vehicles 29, farm 25, zoo 34) is NOT a usable attribute pool: a puzzle's pictures come from a curated `distinct` allowlist per theme (section D), authored by opening every picture. The `colors` theme = 19 paint drops (red blue green yellow ... ), each with a vocab key: the language-free second attribute for F4.
3. **Solver statistics (constructive generation: solution first, add true clues until unique, strip redundant):** 3x3 negative-only = exactly 3 clues, 5,000/5,000; 3x3 with one positive allowed = 2 clues 76 % / 3 clues 24 %; 3x3 negative + either-or = exactly 3; 4x4 negative-only = exactly 6; 4x4 negative + either-or = 4 (79 %) / 5 (21 %) / 6 (<1 %); two-attribute 3x3x3 negative + <= 2 positive = 4 (40 %) / 5 (44 %) / 6 (16 %). **Every unique single-attribute puzzle measured (20,000 per row) was solvable by pure row/column elimination; two-attribute puzzles 99.8-100 %** (the rest need case-splitting and are REFUSED). Random clue sets are the wrong generator (3 random negatives on 3x3: unique 42.9 %; 5 on 4x4: never).
4. **The key is absent and the obvious slugs are TAKEN.** `apps['logic-puzzles']` = false, `axes['exercise-type']['logic-puzzles']` = false. `visual-logic` already owns de `logikraetsel`, sv `logiska-pussel`, no `logiske-gater`, fi `looginen-paattely`, es `logica-visual`, fr `logique-visuelle` (11 slugs), and `sudoku` owns `bilder-sudoku` etc. Section A picks slugs that are free AND are the panel's head.
5. **No strand row fits**: `strand-names.ts` has 14 rows (CC/OA/Geometry/MD/NBT/RF/RI/RL/Writing/PA/Language/Vocabulary/Fractions), none for reasoning. Landings render a raw `l.strand` per locale (the readiness precedent, §22.1), distinct from the sudoku family's label.

### verify() rules (browser; every value re-derived from stamps)
- Common: root `[data-ws-content][data-lcs-size][data-lcs-kinds]`; per puzzle `data-lcs-clues` (JSON `[{k,a,v,...}]` with INDICES), `data-lcs-solution` (index permutation(s)). Re-run the exhaustive solver over all permutations (6 / 24 / 36): **exactly one satisfies every clue and equals the stamp; removing any single clue leaves >= 2 (every clue necessary); the propagation solver (row/column single-open + transitivity for F4) reaches the full solution** (a puzzle needing case-splitting FAILS). Names on the page distinct, pictures distinct and all in `SETS.distinct[theme]`; every clue's rendered `{name}` text and `<img src>` match its stamped indices; `[data-lcs-cell]` cells contain no text, no `<img>`, no mark (blank mode); answer boxes empty; no clue kind outside `d.kinds`; clue count within `d.clues`. Two puzzles on a page use different name sets and different picture triples (no cross-puzzle leak).
- F0: all `neg`. F1: `minEither`/`maxPos` honoured. F2: `size:4`, 16 cells per grid. F3: no `<p>` clue text at all; each clue row = one name + one picture with `data-lcs-crossed="1"` (neg) or `data-lcs-ringed="1"` (pos); answer rows list exactly the 3 puzzle pictures per name, none marked.
