**The array-anchor fidelity call (the pedagogy's emphatic ruling):** anchor HARD on the rectangular array — the child READS the equal addends OFF the row-structure; they do NOT impose equality on a scattered set by trial (= 3.OA-readiness / general-equal-groups / division wearing an array costume, REJECTED). The scattered-set seed is demoted to AT MOST the odd/even sub-act.
**Distinctness — spine = DRAW the boundary (line-cut) on a GIVEN array → partition into equal ROWS/COLUMNS → read each pile → the total resolves as Σ equal addends (array→equation).** vs the LIVE **E13 array-core** ("Build the Array," same 2.OA.C.4 — equation→array: BUILD an R×C array to a PROMPT then a repeated-addition strip; THIS is the REVERSE — a GIVEN array, the child DRAWS the partition + SUPPLIES the numbers); vs Copy-the-Caterpillar (replicate structure); vs Give-Each-a-Fraction (set-fraction); vs Recipe Double/Half (scalar).

## Concept & creative hook
A squirrel sorts its acorn hoard into **fair winter piles** before the snow. The objects sit in a tidy rectangular array (rows); the child takes a chalk stick and **draws a line between rows** — slicing the array into piles. The wobbly stroke snaps with a **chalk-magnet glide + a dust puff** (the cut PREVIEWS before it commits, fix #6 — never a silent surprise).
- **Equality is the child's job, not a gift (the rework, fix #3B):** the child can cut at ANY whole-row boundaries — so they can make uneven piles (2 rows next to 1 row). **Uneven piles are UNFAIR** — they do NOT sparkle, the squirrel can't store them. The child must JUDGE: "to be fair, every pile needs the same number." Cutting at every line is the simplest fair partition, but many rounds ask for a *specific* fair split or to *fix* an unfair one — so "cut every gap blindly" is never a universal win.
- **The child reads each pile into the equation (the rework, fix #3A):** the addend slots start BLANK — `[ ]+[ ]+[ ]=?`. After each cut, the child **reads the pile and taps its count into the addend** (a tap-to-set stepper, NOT the engine counting). The number is the child's; the equation closes only when every supplied addend is correct AND all equal.
- **The signature beat — earned, with a real contrast:** fair piles (all equal) + correctly-read addends → the piles **SPARKLE IN UNISON** + the `=`+total slide in. *"Unfair piles can't shine together; fair piles sparkle as one."* Because UNFAIR is reachable + visible (un-sparkled, the equation refusing to close), the sparkle genuinely MEANS "these are equal" — the child SEES the contrast. The per-pile tally pops with a **rising pip at the same pitch every round** (even the sound is repeated-addition).
- **Anti-generic:** NOT a slice-the-array motor toy — (a) equality is a JUDGMENT the child produces (uneven cuts reachable + unfair), not a guarantee the rectangle hands over; (b) the NUMBER is the child's (read each pile, no auto-fill); (c) the equal-vs-unequal judgment is the spine; (d) a board ships only if a **blind-line-tracer** (cuts every gap, wrong numbers) + an **unequal-acceptor** both FAIL the gate.

## Core loop & the ≥7 distinct experiences
**Loop:** array appears (objects snapped to grid-cell centers) → swipe a line between rows (the snapped cut PREVIEWS; tap-the-gap is a co-equal path for sloppy fingers) → confirm → the pile resolves + tally pops (rising pip) + a BLANK addend slot appears → **read the pile + tap its count into the addend** → repeat → when all piles cut, all addends supplied-correct, all equal, ≥2 piles → FAIR: flip to stage 1, `=`+total slide in, piles sparkle in unison, the squirrel speaks the equation → tap the coral **"lock it in"** pill → `ctx.correct()`. Uneven / mis-read → no sparkle, the equation stays open `?`, redraw/re-read freely.

**≥7 distinct experiences — HONEST re-count (fix #5): distinct = a different JUDGMENT/REASONING + array SHAPE, NOT a different axis/count of the same "cut".** The spine is the **equal-vs-unequal judgment family** (the rework elevated it from a side-dish):
| # | Experience (the JUDGMENT) | Render / act | Why non-guessable |
|---|---|---|---|
| 1 ★ | **Make fair piles + read them** (anchor) | cut a given array into equal whole-row piles, SUPPLY each addend by reading the pile | equality is a judgment (uneven cuts reachable → unfair → won't close); the addend is read by the child (no auto-fill); count-all has nowhere to go (the addend is per-PILE) |
| 2 ★ | **Make exactly N fair piles** | "make 2 fair piles" of a 4×3 → 2 piles of 2 rows → 6+6=12 (NOT cut-every-line) | the child must CHOOSE where to cut so piles are equal; cut-every-gap-blindly produces the wrong #piles |
| 3 ★ | **Spot + fix the unfair piles** (repair) | a pre-cut UNEQUAL partition (3 rows + 1); the equation won't close; re-cut + re-read | the unfair partition GENUINELY can't be Σ equal addends (the math, not a label) |
| 4 ★ | **Reverse — match the given equation** (anti-guess) | equation shown (`4+4+4=12`), bare 4×3 array; cut + read to MATCH | direction reversed → can't read the answer off a sparkle; produce the exact pile-count + read the size |
| 5 | **Same total, two ways** (additive conservation, LATER) | cut a 3×5 by rows → 5+5+5=15; then columns → 3+3+3+3+3=15; the INVARIANT TOTAL the star | a different REASONING; "three rows of five"/"five columns of three" — NEVER "3×5" / "order doesn't matter" (the G3 commutative LAW) |
| 6 | **Odd/even — 2 fair piles?** (2.OA.C.3) | a single column of N; one cut into 2 equal piles; even→fair, odd→one left over | the 2.OA.C.3 definition; the 2-equal-pile partition only EXISTS for even N (the lone single-column exception) |
| 7 | **Arrange-then-cut** (structure-sense, HARDER contrast) | a near-array one row short — can't be cut equal as-is; the squirrel slides strays to complete; THEN cut + read | surfaces WHY the clean array matters — the impose-the-structure contrast |
| — | **Chocolate grooves** (1.G.A.3, absorbed) | trace the snap-grooves of a chocolate bar's equal rows → break + read 4+4=8 | a real-world equal-row array; the grooves ARE the gridlines; same validator + read requirement |

- The variety is the **judgment/reasoning family**, NOT axis/count re-skins. The variety gate asserts distinct by **(judgment-type × array-shape)** + REJECTS "same judgment + only axis/count differs" as a dup (§A.13.60). Decks span distinct (R,C) (2×3,3×4,4×2,5×3,3×5,4×4,2×5…), `makeRounds` procedural. **Free slice = make-fair-piles+read (1) + make-exactly-N (2) + spot-and-fix (3).**

## Win-states & juice (no competition)
No timer/score/streak/countdown/fail/attempts-counter. Per-pile tally pop (spring scale-in + `ctx.sound('pop')` + a rising pip at the SAME pitch every round). **The synchronized sparkle** (signature, now earned): a FAIR partition + correctly-read addends → all piles glitter IN UNISON + the `=`+total slide in + `ctx.speak()` the full equation. Vessel = an **acorn-hoard basket** gaining one acorn per round. **Negative signal = ABSENCE only:** unfair/mis-read → no sparkle, the equation stays open `?`, the equal-addends equation literally can't close. **`ctx.wrong()` essentially never called.** Erase = tap a committed cut-line (fat ≥44px hit-stroke) → fades, re-cut/re-read. The counter who got the total → redirected to the structure ("you found 15! now let's see WHY — make the fair piles + read each one"). Re-teach hints at the STRUCTURE never the solution (pulse the row guide-lines; animate ONE correct cut as a demo of the MOVE; slide two equal piles to show "same size!"). Full-pass keepsake = the filled hoard basket → cross-game `GameCollection`. CSS/SVG/WebAudio; reduced-motion; mute-safe.

## Pedagogy
- **The array-anchor instantiation:** present a rectangular array; draw boundaries ALONG THE STRUCTURE (whole rows/columns); each pile = one equal addend; the equation builds n+n+…+n=total. The line-cut makes the natural partition by-row/by-column → the child READS OFF the equality rather than imposing arbitrary blobs.
- **THE KEYSTONE RULE (now with the child OWNING the number + the judgment — the rework):** (i) every addend is BORN FROM A CUT-PILE (no addend without a cut; **NO type-the-total affordance** → count-all has nowhere to go); (ii) **the child SUPPLIES each addend by reading the pile** (no auto-fill — the original auto-derive made the child a line-tracer); (iii) **equality is a JUDGMENT** — uneven whole-row cuts are reachable + unfair + won't close (the original "unequal physically impossible" removed the standard's exact cognition + left the sparkle no contrast).
- **Two locks:** (A) STRUCTURAL — every pile is a whole-row pile → arbitrary-BLOB grouping impossible (the lasso's door closed by construction; but uneven CONTIGUOUS grouping IS reachable so equality stays a judgment); (B) ASSESSED FORM — validity DERIVED: all child-supplied addends correct (=== actual per-pile count) AND all equal AND #addends===#cut-piles AND Σ===R·C. Never the bare sum.
- **Pre-multiplication:** 5+5+5 NOT 3×5; `×` only a grayed "next year" preview, NEVER assessed.
- **Rows-vs-columns "same total two ways"** (a SEPARATE later sub-act): strictly ADDITIVE — "three rows of five"/"five columns of three," the INVARIANT TOTAL (conservation) the star; NEVER "3×5" / "order doesn't matter" (the G3 commutative LAW).
- **Odd/even (2.OA.C.3):** "can it be exactly TWO equal piles?" **K.OA.A.3:** the EQUAL-pair slice only (the general unequal pair = a TRAP, never offered). **3.OA.A.3:** drift if operative; preview only.
- **Ranges:** R∈[2,5], C∈[2,5] (EXCLUDE degenerate 1×n; the odd/even act #6 is the lone single-column exception). Totals [4,25]. **Vary the ARRAY SHAPE not 7 copies of 3×5.** Math-is-the-teacher no-shame (unfair stays un-sparkled; the equation can't close; re-cut+re-read free).

## Interaction & UX
- **Runtime: DRAW-A-DIVIDING-LINE-BETWEEN-ROWS, snapped to the nearest gridline** — a horizontal swipe is the most finger-robust gesture; the line-cut is inherently whole-row piles (forecloses arbitrary BLOBS by construction); the snap target is a whole LANE (~38px band) not a 38px dot. **Free-lasso REJECTED.** **Tap-the-gap is a CO-EQUAL primary path (fix #6 — not a hidden a11y fallback):** sloppy fingers tap, confident fingers draw; both get the chalk-snap juice + the SAME validator.
- **PREVIEW-before-commit + ambiguous-stroke handling (fix #6A):** the snapped cut PREVIEWS for confirm/cancel — never a silent surprise. (i) a diagonal (dx≈dy ~20%) → snap to the lane it STARTED in OR a "draw across the gap" nudge; (ii) a tap → the tap-the-gap select; (iii) a stroke spanning >1 boundary → snap to the boundary nearest the MIDPOINT + the "cut here" preview to confirm. Mis-snaps are visible + cancelable.
- **DOM/SVG — one shared viewBox `0 0 1000 1000` (CSS-scaled):** L1 array `<use>` sprites snapped to grid-cell centers; L2 pile bands + tally bubbles + **the blank/filled addend steppers** (fix #3A); L3 the LIVE `rg-ink` stroke + committed `rg-cut` lines + the cut PREVIEW; L4 invisible `rg-capture` rect (`touch-action:none`). **Equation = real DOM BELOW the field** — a `<span>`/stepper per token, `aria-live`, flex-wrap to ≥2 lines.
- **Capture & snap:** pointerdown `setPointerCapture` + screen→viewBox via `getScreenCTM().inverse()` (resolution/DPR-independent); pointermove rAF-throttled ink; pointerup RESOLVE (dominant-axis dx>dy→horizontal; median cross-axis → nearest boundary, ±cellH/2 ≈ 38px band) → PREVIEW → confirm → a cut = integer boundary indices → contiguous whole-row PILES → each pile's count = rowsInPile×cols. **ALL re-DERIVED every commit; the equation NEVER stored; the addends NEVER auto-filled — the child reads them.**
- **2-stage (shell `stage`, no inter-stage advance):** stage0 DRAW+READ (tally pops; read each pile into its blank addend; the equation stays open `?` until all addends supplied-correct + equal); flip `data-stage` to **1 only when VALID** (all piles equal + all addends correctly read + ≥2 piles) WITHOUT `ctx.correct()`; stage1 the `=`+total slide in + sparkle + speak + the coral "lock it in" pill (the real commitment after reading, fix #4) → tap → `ctx.correct()`. Another cut/edit in stage1 → flips back, un-resolves.
- **Mobile @280px:** field a CSS square (`width:100%; aspect-ratio:1; max 480px`) → ~248px at 280px; viewBox stays 1000. The GESTURE TARGET is a whole LANE (38px snap band) NOT a 38px object. **The equation gets its OWN vertical space BELOW the field (fix #6B), flex-wraps the 5×5 worst case (`5+5+5+5+5=25`) legibly, aria-live preserves order.** `touch-action:none` + `overscroll-behavior:contain`. Pass `audit-game-mobile.js` 280-768 empty+filled (incl. 5×5 + the stepper-filled states).
- **Accessibility:** TTS reads each pile's count as the child sets it + the full derived equation; the addend stepper keyboard-operable; tap-the-gap + tab-the-lanes co-equal; not color-only (valid = the sparkle ANIMATION + the equation RESOLVING [structural] + TTS + a ✓ glyph, never band tints); ≥44px; reduced-motion; mute-safe.

## Runtime mapping + MEASURED build-gate + PER-LOCALE
- **Round descriptor (DATA; stores ONLY the array + type — NO equation/addends/answer):** `{ id, type, array:{rows,cols}, object, axis:'row'|'col', target?:{addend,count} (match-equation / make-N), preset?:[boundary indices] (fix-the-unfair, an UNEQUAL pre-cut), goal?:'two-equal' (odd/even), twoWays? }`. The 7+ types all run on ONE engine, all DERIVED; `makeRounds` procedural (rows∈2..5, cols∈2..5, type).
- **`verify-draw-partition-core.js` (MEASURED — drives the REAL core; HALTS build):**
  1. **BLIND-LINE-TRACER solver must FAIL (fix #7A — THE headline, analog of Game 5's counting-solver):** a solver that cuts every gap with zero number/equality reasoning (blank/wrong addends) is REJECTED. Only `cut-correctly-AND-read-each-pile-correctly-AND-reject-unequal` PASSES (the UNIQUE passing class). Only has teeth because the addends are CHILD-SUPPLIED (fix #3A) — assert no auto-fill path completes the round.
  2. **UNEQUAL-ACCEPTOR solver must FAIL (fix #7B):** a solver accepting an UNEQUAL partition (uneven whole-row piles) is REJECTED — the equal-addends equation can't close. Assert unequal partitions are REACHABLE (uneven cuts commit) but never VALID (fix #3B).
  3. **COUNT-ALL FAILS** (no type-the-total affordance; the addend is per-PILE) + **WRONG-COUNT FAILS** (a supplied addend ≠ the actual pile count).
  4. **Equation === Σ equal addends, DERIVED from the cut-set + the CHILD's reads:** no stored answer; every addend traces to a cut-pile AND a child-supplied number; #addends===#cut-piles; each addend===per-pile count; Σ===R·C.
  5. **Equal-partition + whole-row FUZZER:** every COMMITTABLE cut is a whole-row/column boundary (arbitrary BLOBS impossible) AND uneven contiguous groupings ARE producible (equality is a real judgment).
  6. **Dimension validity:** 2≤R≤5, 2≤C≤5; exclude degenerate 1×n (the odd/even single-column case asserted separately).
  7. **Odd/even invariant:** even N admits exactly 2 equal piles; odd N cannot.
  8. **≥7 distinct experiences by (judgment-type × array-shape) (fix #5):** distinct JUDGMENTS (read+judge / make-N / fix-unfair / match-equation / two-ways / odd-even / arrange-then-cut), REJECTING "same judgment + only axis/count differs" as a dup; ≥7 distinct (R,C); order-only reshuffle (pass-2 ≠ pass-1).
  9. **`×` never assessed** (no multiplication symbol in any success predicate; preview-only in render).
