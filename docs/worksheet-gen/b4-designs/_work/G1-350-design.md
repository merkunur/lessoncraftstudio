## 4 Answer-hiding + uniqueness

- **The picture on the row is the key; the frame is the lock.** Every frame is authored as a whole literal with ONE `{gap}` and a stored `answer`; the panel signs each frame `single:true` = its predicate is satisfied by the pictured noun and by NO other noun a wave theme can put in the bank ("Der ___ bellt" not "Der ___ ist braun"). The code cannot judge semantics; it asserts the STRUCTURE: exactly one `{gap}`, the answer nowhere in the text (`(?<!\p{L})answer(?!\p{L})`, Unicode-aware, never `\b`), the row picture's vocabKey === the frame key, no key twice on a page, no bank word printed in any frame.
- **Base:** the bank is the answer set (d3: + `extra` frame-invalid words, each recorded); its order is a derangement of the row order (no pill index equals its row index; not the reverse either). Uniform box width (§2). Wrong = a word beside the wrong picture, or a bank word used twice: visible to the teacher in one glance because the picture sits 12 px from the box.
- **Letters (b):** the box count is the grapheme count of the answer, so the length is shown (inherent to the genre; the picture still fixes the noun). The answer is never printed. Wrong = boxes left empty or a letter squeezed outside.
- **Choice (c):** two chips, the correct one in a random position, positions balanced over the page (each position >= 2 of 6); the foil is authored (`foil`), same gender code, same elision class, frame-invalid. Wrong = the un-pictured chip circled.
- **Plural (d):** 2 or 3 clones of ONE picture; the hint chip prints the singular; the answer is the bank's plural literal. Wrong = the singular copied into the box (visible: the chip word repeated).
- **Story (e):** each block's three answers are three DIFFERENT keys, the strip shows them in sentence order (d2) so the picture order confirms the reading; the bank holds each of the nine once. Wrong = a bank word used twice or a picture unused.
- **Match (f):** right column deranged; each sentence names exactly one page key. Wrong = a picture with two lines or none.
- Every root stamps `data-lcs-mode`; verify() branches on that stamp, never on the level index.

- **Picture legibility at 44 px (opened, six native crops).** `animals` reads best: all 37 clear at 44; one-per-page twin groups {jaguar, leopard} (both spotted), {cat, tiger} (both striped orange), {swan, seagull}. `fruits` reads well only with twin exclusion: {apple, cherry, plum, pomegranate} (red rounds), {orange, clementine, grapefruit, peach, nectarine, apricot} (orange rounds; `nectarine` reads as a peach), {lemon, lime}, {blueberry, blackberry}; distinct at 44: banana avocado coconut fig kiwi mango papaya pear persimmon pineapple watermelon strawberry raspberry dragonfruit. `around the house` is the weakest: at 44 these are UNREADABLE and excluded outright: `hose` (a coil), `light_switch`, `outlet`, `picture_frame` (an empty frame), `kitchen` (a scene), `toothpaste` (a tube), `shampoo` (a pump bottle), `comb` (a hairbrush), `brush` (the recorded paint brush); twin groups one-per-page: {sofa, couch}, {fridge, refrigerator}, {oven, stove}, {carpet, rug}, {pen, pencil}, {clock, alarm_clock}, {lamp, floor_lamp}, {pot, pan}, {cup, glass}, {closet, wardrobe, cabinet, dresser, nightstand}, {lawn_mower, vacuum_cleaner}, {door, gate}. **Therefore the base and letter/choice rows use 56 px pictures (not 44), the plural clones 48, the story strip 44 only because those themes are panel-picked.** Theme order for the wave: animals > farm animals > zoo animals > vehicles > fruits > toys > classroom > around the house (the 8 priority themes; the per-theme `twins` + `unreadable` lists live in `data/b4/cloze.js` and the build takes at most one key per twin group per page).
