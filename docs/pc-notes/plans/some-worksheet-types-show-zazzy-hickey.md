# Surface 7 legacy worksheet families on the /worksheets hub page 1

## Context

**Problem (operator report).** Seven printable worksheet families are effectively
unreachable from the flagship hub `https://www.lessoncraftstudio.com/en/worksheets`.
A teacher only meets them through the *"More versions of this worksheet"* thumbnail row
on a landing page they arrived at some other way.

**Measured root cause** (not a missing-content problem — every one of these families
already has landing pages in all 11 locales):

`frontend/lib/worksheets-catalog.ts: interleaveByAxis` (line 112) buckets landings by
`coordinate.type` and orders the buckets **by size DESC**, then round-robins. With
`WORKSHEETS_PAGE_SIZE = 24`, hub page 1 is exactly *round 0* = one landing from each of
the **24 largest type buckets**. There are 53 type buckets. These seven sit at the very
bottom:

| family | landings/locale | bucket rank |
|---|---|---|
| `measurement` | 10 (of which 6 are the last batch) | ~30 |
| `telling-time` | 9 (of which 6 are the last batch) | ~31 |
| `number-charts` | 4 | ~50 |
| `geometry` | 3 | ~51 |
| `graphing-data` | 3 | ~52 |
| `arrays-multiplication` | 2 | ~53 |
| `fractions` | 2 | ~53 |

A family only reaches page 1 organically once its bucket passes ~47 landings. These
never will. The established remedy is the page-1 highlights strip
(`frontend/config/worksheets-new-highlights.ts`, generated by
`scripts/seo-landing/gen-var-highlights.js`) — but its `BASES` map only lists the 21
recent nt20/lowercase families. **Measurement and Telling Time *are* on page 1 today,
but only via their nt20 cards** (`capacity-and-mass`, `draw-the-clock-hands`) — precisely
"the last batch" the operator asked to exclude.

**Outcome.** A second strip on hub page 1 carrying one card per family (7 cards) with the
family's other grade bands as chips (14 chips) = **21 new internal links per locale × 11
locales = 231 links**, each opening an existing landing page. Nothing new is authored, no
existing page's identity changes.

**Scope note — the sibling thumbnails stay where they are.** The ~310 decks in the
"More versions" row per locale are RNG rerolls of the same worksheet
(`telling-time-g3344-2 … -10`, `fractions-easy-g2230-2`, …). The house ruling recorded in
`project_nt20_worksheet_types.md` rejects reroll-as-variation, and giving each its own page
would be thin content. They remain correctly placed in the sibling row.

**Churn freeze (§21.5a).** This is purely additive internal linking — no title, meta,
canonical, slug, or URL of any existing page is touched. Sanctioned.

---

## Decisions taken (operator-approved)

1. **Second strip, own heading** — directly below "New worksheets", so that heading stays
   honest for future launches.
2. **1 card + grade chips per family** — same visual grammar as the nt20 cards.

## Implementation

### 1. `scripts/seo-landing/gen-var-highlights.js` — add a second, family-scan resolver

Keep `BASES`/`GROUPS` untouched. Add alongside them:

```js
// Legacy families that will never reach hub page 1 organically (interleaveByAxis
// orders type buckets by SIZE and these hold 2-4 landings). One card per family,
// its grade bands as chips. Order = the card order on the hub.
const MORE_TYPES = [
  'arrays-multiplication', 'fractions', 'geometry', 'graphing-data',
  'number-charts', 'measurement', 'telling-time',
];
// nt20/nt20-VAR ids inside the two REUSED family keys — already carried by the
// "New worksheets" strip; excluded here so the two strips never duplicate a card.
const MORE_TYPES_EXCLUDE_IDS = [
  'g2252', 'g2260', 'g2261', 'g2262', 'g2263',                     // measurement
  'g1212', 'g1233', 'g1234', 'g1235', 'g1236', 'g1237',            // telling-time
];
```

**Resolve by scanning the corpus, NOT by re-deriving deck slugs from `(id, family, theme)`
triples.** This is load-bearing: the legacy landings' canonical deck slugs carry *different
ids and different themes per locale* — EN `graphing-data-toys-g1142` vs DE
`diagramme-tiere-g1144`; EN `measurement-fruits-k038` vs DE `messen-tiere-k038` vs FI
`mittaaminen-elaimet-k038`. The `BASES`-style triple approach would silently resolve
nothing in most locales. (This is the recorded trap: *derive themed deck slugs from the
measured published slug list, never from assumption*.)

Per locale, per family:
- select `landings.filter(l => l.coordinate.type === family)`
- drop any whose `canonicalDeckSlug` ends with `-<id>` for an id in `MORE_TYPES_EXCLUDE_IDS`
- sort by educational-level order, **derived from `topics-taxonomy.json`**
  `axes['educational-level']` (map each locale's native level slug back to its canonical
  key, whose order is preschool → kindergarten → grade-1 → grade-2 → grade-3). Reads from
  the SoT rather than duplicating the `LEVEL_ORDER` table that lives in TS.
- `base` = first, `variations` = the rest.

**Emit a second export into the same generated file** (one generator, one config file):

```ts
export const MORE_TYPE_GROUPS: Record<string, NewWorksheetGroup[]> = { ... }
```

Reuse the existing `NewWorksheetGroup` interface — no schema change; both arrays are
landing-slug pairs.

**Fail loudly on a short resolve.** The existing generator drops missing slugs silently,
which is right for a rollout-in-progress but wrong here: all 21 landings exist in all 11
locales *today*, so a shortfall means a bug. Print per-locale `groups/links` and exit
non-zero unless every locale yields **7 groups / 21 links**.

### 2. `frontend/config/worksheets-new-highlights.ts` — regenerated

Committed generator output. Gains the `MORE_TYPE_GROUPS` export; `NEW_WORKSHEET_GROUPS`
must come back **byte-identical** (verify with `git diff` — only additions).

### 3. `frontend/messages/<locale>.json` × 11 — one new string

`worksheetsPage.moreTypesHeading`, sibling of the existing `newHeading`. Written from each
locale's already-shipped catalog vocabulary in that same file (`browse.topicLinksHeading`,
`browse.filterType`) so it matches the page's own register — e.g. EN *"More worksheet
types"*, DE *"Weitere Übungstypen"*, SV *"Fler övningstyper"*, FI *"Lisää tehtävätyyppejä"*.
Tag the commit `[NSR-FLAG][sv,da,no,fi]` per §17.5.1.

### 4. `frontend/app/[locale]/worksheets/page.tsx` — render the second strip

- import `MORE_TYPE_GROUPS` next to `NEW_WORKSHEET_GROUPS` (line 47)
- build `moreTypeGroups` beside `newHighlightGroups` (lines 318-328) under the **same gate**
  — `!browseActive && page === 1 && filters.sort === 'variety'` — reusing the same
  `landingBySlug` rehydration and drop-if-unresolvable filtering
- render a second `<section aria-labelledby="more-types-heading">` immediately after the
  existing strip (after line 489), same card grid classes, `<h2>{t('moreTypesHeading')}</h2>`
- **chips are labelled with `levelChip(v.coordinate.level, locale)`** from
  `frontend/lib/worksheets-catalog.ts` — already exists, already covers all 11 locales'
  native level keys (`vorschule`, `2-luokka`, `da:1-klasse`, …), and matches the labels the
  rest of the hub already renders. The grade-band h1s are far too long for a chip row
  ("Grade 3 Geometry Worksheets: Quadrilaterals, Right Angles, Perimeter, and Area"), so
  carry the full h1 in `title`/`aria-label` for accessibility and hover.
- **`eager={false}` for every card in this strip.** `EAGER_CARDS = 6` (line 77) is claimed
  by the first strip; this one is below the fold. Leave the main grid's existing
  `newHighlightGroups.length === 0` yield condition unchanged.
- No JSON-LD change — the existing strip's links are not in `collectionSchema.hasPart`
  either, and this stays consistent.

## Verification

**Generation**
1. `node scripts/seo-landing/gen-var-highlights.js` → every locale reports **7 groups /
   21 links** for the new strip and the unchanged **125** for the old one; non-zero exit on
   any shortfall.
2. `git diff frontend/config/worksheets-new-highlights.ts` → `NEW_WORKSHEET_GROUPS`
   untouched, `MORE_TYPE_GROUPS` added.
3. Spot-check the generated slugs against the corpus for a Germanic, a Romance and a Finnic
   locale (de / pt / fi): the 7 bases are the lowest grade band, and no excluded id
   (`g2252`, `g1233`, …) appears in either strip's slugs.

**Build + render**
4. `cd frontend && npx tsc --noEmit`.
5. Dev-render `/en/worksheets`, `/de/worksheets`, `/fi/worksheets` — screenshots at
   **360 / 768 / 1024**, and I read the 768 and 1024 renders myself: 7 cards under the new
   heading, thumbnails resolving, chips localized and legible, no wrap or overflow.
6. Click through one chip per locale sampled — lands on the right grade-band landing (200).
7. Negative gate: `/en/worksheets?type=fractions`, `?sort=az`, and `?page=2` render **no**
   second strip (the shared gate holds).

**Deploy** (frontend-only; no `mini tools/` cp step needed)
8. commit + push, then `bash /opt/lessoncraftstudio/deploy.sh > /tmp/deploy.log 2>&1; echo EXIT=$?`
   — never pipe to `tail`, which masks a gate abort (recorded trap).
9. Post-deploy, allowing the 5-min Cloudflare TTL: `curl` all 11 `/<loc>/worksheets` and
   assert each contains the 7 expected base slugs and 14 chip slugs for that locale
   (231 links total), and that the two strips share no card.
