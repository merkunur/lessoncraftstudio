**Seven runtime families** (see CLAUDE.md §14.2):

  - typed-letter blanks → `word-guess.html` v13
  - multi-slot number+letter → `code-addition.html` v6
  - choice-button (tap-to-select images) → `more-less.html` v7 (and v17 big-small extends with order-N + image overlay)
  - global-cipher with auto-propagation + live legend → `cryptogram.html` v16
  - **deferred-Check choice-tap (v27.0)** → `odd-one-out.html` — first Family A port to break from the historical instant-feedback pattern; uses Family F's deferred-Check timing with single-select per problem and reveal-correct on wrong. Treats Family A's choice mechanic as compatible with Family F semantics; future choice-tap apps should follow this pattern.
- **Family B — Puzzle drag (v15, v29.2, v32.0):** spatial selection across a grid. Canonical references: `wordsearch.html` v15 (drag across a letter grid, snap to one of 8 directions, validate endpoints against placed words); `picture-path.html` v29.2 (drag-to-trace cell-by-cell with orthogonal-only moves + back-track + per-cell wall blocking + strict path validation against the bundled solution path; works for picture-pathway / classic-maze / choose-the-right-path uniformly); and `treasure-hunt.html` v32.0 (locked-to-start drag-to-trace, no walls, hidden endpoint, kid follows written direction clues to find an unrevealed treasure cell — closest variant to picture-path but with the start cell visible and the goal hidden, so the puzzle is "follow the directions accurately" rather than "find the path").
- **Family C — Grid-tap / Tap-to-mark + count-in-blank (v19, v30.0):** tap a worksheet cell or scene item to apply a per-task mark, with optional inputs overlaying baked-in legend blanks. References: `find-and-count.html` v19.1.2 (cell-based tap-mark per task type — circle/square/cross/count-dot — plus tap-only auto-celebrate for letter-spotting); `find-objects.html` v30.0 (busy-scene tap-to-mark with rotation/scale-aware bboxes; auto-fill legend counts from taps with `imgPath`-based direct lookup; dual-mode shared runtime via `mode` switch in the bundle).
- **Family D — Bar-chart cell tap (v20):** column-snap fill into a fixed grid of cells, per-column grading against expected counts, no typed inputs. Reference: `chart-count.html` v20.
- **Family E — Tap-to-connect line drawing (v21, v23):** tap left item then tap right item to draw an SVG line. 1-to-1 replacement semantics, tap-line-to-undo, green-dashed hint overlay for wrong lines. References: `matching.html` v21 (horizontal column pairs) and `shadow-match.html` v23 (top/bottom row pairs).
- **Family F — Drag-and-drop with deferred Check-Answers (v22.3, v24.3, v25.1, v26.1, v28.0):** pointerdown on palette tile spawns ghost (paletteReveal WebP at grid-cell scale), drag to ANY empty grid cell. Two-phase model: during "fill" every drop is accepted with no right/wrong feedback (no green, no red), pieces are freely movable between cells, Check Answers button is disabled. When all non-clue cells are filled, Check enables. Click Check → "reviewed" phase: correct cells get green glow, wrong cells get red inset border, all locked, celebration on all-correct. Try Again resets to fill. References: `grid-match.html` v22.3 (1-to-1 grid cells), `bingo.html` v24.3 (1-to-1 + announce-only caller), `picture-sort.html` v25.1 (multi-occupancy bins + STRICT scoring + Custom Words text-tile mode), `missing-pieces.html` v26.1 (shape-masked placed pieces over cutout holes + 1-to-N options-with-distractors + amplified wrong-piece cue with ✖ overlay + shake), `sudoku.html` v28.0 (4×4 picture-sudoku grid with **image-index matching** instead of cutout-identity matching — duplicate images interchangeable, since multiple sudoku cells legitimately need the same image).
- **Family G — Drag-with-caller (retired):** prototyped in bingo v24.0 / v24.1 — caller bar announces one random word at a time, only correct chip→cell→call locks, wrong drops snap back. Retired in v24.2 because the pre-drag visual hint on the matching chip defeated the literacy task; the operator preferred Family F semantics. No app currently uses this family. Kept here as a design note in case a future caller-driven activity needs to revive it.

**Shared attribution module** (`frontend/public/worksheet-generators/js/attribution-manager.js`, deployed-only, not in git):
- All 27 live apps include it via 7 standard edits (documented in CLAUDE.md §14.3).

- Interactive runtime overlays an invisible clickable `<a class="lcs-attrib-link">` at the baked text's world rect.

Nginx `location /image-library-webp/` block in place. Used by `image-references-v3` bundles to keep interactive HTML files small (no inlined PNGs).

**Deploy pattern per app:**
1. `git push origin pivot/printable-business-toolkit`
2. `plink ... "bash /opt/lessoncraftstudio/deploy.sh"`
3. `plink ... "cp '/opt/lessoncraftstudio/REFERENCE APPS/<app>.html' /tmp/<app>.html && /var/www/lcs-media/scripts/update-worksheet.sh /tmp/<app>.html <app>.html"` ← mandatory, `deploy.sh` alone does not refresh the `chattr +i` served copy.
4. Verify: `curl -s https://www.lessoncraftstudio.com/worksheet-generators/<app>.html | grep -c 'Interactive-HTML export v<N>'` must return ≥ 1.
