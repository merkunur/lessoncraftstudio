## 2. Concept & creative hook
**Coraline the Coin-Cat runs a sun-warmed market stall and delights in a secret: coins aren't worth their SIZE. "The little one's the rich one!" — she points, gleefully, at the dime (smaller than the nickel, worth twice as much). The child helps Coraline by UNDERSTANDING what coins are worth: count what a pile is worth, swap coins for equal value, pay with the fewest, and catch Coraline when she thinks "more coins must be more money!"**
- **VALUE ≠ SIZE, AS A MECHANIC (the premium hook + the standard's heart — the critic's deepest fix):** the coins render at their TRUE relative diameters (the dime really IS smaller than the nickel) — so a child who reaches for the "biggest coin" gets the dime/nickel WRONG every time. Size is a TRAP the game springs, not a proxy it allows. A `SIZE_SOLVER` scores 0% because the smaller dime is the richer coin.
- **THE EXACT VALUE DECIDES, NOT THE ORDER (the rote-order kill — the dominant cognitions):** the game leans on EQUIVALENCE ("Coraline's out of nickels — what's a nickel worth in pennies?" → the child swaps 5 pennies for 5¢, the EXACT 5, not "the next biggest") and VALUATION ("what is this pile worth?" → the EXACT total, order tells you nothing). A child who memorized only the rank ORDER (quarter>dime>nickel) — without the 25/10/5/1 cents — CANNOT do equivalence or valuation; the order-proxy collapses where the exact value is needed.
- **NO LIVE TOTAL — COMMIT THEN COUNT (the tuner kill):** the tray shows coins-as-coins (each stamped with its ¢ value in DOM text), never a climbing sum. The child holds the value in their head, taps "Pay the cat," and ONLY THEN Coraline counts aloud in value order ("twenty-five... thirty-five... forty-FIVE!"). A wrong amount hands ALL coins back (full reset — brute-force pays the full cost every time).
- **FEWEST-COINS rides along, demoted:** "Coraline purrs loudest for the fewest coins" — a recognizable, motivating mode, but a MINORITY (≤25%, never the entry) because for US coins it's greedy-passable; the premium claim rests on equivalence + valuation + the size-inversion.
- **THE PAYOFF:** value reasoned correctly → the item floats into the basket, Coraline purrs, a good + a ribbon join the stall (`GameCollection` — non-numeric AND non-content, NEVER a coin total). `ctx.correct()`. A wrong move → no fail; Coraline gently hands the coins back + a value-prompting hint ("count what you have so far" — never names a coin, never the gap number) + the child re-reasons.
- **Anti-generic statement:** NOT pay-the-shopkeeper (that's the FREE activity) — (a) the constrained purse + the `PENNY_COUNT_SOLVER` kill penny-counting; (b) the no-live-total + commit-then-check + `WRONG_COMMIT_FULL_RESET` + the `RUNNING_TOTAL_TUNER` kill the tuner; (c) the true-diameter size-inversion + the `SIZE_SOLVER` kill the size-proxy; (d) the exact-value-dominant mix + the `ROTE_ORDER_SOLVER` kill the rote-order proxy (the critic's deepest); (e) value-graded + `GRADE_BY_VALUE_NOT_IDENTITY` honor equivalence; the gate proves penny-count + running-total + size + rote-order + brute-tapper solvers ALL fail while the denomination-value oracle passes.
