## Why three faces are HANDWRITTEN (the per-face exemplar)
nt20-C ships ONE exemplar rule per locale (`bank.exemplar`), and every face fans by rule through the base's `unitAxis`. The en exemplar **magic e is a split rule** (`c[a]k[e]`): it has no letter pair (`pair:null` on the base — the base builder already read §3 as refusing its F2/F4) and no plural form. A Which One? / Sort / Plural page on magic e is therefore a REFUSAL, and a face whose exemplar refuses it would have no en deck at all. The honest mechanism: **`exemplarFor(bank, face)` = the locale's exemplar when it carries the face, else the first rule in bank order that does** (en: choice/bins → `c-k-ck`, plural → `y-ies-f-ves`; detective/anchor keep magic e), `unitsFor(bank, face)` = the carrying rules only (so a wave's `unitsPerType` never asks a face for a rule it refuses), and `{UNIT}` = `rule.pairHead` on the pair faces ("c or k"), `rule.head` elsewhere. That is a function-valued `unitAxis`, so `_FACE-BRIEF` rule "HANDWRITTEN spec" applies to G2-324 / G2-326 / G2-328; G2-325 / G2-327 are rows. The gate asserts `faceSpec.unitAxis.exemplar('en') === exemplarFor(bank, face)` for all five and that the base's `units()` lists no plural-form rule.
