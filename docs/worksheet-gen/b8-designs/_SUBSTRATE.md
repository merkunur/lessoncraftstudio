## The maze engine (prototype, `%TEMP%\hm\proto\proto1.js` → `p7.png`, LOOK at it)
- Topology = a seeded perfect spanning tree (DFS) over a jittered 6 × 7 point grid; corridors = the tree split into chains at nodes of degree ≠ 2, each chain smoothed (Catmull-Rom through the nodes + a wobbled midpoint), rendered as an OUTLINE stroke (corridor W + 7) under a FILL stroke (W). All outlines before all fills → junctions merge cleanly, the hand-drawn road of the samples.
- Measured on p7: W = 0.46 × cell (≈ 42 px) reads as a friendly road; it leaves thin "islands" where scene art can sit. The engine will add: corridor width per face, island size control (larger cells and fewer nodes give big islands for art), the start/goal OUTSIDE the maze at its mouths, tunnels/streets/river variants (same graph, different paint), and a clearance rule (non-adjacent centrelines ≥ W + outline + 10).
- Correctness is proved twice: by construction (a tree: one route) AND by a raster oracle in the rendered page (flood-fill from start reaches goal; walling any solution edge disconnects it).
- **Oracle prototype MEASURED (`%TEMP%\hm\proto\oracle.js` + `test-oracle.js`, 3 seeds):** control reachable, 29/29 · 23/23 · 21/21 solution edges are bridges (unique route); poisons all caught: a leak corridor creating a second route (1 · 4 · 17 non-bridges), a dropped solution chain (unreachable), corridors × 2.3 wide merging walls (28 · 23 · 21 non-bridges).
- **Branchiness knob MEASURED (`gen.js make({newest})`, growing-tree algorithm, 6 × 7 = 42 nodes, start = top-left node, goal = bottom-right, 200 seeds):**

  | newest (1 = DFS, 0 = Prim) | solution nodes | dead ends | choice points on the route |
  |---|---|---|---|
  | 1 | 22.6 | 6.0 | 2.2 |
  | 0.75 | 16.7 | 8.6 | 4.0 |
  | 0.5 | 14.4 | 10.5 | 4.7 |
  | 0.25 | 13.1 | 12.0 | 5.2 |
  | 0 | 12.3 | 11.9 | 5.2 |

- **Island placement prototype (`%TEMP%\hm\proto\scene1.js` → `s5.png`, LOOK at it):** 5 × 6 nodes in a 675 × 720 body, corridor W ≈ 0.34 cell (≈ 37 px) + 4 px edge, a distance field from the corridors (+ 7 px margin) and the frame; the largest inscribed disc gets the next library drawing. Result: 10 drawings placed at 70-83 px, none touching a corridor. Lessons: (a) a 5 × 6 jittered grid still reads slightly square, so an organic layout (Poisson field) is wanted for the curvy faces; (b) art on islands is ~80 px, so a scene that needs BIG art (a castle, a house) must reserve it a zone the maze avoids (a keep-out region before the maze is generated); (c) start / goal sprites must enter the distance field (the prototype's chicken overlaps the start dog); (d) the door (`around the house`, mid-century) next to cute farm animals proves the style-family rule.
- **Organic topology prototype (`%TEMP%\hm\proto\gen2.js` → `o4.png`, `o9.png`, LOOK):** Poisson-disk points (r = 92 px) in the body minus keep-out discs → Gabriel graph (planar, no crossing corridors) → edges meeting at < 55° pruned → growing-tree spanning tree (newest 0.6) → smooth chains. MEASURED over 40 seeds with a 120 px keep-out disc: **oracle failures 0/40**, ~30 nodes, ~12 on the route, ~7.5 dead ends. Reads hand-made, not gridded; a keep-out disc holds a 190 px hero drawing (the horse in o4). Lessons: (e) size library drawings by a REAL-WORLD size class (horse > sheep > rabbit > flower), never by island size (o4's rabbit is tiny beside the sheep); (f) no noun twice in one scene (o4 shows two horses).
  DFS = long winding "river" routes with few choices (good for PreK/K tracking); low `newest` = many short dead ends and real choices (G1+). Start / goal can also be placed at the tree's diameter ends to lengthen the route.

## The interactive screen: `trace-path` mechanics PROVEN (prototype `%TEMP%\hm\proto\trace-runtime.html` + `trace-robot.js`)
Bundle = nodes in % of the stage, edges each with ~11 curve samples taken from the drawn chain paths (`getPointAtLength`), routes `{start, goal}`. The child presses near the route's tip (radius max(44 css px, 13 % of stage width ≈ 90 page px)); moving along an incident edge draws partial ink; passing 92 % of it advances the tip; moving back along the previous edge retracts. Measured with real mouse drags (puppeteer) at 360 and 768 px: CONTROL (the solution) → "You did it!"; a straight drag start→goal across the walls → only legal corridor ink, tip stuck mid-maze, Check fails; a drag into a dead end → fails; dead end + retract + finish → passes. Open for designer C: ink colour and width, start / goal markers on screen, route colours, celebration, keyboard / screen-reader path (a "next junction" button row is one option).
