# nt20-C design studio brief — read this FIRST, then `_SUBSTRATE.md`, then `_PANEL-FINDINGS.md`

You are one expert on a four-role studio designing ONE printable worksheet TYPE for K-3 (ages 5–10) with **six faces**: the base page plus five pedagogically distinct variations. The type will be rebuilt natively in 11 languages (en de es pt fr it nl sv da no fi) and every face will be published as a real PDF worksheet + an SEO landing page. The operator's standard: *"educational materials for a certain age group are meaningful only if they are top quality in all senses — unless they are top quality it is only waste of time"*. Nothing is built in this phase; your output is a DESIGN precise enough that an engineer builds it without asking you anything, and a native panel rebuilds it without guessing.

## The generator you are designing for (facts, not prose)

- Headless HTML/SVG generator at `scripts/worksheet-gen/`. Page box **703×945 CSS px** (186×250 mm, the A4∩Letter box) = header (title + name/date) + instruction strip (coral star badge + ONE sentence ≤ ~150 chars) + body ≈ **703×760 px** + footer. NOTHING may overflow (QA lint hard-fails); no text under 9 px; every page must read as one calm, generous page — whitespace is a feature.
- Palette = tokens ONLY (`primitives/_tokens.js`): cream `#FBF3E4` page/cards, creamDeep `#F5E9D2`, teal `#146B5E` ink/frames, tealSoft `#DDEBE8`, coral `#F2784B` accent, coralSoft `#FBE3D8`, ink `#3A3530`, inkSoft `#8A8276`, white, grid `#C8BFAE`. Colouring legends may use the 8 `codeColors` (red blue yellow green orange purple brown pink). Fonts Baloo 2 (display/numerals) + Nunito (body). Any other hex fails the palette lint.
- Density floors: **K min element 56 px / answer numeral 30 px / 4–8 items · G1 44 / 26 / 6–12 · G2–G3 36 / 22 / 8–16.**
- The child writes with a PENCIL: answer boxes are dashed coral (`answerBox`), tracing = solid model + dashed hollow (`strokeWordLane`/`strokeGlyphLane`), handwriting on school lines (`schoolLines`/`rulingBlock`: baseline + dotted mid + top; glyphH ≥ 24 at G2-3, ≥ 40 for K whole words).
- **The answer is NEVER printed on the page.** Every item has exactly ONE correct solution (verify() re-derives it from `data-lcs-*` stamps) unless the page is explicitly open-ended (writing templates), in which case there is no verify() and only the layout lints apply.
- Pictures: ~1,500 transparent object pictures (see `_SUBSTRATE.md` for themes + counts). They can be scaled, mirrored, rotated ±8°, cloned, greyed (opacity), crossed out (coral X). **No recolouring, no scene/background art** — a "scene" is composed from objects. BW (line-art) themes exist for colouring pages only.
- Words: the picture vocabulary stores **singular, plural (+ gender code)** per locale, nothing else. Every other word form (case, article, adjective agreement, verb form) must be authored by the native panel as a literal in a data bank; **the code substitutes stored literals and never inflects**. Slots in frames are `{noun}` `{name}` `{n}` `{color}` `{ordinal}` `{position}` …; two `{name}` in one frame get two different names; `{name}` repeats, never a pronoun (gender underivable).
- Literacy data with a correctness guarantee: `approved-words-<loc>.json` (the phonics safety pipeline): per word `{key, word, split:['ei','chel'], count, chunks}` verified by ≥3 independent sources per locale — the SYLLABLE split is verified in all 11; the per-grapheme `chunks` layer (`[['ei'],['ch','e','l']]`) exists ONLY in de/nl/sv/no (elsewhere `chunks` = a flat copy of `split`; see `_SUBSTRATE.md`). **Any page that shows a syllable split or a grapheme segmentation reads THIS file, never the raw vocab, and refuses words absent from it** (§20.5).
- Locale-neutral seed: the SAME numbers/pictures render in all 11 locales; only words change. Text runs 30–40 % longer in de/fi/pt than en — leave room. Three difficulty levels d1/d2/d3 per face; **the wave publishes d2 only**, so d2 must be the best page and every d-level claim in copy must describe a page that ships.

## The six faces — the variation doctrine (each rule cost a real defect in nt20-B-VAR)

1. **A theme swap is never a face.** Themes are fanned by the wave as an orthogonal axis. A face must change what the child DOES or LEARNS.
2. **A face must differ from the base in its RESOLVED config at the shipped level** (`tools/gate-variation-distinct.js` compares `difficulty[2]` of the face against the base's published d2 — identical config = the published base deck with a new title = REJECTED). Re-labelling the base's unpublished d1 or d3 as "a variation" is allowed ONLY if that level is a genuinely different teaching move (it usually is not; say so).
3. **Demand-weighted, honest ceiling.** Design exactly 5 variations, but if a face cannot be filled by a locale's data (e.g. pool too small, grammar makes it a non-task), the face is REFUSED for that locale — recorded, never faked with fillers. A face that is unbuildable in ≥4 locales is not a face; propose another.
4. **Each face owns a distinct QUERY FACE** (a range, a scaffold level, a sub-skill, a notation, a step) so landing pages do not cannibalise: the base owns the bare genre head; each variation adds ONE distinguishing element to the head. Never two faces whose titles differ only by an adjective.
5. **PARAM before CODE.** A PARAM face = `{...base.difficulty[src], ...overrides}` with no new build code (near-zero regression risk). A CODE face = a named additive knob on `build()` + a `verify()` branch, stamped ONLY when declared so the base stays byte-identical. Say which each face is.
6. **A guard is keyed on the CONFIG, never on the level index** (a face re-points d1's config into d2 — a guard on `difficulty === 1` is blind).
7. **Quote numbers from the resolved config or the render, never from the base's table**, and check the locale POOL can reach a configured bound (sv frames never reach 6 tokens even if `maxTok:6`).
8. **The description window is two-sided:** the meta description = `"Free printable {TITLE} … {LEVEL}. {MIDDLE}. …"` where MIDDLE is the LONGEST candidate that fits 120–170 — the face's instruction competes with the family skill sentence; too long overflows, too short loses. The instruction must say what is different about THIS page.
9. **The instruction is the child's sentence** — one clear imperative a 5–8-year-old understands; the meta is a side effect, never the master.

## Native-rebuild rules (every panel will be held to these; design the SLOTS so they can)
- Titles = the GENRE NAME a teacher in that country types into Google (Silbenbögen, dictée muette, tiokompisar…); never contain the locale's worksheet-word (the engine appends it); ≤70 chars; unique in the band.
- The locale panel may REFUSE a face or re-target it to the locale's own teaching point (fi has no articles; pt "família silábica" ≠ "família de palavras"; sv `÷` is a historic minus — never render it). Design each face so that refusal or re-targeting is a data decision, not a code change.
- Traps to design around: de nouns keep the capital; fi case (a fixed nominative token dropped into a sentence is usually ungrammatical — the panel writes the inflected form out); sv/da/no definite forms (sv `bana`→`banan` = banana); nl de/het + IJ digraph; es/pt/it/fr agreement with an unknown picture noun (prefer frames that never agree with it); emotion adjectives in the vocab are MASCULINE singular in es/pt/it/fr (Enojado/Assustado/Effrayé) — a page about a girl needs the panel's feminine form; the `crane` picture is a machine but the word is the BIRD in 8 locales (`B2_EXCLUDE` already guards it).
