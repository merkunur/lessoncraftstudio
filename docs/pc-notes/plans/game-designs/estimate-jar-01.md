## 2. Concept & creative hook
A wondering sweet-shop **owl** loves to guess jars — "Hoooo many, do you think?" The child is the owl's apprentice. Each jar arrives **clumped + frosted** — you can sense *how full*, you can't tally. You commit a **wish** on the number line… and then the jar **spreads its sweets out** and you count them, one by one, to find out the truth. The thrill is the reveal: *HOW MANY were in there?!* — and your wish was the ticket that made you care.
- **Clump-then-spread is the SPINE (the rework + leak-guard):** the jar is **clumped/occluded** while the child commits the guess (eye-counting is impossible) → on lock, the jar **spreads ALL N items into a countable arrangement** (line/array/circle/scatter) that stays STABLE → the child counts. Locking the guess against an uncountable jar makes "eye-count then slide the star to the actual" **impossible by construction.**
- **COUNT-A-STABLE-SET is the genuine count (the critical rework):** the spread items are ALL present; the child taps **each DISTINCT item once** to count it (the tapped item dims / gets a check; **re-tapping a counted item is a no-op, never +1**; the number word speaks ONLY on a genuine new-item count event). The cognitive act is *find an uncounted item and tag it* — that IS one-to-one correspondence. (The killed alternative — tap-a-jar-button that auto-spawns + auto-positions + auto-speaks each item in order — was a CONVEYOR BELT: any N taps complete it, the engine counts, the child paces a slideshow. Dead.)
- **The wish is reasoned, never a blind flick (the pedagogy's non-hollow requirement):** the 0-20 number line carries **benchmark anchors at 5/10/20**, named as the marker crosses ("more than five… closer to ten"); the clumped jar's **fullness** is the perceptual cue; a **reference jar** anchors the relational rounds. Good guessing is made easier/funner than flicking; a flick is NEVER penalized.
- **The reveal is the thrill (production reinvested here, NOT the compare):** the last item counted → the owl reveals the cardinal big and warm, **fusing the wish and the count**: *"You wondered SEVEN… one, two, three… it was NINE! The jar had MORE than you thought!"* Equal warmth + equal celebration for a perfect guess and a wild one — the narration names **direction** (same / fewer / more), NEVER proximity ("close"/"far") or a distance number.
- **Anti-generic statement:** NOT a guess-and-count worksheet — (a) the count is a genuine count-a-stable-set with one-to-one tracking (not a conveyor; gate-proven by tap-distinct-items); (b) the guess is locked against an uncountable clumped jar (no eye-count leak); (c) the guess is honored-never-graded (no accuracy gradient — the Wish-Wall stores NO gap); (d) the count narratively ANSWERS the wondering (the predict-then-check identity); (e) a board ships only if a **watch-the-movie solver**, a **same-item-repeat (conveyor) solver**, a **slide-to-a-leaked-actual solver**, and an **estimate-graded path** ALL fail the gate while a genuine distinct-item counter passes (§8).

## 3. Core loop & the ≥7 distinct experiences
**Loop (3 stages via `stage`, no inter-stage auto-advance):** **`estimate`** — the clumped/frosted jar (uncountable); the child slides the wish-star on the 0-20 line (benchmarks named as it crosses) → taps **"Lock my wish"** (always honored, any value) → **`count`** — the jar SPREADS all N items into the round's arrangement (stable); the child taps each DISTINCT item once (it dims; the number word speaks on each new count; re-tap = silent no-op) → when all N distinct items are tapped → **`compare`** — the wish-star (persisted, glowing) and the actual-star meet on the same line; the owl fuses wish+count warmly (direction only) → `ctx.correct()` → the jar joins the **Wish-Wall** keepsake. **No fail, no score, no "wrong," no distance number.** A mis-tap (empty space / a counted item) does nothing — no shame.

**The ≥7 distinct experiences — HONEST re-derivation (the critic's catch): distinct = the COUNT ARRANGEMENT or the JUDGMENT, NOT the estimate-prompt reworded.** The estimate FLAVORS (binary / revise-after-a-peek / glimpse) ride as **texture on top**, NEVER counted as experiences (1/2/4/7 of the old list were one act — guess-then-count — with the guess dressed differently). The genuinely distinct child-acts:
| # | Experience (the distinct COUNT-ACT / JUDGMENT) | Render / act | Why it's distinct & non-guessable |
|---|---|---|---|
| 1 ★ | **Count a LINE** (the base) | jar spreads into a row → tap each distinct item L→R | the easiest one-to-one tracking (a clear path); the foundational count |
| 2 ★ | **Count an ARRAY / rows** | jar spreads into a rectangular array → count by rows | a grouping-strategy tracking problem (rows) — genuinely different from a line |
| 3 ★ | **Count a CIRCLE** | jar spreads into a ring → count around, must MARK the start | the circle has no natural end — the child must mark where they began (a distinct tracking demand) |
| 4 ★ | **Count a SCATTERED set (≤10)** | jar spills into a scatter → tap each in place, counted items dim | the hardest one-to-one: no order; the child self-imposes tracking (the standard's ≤10 scattered clause) |
| 5 ★ | **Relational estimate off a reference jar** | jar A already counted + its number shown → guess B's count using A as the anchor → count B | anchored-magnitude reasoning (the estimate uses a KNOWN count) — a distinct number-sense judgment |
| 6 ★ | **Predict-the-comparison** | judge jar B "more or fewer than" the counted reference A (perceptual) → COUNT to verify | a perceptual comparison the count RESOLVES (appearance vs count — the predict-then-check identity at its purest) |
| 7 ★ | **Compare two self-counted jars** | count A, count B (each a full count) → "which had more?" | a comparison built on TWO counts the child produced (informal K.CC.C.6, count-grounded) — distinct from #6 (which predicts before counting) |

- **Honest framing:** seven distinct (arrangement | judgment) child-acts — the four named arrangements (line/array/circle/scattered, which the standard ITSELF treats as the construct) + three relational/comparison judgments. The **estimate flavors are TEXTURE** (a round may use a binary "more/less than 10?" prompt, a revise-after-a-peek, or a glimpse-then-cover — these vary the *wrapper*, never count as the 7). The variety gate keys distinctness on **(arrangement | judgment), EXCLUDING estimate-flavor** (§8, §A.13.60); #5/#6/#7 flagged for playtest (if any two collapse, replace per the standing backlog discipline).
- **Free slice = count-a-line (1) + count-a-scatter (4) + predict-the-comparison (6)** — proves genuine one-to-one + the predict-then-check identity.

## 4. Win-states & juice (no competition)
No timer/score/streak/countdown/**fail-state**/attempts-counter/"X of Y"/**estimate-score**. **Per-distinct-item count:** the item dims/checks + a soft pop + a rising pip + `ctx.speak()` the number word (the count is audible + the child's — bound to a genuine new-item tag, never a bare re-tap). **The reveal payoff (signature, production reinvested here):** the last item counted → the owl reveals the cardinal big, fusing wish+count ("you wondered seven… it was NINE — MORE than you thought!"), the wish-star + actual-star meet on the line. **Non-numeric vessel = the Wish-Wall** (`GameCollection`) — each jar shelved as a keepsake of a WONDERING (the jar + its number), tap to replay its count-chime; **NO accuracy/gap encoding** (the gap is NOT stored or shelved — killing the covert calibration score). **Negative signal = NONE on the estimate (it can't be wrong); the count has no fail** (a mis-tap is inert). **The compare = visual + directional ONLY:** the wish-pin (above the line) and actual-star (below, never colliding); the gap shown as a soft band; narration keyed on **direction (same/fewer/more)**, NEVER a distance number or "close/far" (no accuracy gradient). **Every reveal is equally warm** — a wild wish gets "ooh, the jar surprised us — now we know!", a perfect one gets "you have a good wondering-eye!". The owl WONDERS, never judges. Full-pass keepsake = the filled Wish-Wall → cross-game `GameCollection`. CSS/SVG/WebAudio; reduced-motion; mute-safe (the dim + pip + numeral carry the count when muted).

## 5. Pedagogy
- **K.CC.B.5 instantiation:** the graded act is the child counting a STABLE SET one-to-one — all N items present, the child tags each DISTINCT item exactly once (tracking which are done; re-tap inert). This is the standard's cognition (one tag per object, none skipped/doubled), in the arrangements the standard names (line/array/circle ≤20; scattered ≤10). The closure states the cardinal ("you counted twelve!" — K.CC.B.4 support).
- **THE KEYSTONE RULES (non-guessability):** (i) **COUNT-A-STABLE-SET, NOT A CONVEYOR** — items are all present; reaching the count REQUIRES N distinct items each tapped once (a same-item-N-times / rhythmic-tap solver FAILS; the engine never auto-positions or auto-counts). (ii) **THE COUNT IS THE CHILD'S** — the number word speaks only on a genuine new-item count event (re-tap silent); the whole count is spoken at the reveal (cardinality), never auto-recited as a slideshow. (iii) **CLUMP-THEN-SPREAD** — the guess is locked against an uncountable clumped jar; items spread into the countable arrangement only AFTER lock (eye-count-then-guess impossible by construction). (iv) **THE ESTIMATE IS HONORED-NEVER-GRADED** — `lockGuess` accepts any value; no `estimateCorrect`/distance/score; `ctx.correct()` gates on `counted===actual` INDEPENDENT of the estimate. (v) **NO ACCURACY GRADIENT** — no distance metric, no "close/far", no stored gap, no session "shrinking-gap" aggregate; the compare narrates DIRECTION only.
- **Number ranges + arrangements (pedagogy):** counting is load-bearing when N forces tracking — **N ∈ [6,20] for line/array/circle; N ≤ 10 for scattered** (the standard's hard cap; never scatter >10). Early-K skews 6-12; challenge rounds reach 15-20 in a LINE (easiest tracking at the high end). **5-7 jars** per session (enough for the predict-check loop to be felt; ≥7 distinct per §A.13.60). Arrangement = the standard's named configs (the genuine variety surface).
- **Estimation for K (what's real):** benchmark/comparative ONLY (visual fullness; more/less than 10; relative to a reference jar) — NEVER precise, NEVER accuracy. "How close was I?" is reframed as DIRECTIONAL SURPRISE + growth ("more than you thought — jars surprise us!"), never a metric. Estimation is EXPERIENCE, never assessment.
- **No-shame:** the estimate is structurally un-wrongable (a wish); the count has no fail (mis-taps inert); the reveal is the intrinsic reward; calibration is witnessed-comparison (the Wish-Wall keepsakes), never a mastery score.

## 6. Interaction & UX
- **Runtime: count-a-stable-set + the guarded distinct-item count event.** `count` stage: all N items are spread + present (DOM/SVG). Tapping an UNCOUNTED item → `countItem(id)` tags it (the SOLE count-advancing path): marks `counted.add(id)`, dims/checks the item, advances the running count by one, speaks the number word, ticks the readout. Tapping a COUNTED item or empty space → inert (no +1, no speech). An rAF `_busy` guard serializes the dim animation. **No auto-spawn, no auto-position, no auto-recite, no "count all" button** — the count is N distinct child tags.
- **State separation (anti-cheat + leak-guard):** `getActual()` (= the spread items' count) THROWS unless `stage==='compare'`; `renderableState()` at `estimate`/`count` exposes NO field labeled as the answer and places NO marker at the actual position before compare; the clumped jar at `estimate` is genuinely uncountable; `_trace` records every distinct-item count event for the gate.
- **The estimate slider (finger-robust @280px):** an SVG 0-20 number line; the thumb has a ≥44px grab-rect (visible knob ~44px) snapping to integer ticks; `getScreenCTM().inverse()` for screen→viewBox; `setPointerCapture`; `touch-action:none`; rAF-throttled. Benchmark anchors 5/10/20 = taller ticks + a small icon (a reference scaffold, NOT the answer), named via `ctx.speak` as the marker crosses. The value = real DOM `<text>` in a coral pill. **"Lock my wish"** is a commit (always honored), NOT a correctness Check.
- **The reveal/compare:** the same line; the persisted wish-pin (above) + the actual-star (below, never colliding); the gap = a soft band; narration **direction-keyed only**. NO distance text.
- **Mobile @280px (truth-tested, stage-budget enforced):** each stage owns the full ~248px inner width — **the estimate line + clumped jar / the spread items / the compare markers are NEVER co-resident.** The Wish-Wall is a **between-rounds** screen (or a small drawer), never co-resident with the active jar+line. The 0-20 line labels ONLY 0/5/10/15/20 (minor ticks are hairlines). **Verify N=20 array/scattered packs ≥40px items within 248px** (a 5×4 grid ≈ 200×160 fits) — `audit-game-mobile.js` 280-768 empty (clumped jar + line + thumb) + filled (20 items spread + both compare markers), assert ≥44px controls, no overlap, no over-wide element, AND the N=20 pack.
- **Accessibility:** TTS speaks each number word as each distinct item is counted (`_NUMBER_WORD_HELPERS`); `ctx.announce()` mirrors the estimate value (polite), the running count (assertive), the compare (direction); keyboard path = slider is `role=slider` (arrows ±1, Home/End, Enter=lock), each spread item is focusable (Enter counts it — re-focusing a counted item does nothing); ≥44px; reduced-motion (instant dim, no hop arc); mute-safe (dim + numeral carry the count); not color-only (wish-pin vs actual-star differ by SHAPE + position above/below the line).
