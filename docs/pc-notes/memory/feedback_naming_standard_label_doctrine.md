When an activity's standard is about **naming / classification** (the child labels or sorts by what a thing IS), the on-screen label uses the locale's **FORMAL curriculum term**, NOT a transparent/descriptive paraphrase — provided the native expert confirms the formal term is valid + natural for that grade + locale. Codified as CLAUDE.md **§A.13.61**.

**Why:** transparent labels ("3 sides" / "N lados") undercut the *naming* standard itself — the child is supposed to learn the term. Cross-locale consistency also wants the formal noun. Origin: E3 #1 (2.G.A.1) — the es ensemble proposed "N lados"; the operator ruled the formal "Triángulos".

**How to apply:**
- Positive/category label = the formal polygon/category noun per locale (reuse already-shipped labels; the native expert CONFIRMS validity, can still flag if wrong).
- **Negation label (E3 #2, 1.G.A.1 defining-vs-non-defining):** a "Not a <shape>" box is a FULL literal per-(target, locale) phrase authored by the native expert — de "Keine Dreiecke", es/pt/it plural "No son…/Não são…/Non sono…", fr "Pas des…", nl/Nordic "Geen…/Inga…/Ingen…", **fi partitive-plural "Ei kolmioita"**. NEVER a fill-in `Not a {shape}` token apposition (the [[feedback-activity-i18n-fanout-gender-anchor]] / §A.13.56 case-language trap — Finnish especially).
- Auto-applies to every future naming/classify activity; do not re-litigate per build.
