# Building a homepage natively in a non-EN locale (German, 2026-07-11 · commit 4847c8e6 + hero fix)

Operator: "Build the /de homepage in German — NOT translation. Employ native content writer + linguist + marketing expert. Everything on the page in German. Analyze ALL text FIRST (you often miss labels, buttons, aria)."

**Why /de was ~half English (the non-obvious root cause):** the homepage-v4 redesign introduced a NEW i18n namespace (`homepageV4`) whose keys were authored only in `en.json`. next-intl **deep-merges EN as the fallback**, so every un-authored `de.json` key renders **English silently** — 8 whole sections leaked English while nav/footer (older namespaces) stayed German. **Forward rule: any homepage/section redesign that adds a new i18n namespace MUST author that namespace in ALL target locales in the same arc, or those locales silently ship English.** The stale `de.json` block also carried DEAD keys (old `hero.chipMakers`/`signup`/`embed`) that NO live component read — always confirm which sub-namespaces the components actually consume (grep `namespace: 'homepageV4.X'` + `useTranslations`) and REPLACE, don't merge.

**How to author (worked well):** a **3-agent native ensemble** (§A.13.48) — German linguist + B2C/EdTech marketing + Grundschule (K-3) educator — each rebuilt the full namespace from the EN source; I synthesized by majority + curriculum-correctness (§A.13.61, formal "Fläche oder Körper?" over childlike "flach/räumlich") + **consistency with the site's existing nav terms** (Aufgaben=activities, Werkzeuge=manipulatives, Arbeitsblatt-Generatoren=makers, Zehnerfeld/Zahlenstrahl/Lineal, Lehrkraft-Abo, Lösungsblatt). Lehrplan-FIRST framing (never "Common Core translated"), informal `du`, German number format (`45.309`, `69 $`, `8,99 $`). Big-JSON edit done via a parse→mutate→`JSON.stringify(,,2)` Node script (clean localized diff since the file is 2-space Prettier).

**The easy-to-miss surfaces (the operator's actual complaint) — all needed i18n-izing:**
- hardcoded `alt` on `<img>` (hero worksheets, printable, saved, QR), the ActivitiesMoat English label ARRAY + alt template, hardcoded stat numbers (`45,309`→`t()` so `45.309` renders), `toLocaleString('en-US')`→`toLocaleString(locale)`, language-panel names via `Intl.DisplayNames([locale])` (EN kept endonyms to avoid an /en change).
- shared-chrome `aria-label`s that render on every page: Navigation "Toggle menu", LanguageSelector "Select language", PlatformSearch "Language: {loc}". (PlatformSearch is deliberately next-intl-free → matched its own self-contained map pattern.)
- **Worksheet THUMBNAILS were hardcoded to `/en/decks/<slug>`** → English worksheet images on /de. Fix: `getTypedThumbs(locale, types)` (new export in `lib/showcase-decks.ts`, reuses `candidatesForType`) pulls a real deck of each type IN the visitor's language; EN keeps its hand-picked decks. Pair with THEME-NEUTRAL alts (the German deck's theme varies).

**Layout trap (caught ONLY by the mobile screenshot, body-overflow was 0px):** the hero's 2nd headline span had `whitespace-nowrap` (keeps the coral squiggle word with its phrase). Fine for short English "Watch them play." but the longer German "Sieh zu, wie sie spielen." overflowed the `overflow-hidden` hero at ~390px and **clipped "spielen"** — with NO body horizontal scroll (the section clipped it), so an overflow-metric check missed it. Fix = `md:whitespace-nowrap` (desktop only). **Lesson: for a non-EN homepage, a rendered mobile screenshot is mandatory — longer translations clip inside `overflow-hidden`/`nowrap` containers without tripping body-overflow.**

**Deliberately NOT changed (flagged to operator):** product/activity screenshots (`maker.webp`, `interactive-play/celebrate.webp`, 6 `mini-tools/previews/*.webp`) have English UI baked into pixels — operator chose "ship text now, screenshots follow"; alts already German. Currency stays `$` (Lemon Squeezy USD). Organization JSON-LD `slogan`/`knowsAbout` are INTENTIONALLY English brand-disambiguation fields (2026-06-14 SEO rescue, invisible) — the localized `description` IS passed per-locale; don't localize the slogan as part of a homepage task. Other 9 locales' shared aria fall back to EN (later sweep).

Verified live: visible-layer audit 0 English / 0 raw-key leaks, German thumbnails HTTP 200, /en byte-identical output, desktop+mobile screenshots clean. Related: [[feedback-visual-qa-container-containment]] (screenshot-before-done), [[project-homepage-redesign-2026-07]].

## FRENCH followed the same day (commit for /fr) — the SECOND locale is PURE CONTENT (no code)
Because the German build made every component locale-generic, `/fr` needed **ZERO component changes** — just author `fr.json homepageV4` + the 2 `fr` nav aria keys. `getTypedThumbs(locale)`, `Intl.DisplayNames(locale)`, `LANG_ARIA_PREFIX.fr`, the `md:whitespace-nowrap` hero fix, and the `[NEW]` en.json keys all already existed. **Forward rule: the first locale of a homepage-i18n build pays the code cost; every subsequent locale is a `<lang>.json` authoring job + verify.** Same 3-agent native ensemble (linguist + marketing + professeur des écoles).

French-specific findings worth keeping:
- **Match the EXISTING site's register + terms, don't reinvent.** fr uses **vous** (not tu — the German used du); worksheet = **fiche** (never "feuille de travail"); makers = **Générateurs de fiches**; answer key = **corrigé**; teacher plan = **abonnement Enseignant** (all already in the stale fr copy — grep the existing locale copy for register + locked terms BEFORE briefing the ensemble).
- **Manipulative labels: match the data SoT, not the tool page.** `lib/manipulatives.ts` + `fr.json` call number-line **"Droite numérique"**; the tool landing page (`tool-content/fr.json`) calls it "Ligne numérique" — a pre-existing site split. Homepage used "Droite numérique" (the manipulatives SoT + all 3 agents agreed). Verify manip labels against `lib/manipulatives.ts`.
- **French number format = SPACE thousands separator** (`45 309`, not `45.309`/`45,309`), decimal comma (`8,99 $`), space before `? ! : ;`. Curriculum frame = **programmes officiels** first.
- **Apostrophe: check the FILE's convention, don't assume "typographic is better."** `fr.json` is **746 straight `'` vs 4 curly `'`** — straight is this locale file's convention, so straight `'` in new content is CORRECT (consistent); normalizing to curly would DE-harmonize it. (The plan/agents specified curly; the shipped-file reality overrode it.)
- **The makers headline period trap:** `PillarMakersV4` renders `{h2a} <coral>{h2coral}</coral> {h2b}` with a hardcoded space before `h2b`. English `h2b="worksheet."` is fine (word+period); French can't end on the noun (adjectives follow), so a bare `h2b="."` renders "…autocorrective ." (space-before-period, wrong in FR). Fix without touching the component: put the period at the END of `h2coral` and set `h2b=""` (period is coral, harmless). Applies to any adjectives-follow-noun language (fr, es).
