# Interactive Storybook — Authoring Guide (schema `sb-1`)

The storybook player (`mini tools/storybook*.js`, PixiJS 7.4-legacy) turns
**pure data + assets** into a playable, narrated, page-by-page learning story.
Producing story #2..#N is data work: write the story → drop in scene art →
pick a mechanic per page → wire `story.json` + `strings.json` → validate →
ship. **No engineering per story.**

Reference implementation (copy it): `mini tools/stories/pips-picnic/`.

---

## 1. What a story IS

- Linear pages. **Each page = scene + characters + narration wrapping exactly
  ONE interaction.** Solve the page → the story advances.
- Everything a child sees or hears is a key into `strings.json` (11-locale
  dict shape `{ "key": { "en": "…", "de": "…" } }`). Raw strings in
  `story.json` fail validation.
- **Every spatial fact is data** — zone rects, character anchors, hitboxes —
  in the **1600×1000 design space** (16:10, origin top-left). The player never
  infers a position. Compose the scene in your art tool; read coordinates off
  your canvas.
- Rewards: per-page visual celebration + optional session sticker; story
  completion grants ONE keepsake into the shared collection
  (`reward: { id: "story.<id>", label: {…}, emoji }`). No scores, timers,
  or streaks — ever.

## 2. Files per story

```
mini tools/stories/<storyId>/
  story.json          the story definition (git)
  strings.json        all human-facing text, 11-locale shape (git)
  manifest.json       GENERATED by the validator — do not hand-edit
  scenes/page-NN.webp 1600×1000 q80 (packed by pack-atlas.js; server-only binaries)
  cast/<char>/<char>.base.{json,webp}   poses+idle atlas (always loaded)
  cast/<char>/<char>.clips.{json,webp}  optional full-motion atlas (tier-gated)
  audio/<locale>/<lineId>.mp3           narration, one file per line per locale
  exercises/<exId>/…                    unzipped Storybook Exercise Packages (SEP)
```

## 3. story.json anatomy (see pips-picnic for a complete example)

- `schemaVersion: "sb-1"` — required; the player hard-fails on anything else.
- `locales: ["en"]` — the locales the story SHIPS in. Strings/audio coverage
  is validated against THIS list. Adding a locale = fill every key's locale in
  `strings.json` + record `audio/<locale>/*.mp3` + extend this array. Nothing
  else changes.
- `cast[]` — `{ id, name:"@key", role:"guide"|"companion", atlasBase,
  atlasClips?, poses:[…], clips?:{ <name>:{ fallbackPose } } }`. Exactly ONE
  guide. Every pose/clip referenced anywhere must exist in the atlas
  (validator-checked). Every clip MUST name a `fallbackPose` — that's what
  weak tablets and reduced-motion users see.
- `assets{}` — the manifest every reference resolves through:
  `{ kind: "atlas"|"image", src, size?, vocab? }`. `vocab: "<noun>"` opts the
  asset into the canonical-vocabulary check (any strings key ending
  `.word.<noun>` must equal the `IMAGE_VOCABULARY` singular per locale).
- `pages[]`:
  - `scene`: `{ image: assetId }` (pre-composed 1600×1000 — the DEFAULT) or
    `layers: [{ image, x, y, w, h }]` with explicit coordinates.
  - `characters`: `[{ characterId, pose, anchor:{x,y} /* FEET point */,
    scale, flip }]`.
  - `narration`: `{ gate: "end"(default)|"immediate", cues: [{ id, characterId,
    pauseAfterMs? }] }`. **A cue's `id` is simultaneously its strings.json key
    AND its mp3 filename** (`audio/<loc>/<id>.mp3`) — stable across copy edits.
    Missing mp3 → browser TTS fallback, automatically.
  - `interaction` (exactly one, never an array):
    `{ moduleType, zone:{x,y,w,h}, completionMode:"auto"|"check", hintKey?,
    taskData }`. `taskData` is the module's own schema — validated by the
    module's `validateTask`.
  - `success`: `{ celebration:"burst"|"quiet", sticker?: assetId,
    narrationKey?, holdMs, clip?:{characterId,name} }`.

**Tap floor:** interactive rects ≥ **112 design units** (≈44 real px at the
560px minimum stage). Below 480px stage width the player shows a
rotate-device hint; portrait phones are degraded-by-design territory
(sub-480 spills/small-taps are QA WARNINGS, not failures).

**Wrapped-core containment:** the adapter scale-to-fits a core's stage into
the zone automatically (cores authored with viewport-relative sizing can
never spill a zone) — no per-story tuning needed.

## 4b. Making a module appear in the Studio (`meta.studio`)

The **Storybook Studio** (`docs/storybook/studio-quickstart.md`) generates its
per-mechanic form and canvas drawables from an optional `studio` block on the
module's `meta`. Add it and your module shows up in the mechanic picker with a
form automatically — no Studio code changes (the open-socket principle).

```js
meta: {
  type, version, surfaces, completionModes, minZone,
  studio: {
    label: 'Tap the answer',          // picker card + zone label
    group: 'Look & find',             // picker category
    icon: '👆', blurb: 'one sentence',
    defaults: { … },                  // a VALID starter taskData (born ready)
    fields: [ { key, kind, label, … } ],   // generates the inspector form
    drawables: [ { kind:'rect'|'point', bind, … } ]   // canvas geometry (optional)
  }
}
```

**Field kinds:** `text` (`lowercase`,`maxLen`) · `number` (`min/max/step`) ·
`boolean` (`memberOf:'arr'` = truth ⇒ key ∈ sibling array) · `enum`
(`from:[…]`+`labels`, or `from:'endpoint:/studio/…'`) · `seed` (a Shuffle
button — never shows a number) · `stringRef` (edits strings.json; the Studio
generates + owns an immutable key `<page>.<hint>.<n>`) · `image` (library
picker → creates/reuses an `img.*` asset; `vocabAutofill:true` fills sibling
key+word) · `chips` (token row; `singleChar`, `numeric`, or `from` catalog) ·
`group` (`optional`→nullable sub-object) · `list` (`itemFields`, `keyField`,
`selfList` for bare-value lists) · `correctPick` (radio over a sibling list:
`of:'options', by:'key'`).

**Drawables** put geometry on the canvas: `rect` (a `list` whose items carry a
`rect`; `fields` render in the object-detail panel; `badge` labels it;
`minSize`, `defaultSize`) and `point` (`ordered`, `min/max`, `minSpacing`).
Rect/point coordinates are stored **zone-relative**; the Studio converts to
absolute only at render + edit, and re-encodes them if the zone moves (so
objects stay put on the art).

**No `studio` block?** The Studio still lists the module and gives a guarded
raw-JSON editor for its `taskData`, with live `validateTask` and commit
disabled while invalid. Nothing breaks; the form is just manual.

Bespoke editors (`studio.pattern`, `studio.spotDiff`) exist for the two
modules whose stored shape is a normalized encoding — they get hand-built
inspector widgets instead of generated fields.

## 5. Writing a NEW interaction module (copy-the-pattern)

Register into the socket (`mini tools/storybook-interaction.js` header
documents the full contract):

```js
SBModules.register({
  meta: { type: 'my-mechanic', version: 1, surfaces: ['dom'],
          completionModes: ['auto'], minZone: { w: 480, h: 360 } },
  validateTask: function (taskData, v) { /* PURE — runs in Node */ },
  create: function () {
    return {
      mount(ctx) {},   // render INERT into ctx.surface.el
      start() {},      // player calls after narration — enable pointers
      setEnabled(b) {},
      destroy() {},    // remove EVERYTHING you attached
      showHint() {},   // optional visual nudge
      autoSolve() {}   // optional dev-only QA seam
    };
  }
});
```

Report through `ctx.report`: `success()` (terminal — the PLAYER celebrates
and advances), `miss(info)`, `progress({done,total})`, `answerChanged(bool)`
(check mode). Audio ONLY via `ctx.audio` (`speak`, `pop`, `replayPrompt`) —
never play success sounds (the player queues its chime behind narration).
Honor `ctx.reducedMotion`. All strings via `ctx.t('key')`, images via
`ctx.assets.url(assetId)`. No free keyboard input, no storage, no navigation.

Wrapping an existing hardened activity core: use
`SBLegacyAdapter.wrap({...})` — see `sb-mod-choice-board.js` (check-mode,
`buildTask`) and `sb-mod-sort-bins.js` (auto-mode `detect`) as the two worked
examples. **Never edit the core file** — the adapter fabricates the shell's
`api` seam and records/removes page-level listeners for you.

New module file → flat in `mini tools/` (`sb-mod-<name>.js`) + a
`<script>` tag in `storybook.html` + list it in
`scripts/storybook/validate-story.js` `loadModulesSandbox()`.

## 6. Validate + QA (the definition of done)

```
node scripts/storybook/validate-story.js <storyId>       # fatal gate + manifest.json
node scripts/preflight-activity-routes.js                # route resolution
node scripts/storybook/qa-storybook.js --story=<storyId> # puppeteer: 4 viewports ×
                                                         # every page + reduced-motion,
                                                         # solves each page, screenshots
```

QA gates: zero console errors · no overflow · zone containment · ≥43px taps ·
every page advances · completion + keepsake granted. Screenshots land in
`docs/audit-results/storybook/qa/<story>/` — **look at them, desktop first.**

## 7. SEO surface (one row per STORY)

Add one row to `mini tools/storybook-activities.json` (`tool: "storybook"`,
`params.story: "<storyId>"`, native slugs/titles/intros per locale) — the
existing activities route renders the page, JSON-LD, hreflang. Then:
hand-written `prose["storybook.<id>"]` in
`frontend/messages/activity-content/en.json` + a preview webp at
`frontend/public/mini-tools/previews/storybook.<id>.webp` (the standing
activity-page rule).

## 8. What the native-locale ensembles fill per locale (the known plug)

Per story × locale, the ensemble receives and returns EXACTLY:
1. `strings.json` — add the locale value to every key (narration lines,
   hints, success lines, on-page words). Keys ending `.word.<noun>` MUST
   equal the `IMAGE_VOCABULARY` singular for that noun/locale (validator
   enforces).
2. `reward.label.<locale>` in story.json.
3. The SEO row's `slug/page_title/page_intro.<locale>` (native-language slug).
4. SEP descriptors' `locales.<locale>` blocks (prompt/success/tryAgain/hint)
   for any embedded exercises.
5. Narration recordings: one mp3 per cue id at `audio/<locale>/<id>.mp3`
   (TTS covers gaps until recorded).
Then extend `story.locales` and re-run the validator — full coverage is
enforced mechanically.

## 9. Deploy

Story JS/HTML/JSON ride the normal mini-tools flow (master-sync copies the
`stories/` subtree too). Server binaries (atlases/scenes/audio/exercises) are
pscp'd to `/var/www/lcs-media/mini-tools/stories/<id>/` — see
`mini tools/SERVER-SETUP.md` §Storybook. cp files BEFORE `deploy.sh` builds
(§20.4 rule). Verify live on
`/{locale}/activities/<slug>` after the Cloudflare 5-min TTL.
