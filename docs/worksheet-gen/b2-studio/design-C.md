# Design studio C — sentence / story / real-world pages

Types: #6 G1-242 Read and Color · #13 G1-249 Unscramble the Sentence · #14 G2-274 Fix the Sentence · #15 G2-275 Word Classes · #16 G2-276 Shopping Math · #18 G2-278 Write About the Picture · #20 G3-370 Multiplication and Division Word Problems.

Everything below is measured against the house pages I read (K-243 / G1-213 / G2-253 renders): cream `.ws-card` with the teal corner badge, white inner boxes with the `#F0E4CB` hairline, dashed-coral/grid answer boxes, dot-grid thinking panels, and a LOT of air. Usable body width is **675 px** (page 703 − 2×14 padding); every design below is laid out on a **660 px** stage like K-241/K-239. Body height is designed to **≤ 760 px** (two-line title + two-line instruction worst case). Fonts: Baloo 2 for numerals/badges/tags, Nunito for sentences.

Shared conventions used by every spec here:
- **Sentence text**: Nunito 800, 17-18 px, line-height 1.45, colour `ink`. Never below 16 px on a G1 page, 15 px on a G2/G3 page.
- **Ruling** (= `rulingBlock`, a thin wrapper over `writingRow({xHeight:true})`): `schoolLines` = solid top + dotted mid (`3 5`) + solid base in `grid` colour, exactly as K-239 renders them. Row height `h` and `glyphH` are given per type.
- **Ground truth** rides on `data-lcs-*` attributes; verify() re-derives it inside `page.evaluate` and additionally asserts that **no visible text node equals the answer** (the K-243 "count the printed numerals" idea, generalised).
- **Language-light apparatus**: every word the child reads inside the body comes from (a) the vocab SoT, (b) a per-locale authored bank in `data/b2/`, or (c) `data/color-words.js`. No word is ever generated, inflected, or capitalised by code — the one exception is the *lowercasing* corruption in #14, which is destructive on purpose.
- **New CSS classes** (append to `page.css`, all token colours): `.ws-tile`, `.ws-tilerow`, `.ws-lane`, `.ws-shelf`, `.ws-price-tag`, `.ws-legend-swatch`. Every new full-width layout stamps `[data-ws-content]` so `qa/lints.js CONTENT_SEL` sees it.
- **`codeColors` growth** (4 → 8; K-241 keeps reading the first four — the object gains keys, no key changes):
  `codeOrange: '#DC7C15'` · `codePurple: '#7A4E9E'` · `codeBrown: '#8A5A33'` · `codePink: '#D5679B'`.
  Chosen against cream `#FBF3E4`: orange is more yellow than coral `#F2784B` so the two never read as one hue; purple/brown are dark enough to survive a light-toner laser; pink is a mid-magenta, not a pastel (pastels vanish on cream). All eight are ≥ 3:1 against cream and each pair differs in lightness by ≥ 12 % (so a greyscale print still shows eight distinct swatch tones — but the WORD is the signal, per K-241).

## 0. The shared sentence-bank contract — `data/b2/sentences.js`

One bank per locale feeds #6 (read-and-color), #13 (unscramble) and #14 (fix-the-sentence). The contract is deliberately tiny: a native panel authors **12-16 frames** per locale and proves them on five nouns; the code only ever *substitutes*.

### 0.1 Shape (GENERATED by `tools/apply-b2-locale.js` from `i18n/.draft-b2-<loc>.json` → `data.sentences`)

```js
const SENTENCES = {
  en: {
    nounCase: 'lower',            // 'lower' → vocab form is toLocaleLowerCase'd; 'keep' (de) → vocab capital stays
    endSpace: false,              // fr: true → a narrow no-break space precedes ? and ! ("Où est le chat ?")
    names: ['Mia','Ben','Emma','Leo','Anna','Tom','Lily','Max'],   // reuse FRAMES[loc].names — same pool as G1-213
    colorWords: null,             // optional in-SENTENCE colour forms {red:'röda',…}; null → data/color-words.js
    nounForms: {},                // optional NAMED literal tables, e.g. fi: { partitive: { cat:'kissaa', … } }
    fixLabels: { capital: 'Capital letter', name: 'Names', end: 'End mark' },   // 3 chrome words for #14's checklist
    frames: [
      // kind 'color' — consumed by #6 only. Exactly one {n}, one {noun}, one {color}. {name} optional.
      { id: 'c1', kind: 'color', text: 'Color {n} {noun} {color}.',            noun: 'pl' },
      { id: 'c2', kind: 'color', text: 'Find {n} {noun}. Color them {color}.', noun: 'pl' },
      // kind 'simple' — consumed by #13 and/or #14. Exactly one {noun}; {name} at most twice; no {n}/{color}.
      { id: 's1', kind: 'simple', text: 'The {noun} sleeps on the bed.',   noun: 'sg', uses: ['unscramble','fix'] },
      { id: 's2', kind: 'simple', text: '{name} feeds the {noun} every day.', noun: 'sg', uses: ['unscramble','fix'] },
      { id: 's3', kind: 'simple', text: 'Where is the {noun}?',            noun: 'sg', uses: ['fix'] },
      { id: 's4', kind: 'simple', text: 'Look at the big {noun}!',         noun: 'sg', uses: ['fix'] },
      { id: 's5', kind: 'simple', text: 'I can see two {noun}.',           noun: 'pl', uses: ['unscramble','fix'] },
      …
    ],
  },
  de: { nounCase: 'keep', … frames: [ { id:'c1', kind:'color', text:'Male {n} {noun} {color} an.', noun:'pl' },
                                       { id:'s1', kind:'simple', text:'{name} füttert die {noun}.', noun:'pl', uses:['unscramble','fix'] }, … ] },
  fi: { nounCase: 'lower', nounForms: { partitive: { …every wave-theme noun… } },
        colorWords: { red:'punaiseksi', blue:'siniseksi', … },     // translative — the only form "Väritä … siniseksi" accepts
        frames: [ { id:'c1', kind:'color', text:'Väritä {n} {noun} {color}.', noun:'partitive' }, … ] },
  sv: { colorWords: { red:'röda', blue:'blå', yellow:'gula', green:'gröna', … },   // plural-attributive forms after "Måla 3 katter …"
        frames: [ { id:'c1', kind:'color', text:'Måla {n} {noun} {color}.', noun:'pl' }, … ] },
};
```

### 0.2 Slot types — four, and only four

| slot | resolved from | language-invariant? | allowed in |
|---|---|---|---|
| `{name}` | `bank.names` (rng.pick) — capitalised proper noun | **yes** (always a capital word; never inflected) | color, simple |
| `{n}` | digit **2..6** (never 1 → no singular agreement; never 0) | **yes** (digits; the seed renders the same digit in all 11 locales) | color only |
| `{noun}` | the vocab noun in the frame's declared `noun` form: `'sg'` = `labels(noun,loc)[0]`, `'pl'` = `labels(noun,loc)[1]`, or `'<table>'` = `bank.nounForms[table][vocabKey]` (REFUSE if missing) — then `nounCase` applied | the literal is per-locale, but the CODE never inflects it: pure substitution | color, simple |
| `{color}` | `bank.colorWords[key] ?? COLOR_WORDS[loc][key]` | per-locale literal; the legend shows the dictionary form from `color-words.js`, the sentence shows the bank's form (sv "röda" / fi "siniseksi" / de "blau … an") | color only |

**No `{place}`, no `{art}`, no `{adj}` slot.** Places, articles, prepositions and adjectives are *authored inside the frame text*. Every trap the nt20 panels hit (de dative, fr elision l'/de, it lo/gli/un', sv/da/no suffix definiteness, pt duas/dois) disappears when the only things that move are a capitalised name, a digit, a stored noun literal and a stored colour literal. Panels that need an article before `{noun}` have exactly three safe devices:
1. plural without article — `"Katzen schlafen gern."` / `"{name} ser tre {noun}."`;
2. an invariant article — en `the`, de plural `die` (nom/acc only — the panel is told never to write a dative frame), nl plural `de`, fr plural `les`, es/pt/it plural `los/las` → **no**: es plural articles carry gender — es/pt/it panels use device 1 or 3;
3. a **curated literal table** that *contains* the article/inflection — `nounForms.sgDef = { cat: 'die Katze', elephant: 'der Elefant' }`, fi `partitive`, sv `sgDef = { cat: 'katten', apple: 'äpplet' }` (the sv-render lesson: hand-verified literals, zero morphology; the validator asserts coverage of every wave-theme noun for every table a frame references).

### 0.3 Derived fields (computed by the validator and by `lib/sentence-bank.js`, never authored)
- `tokens` — `text.split(' ')`, then any token that is *only* punctuation (`?`, `!`, `.`, `¿`, `¡`) is merged into its neighbour (fr `"chat ?"` → `"chat ?"` stays one tile; es `"¿Dónde"` is already one token). Unscramble tiles = these tokens after slot fill.
- `end` — last char of `text` ∈ `. ? !`; `open` — first char ∈ `¿ ¡` (es/pt only).
- `caps` — indices (>0) of tokens whose first letter is uppercase in the canonical (names, de nouns, en `I`). `fixCount = 1 + caps.length + 1 (+1 if open)`.
- `words` — token count.

### 0.4 What each consumer needs from a frame
| consumer | frame kind | requirement | how the frame satisfies it |
|---|---|---|---|
| #6 read-and-color | `color` | grammatical with vocab plural + invariant colour device | `{noun}` = `pl` (or fi `partitive`); `{color}` from `colorWords` where the language inflects the adjective |
| #13 unscramble | `simple`, `uses` ∋ `unscramble` | a tile sequence with **one** natural order | panel certifies (that is what `uses:['unscramble']` MEANS); validator: 3..7 tokens, **no repeated token** (case-insensitive) so tiles are visually distinct, ≥ 1 `{noun}` (the picture) |
| #14 fix | `simple`, `uses` ∋ `fix` | canonical capitalised + punctuated form AND a corrupted form | canonical = filled `text`; corrupted = `toLocaleLowerCase(loc)` + strip `end` (+ `open`, + the fr space) — a pure function, `corrupt(canonical)`. d2 needs frames with `caps.length ≥ 1` (a `{name}` or, in de, any noun — de gets Nomen-Großschreibung for free from `nounCase:'keep'`); d3 needs ≥ 2 frames with `?` and ≥ 2 with `!` |

### 0.5 Minimum bank per locale (validator-enforced)
`color` ≥ 3 · `simple` with `unscramble` ≥ 8 · `simple` with `fix` ≥ 10 (overlap allowed; a good frame serves both) · of the fix frames ≥ 6 with `caps.length ≥ 1`, ≥ 2 ending `?`, ≥ 2 ending `!` · both noun forms `sg` and `pl` used at least once (so the picture-noun and the plural-count pages both work) · **total 12-16 frames**. Every frame renders on 5 sample nouns per wave theme with no `{`, no double space, no leading/trailing space, first visible letter uppercase, last char ∈ `.?!`. Poison test: a frame with `{noun} {noun}`, a frame missing its end mark, a fi frame referencing a noun absent from `partitive`, a `color` frame with `{n}` = 1 — all must FAIL; the fi partitive frame on a covered noun must PASS.

### 0.6 The one shared helper — `lib/sentence-bank.js`
`fillFrame(frame, {name, n, noun, color}) → {text, tokens, canonical, corrupted, caps, end}`; `pickFrames(bank, {kind, use, count, rng, needEnds})`; `resolveNoun(bank, frame, nounEntry, loc)` (throws on a missing table entry). #6/#13/#14 import it; nothing else touches the bank structure.

## #6 — G1-242 Read and Color (`read-and-color`, BW themes only, RF.1.4)

### 1. Page concept
Six cream cards. Each card has one short sentence — *Color 3 cats blue.* — and under it a little line-art strip: three cats and a dog (or two dogs), shuffled. The child must actually READ: the noun tells them which animals, the number confirms it, the colour word (looked up in the legend banner at the top, or simply known) tells them what to do. Then they colour — the reward is built into the task. It is delightful because every card is a tiny treasure hunt and the finished page is a colouring page they made themselves.

### 2. Layout (d2)
```
[ legend banner: ■ red   ■ blue   ■ yellow   ■ green   ■ orange   ■ purple ]   660×50, .ws-scene-banner
┌1──────────────────────────┐ ┌2──────────────────────────┐
│ Color 3 cats blue.        │ │ Color 2 dogs red.         │      2 cols × 3 rows, gap 14
│  🐱  🐶  🐱               │ │  🐶  🐱  🐶  🐱            │      card 323×218 (grid rows minmax(0,1fr))
│  🐱                       │ │                           │      icons 66 px, 3 per row, gap 10, wrap
└───────────────────────────┘ └───────────────────────────┘
┌3───────┐ ┌4───────┐  ┌5───────┐ ┌6───────┐
```
- Legend: `.ws-scene-banner` (white, dashed coral) with N entries `[22×22 swatch rx5, stroke ink 1px] [word Nunito 800 17px]`, gap 24, `flex-wrap`; entries = exactly the colours used on the page (6 at d2, in page order), rendered by the K-241 `legendBanner` shape (data-lcs-legend on each).
- Card: `.ws-card` from `cardGrid({cols:2, rows:3})`, badge number, inner column: `<p data-lcs-sentence>` Nunito 800 17px (2 lines max, 48 px reserved) → 8 px gap → strip `<div data-lcs-strip>` `display:flex; flex-wrap:wrap; justify-content:center; gap:10px` of `<img class="ws-icon">` 66×66, each rotated ±6°, with `data-lcs-noun="<vocabKey>"` and `data-lcs-target="1"` on the targets. Strip ≤ 6 icons (2 rows of 3 = 142 px) → card inner 48+8+142 = 198 ≤ 218−24 pad ✓.
- d1: 4 cards 2×2 (card 323×335), icons 96 (2×2 grid max 4 icons), sentence 18 px.
- d3: 6 cards 2×3, icons 56, strip ≤ 8 icons (2 rows of 4 = 120 px), 8-colour legend wraps to two rows (banner 84 px → card 207: 48+8+120 = 176 + 24 ✓).

### 3. Difficulty ladder
| | cards | n (targets) | distractors | distractor nouns | colours | icons |
|---|---|---|---|---|---|---|
| d1 | 4 | 2..3 | 1 | 1 other noun | 4 (red/blue/yellow/green) | 96 |
| d2 | 6 | 2..4 | 1..2 | 1 other noun | 6 | 66 |
| d3 | 6 | 3..5 | 2..3 (strip ≤ 8) | 2 other nouns | 8 | 56 |
Each card uses a **distinct target noun** and a **distinct colour** (so the page needs ≥ cards+2 label-safe BW nouns: `animals bw` 56 ✓, `fruits bw` 14 ✓). Frame per card = `rng.pick(color frames)`; d3 prefers the two-sentence frames (`c2`) when the bank has them.

### 4. Answer-hiding + uniqueness
Nothing on the card marks the targets: all icons are plain BW line art, identical size, no ordering (targets shuffled among distractors), no numbering. Uniqueness = exactly `n` icons of the sentence noun exist in the strip, all others are a different noun → the set to colour is unique and the count `n` is verifiable. verify():
- `[data-lcs-card]` count == d.cards; each card has one `[data-lcs-sentence]`, one `[data-lcs-strip]`.
- `strip.dataset.lcsN == n`, `strip.dataset.lcsNoun == key`, `strip.dataset.lcsColor == colorKey`; `[data-lcs-target]` count == n; every `[data-lcs-target]` has `data-lcs-noun == key`; every non-target has `data-lcs-noun != key`; total icons ≤ strip cap.
- sentence text contains the digit `n` (`(^|\D)n(\D|$)`), contains the rendered plural literal (`strip.dataset.lcsNounText`) and the colour literal (`strip.dataset.lcsColorText`); no `{` left.
- legend: `[data-lcs-legend]` set == the set of `lcsColor` on the page, no duplicate colours, no duplicate target nouns across cards; every `data-lcs-color` ∈ the 8 codeColors keys.
- No `data-lcs-target` is visually distinguishable: assert every img in a strip has identical `width/height` and `opacity == 1` and no sibling SVG (no crosses, no rings).

### 5. Primitives / components
Reuse: `cardGrid`, K-241's `legendBanner` (lift it into `templates/components.js` as `colorLegend({entries})`, byte-identical output for K-241's call), `fileUri` on the BW theme, `COLOR_WORDS` (8 keys), `codeColors` (8). New: none — the strip is flex + `<img>`. `themeAxis: { applicable: true, minNouns: 8, needsBw: true }`; the wave resolver maps `animals → 'animals bw'` (pull `vehicles bw`, `food bw`, `toys bw`, `farm bw` via `pull-themes.js` first; a theme whose BW twin is uncached is skipped by the wave, never faked with greyed colour art).

### 6. Locale slots
Frame kind `color` from `data/b2/sentences.js`: `{n}` digit 2..5, `{noun}` = vocab **plural** (`pl`) or fi `partitive` table (extend `FRAMES.fi.nounForms` — the same table object is shared: `SENTENCES.fi.nounForms.partitive === FRAMES.fi.nounForms`), `{color}` from `bank.colorWords` (sv/da/no plural adjectives `röda/gula/gröna`, fi translative `punaiseksi/siniseksi`, everything else = `COLOR_WORDS`). Legend words = `COLOR_WORDS[loc]` dictionary forms (8 colours added at the fan; de lowercase confirmed-by-convention stays). What a panel overrides: the frame texts, `colorWords`, the fi partitive rows for BW-theme nouns (BW nouns overlap the colour themes' vocabKeys ≈ 80 %; the validator lists the gaps).

### 7. Alternatives
- **A — one big BW scene + a list of 6 sentences.** More "hunt", but the scene needs many nouns of equal size, colouring targets are far from their sentence, and the count becomes ambiguous when a noun appears more than `n` times. Rejected.
- **B — full-width lanes (sentence left, strip right)** like K-239's lanes. Reads well but caps icons at ~56 px because the strip shares the row with the sentence. Rejected for colouring size.
- **Recommendation: the 2×3 card grid** — house look, 66-96 px colourable icons, sentence directly above its own strip.

### 8. Risks
- Long plurals (de *Schildkröten*, fi *Granaattiomenat*, fr *Chauves-souris*) push the sentence to 2 lines — 48 px is reserved; the validator's 5-noun render check + `qa/lints` overflow guard cover the rest. If a bank's longest color frame exceeds 2 lines at 17 px on any wave noun, the type drops to 16 px for that locale (bank flag `compact:true`), never below.
- Distractor visually similar to target (cat vs kitten, bull vs cow): choose distractor nouns from the theme excluding a per-theme `confusables` list in the type (small, hand-authored: `[cat,kitten],[bull,cow,calf],[dog,puppy],[duck,duckling]`).
- B&W print: the legend swatches go grey — the colour WORD carries the task (K-241 precedent). The BW icons are line art already.
- A sentence colour that equals the animal's "real" colour is harmless; a sentence asking to colour a *banana purple* is fine too (it's a reading task) — but the pedagogue may prefer `fruits bw` to avoid "wrong" colours; flagged, not decided here.

## #13 — G1-249 Unscramble the Sentence (`sentence-building`, L.1.1.j)

### 1. Page concept
Four cream lanes. In each: a picture of the thing the sentence is about (a colour icon), a row of word tiles that look like cut-out cards someone dropped on the desk — *bed. / sleeps / the / The / cat / on* — and a proper three-line writing rule underneath. The child reads the tiles, finds the one order that makes sense (the picture nudges them), and writes the sentence on the lines. The tiles look physical (white cards with a flat 2 px "shadow"), which makes the ordering feel like a game rather than a test.

### 2. Layout (d2)
```
┌1──────────────────────────────────────────────────────────────┐
│ [🐱 64]  [bed.] [sleeps] [the] [The] [cat] [on]                │  tile row, wrap, gap 8
│ ──────────────────────────────────────────────── (top line)    │  writingRow 596×64, glyphH 26
│ - - - - - - - - - - - - - - - - - - - - - - - - (mid, dotted) │
│ ──────────────────────────────────────────────── (base)        │
└────────────────────────────────────────────────────────────────┘
× 4 lanes, gap 16, lane = 660 × 156
```
- Lane: `.ws-lane` = `.ws-card` styling (cream, `#F0E4CB` border, r14, padding 12 16), `data-lcs-item`; badge number; inner grid `[64px icon] [1fr]`, gap 14: right column = `.ws-tilerow` (flex, wrap, gap 8, `align-items:center`, min-height 44) then 10 px then `rulingBlock({rows:1, w:596, h:64, glyphH:26})`. Lane height = 12 + 44 + 10 + 64 + 12 = 142 (+ a second tile row = 190 when the tiles wrap). 4 × 142 + 3 × 16 = 616 ✓; with one wrapped lane 664 ✓; every lane wrapped 808 ✗ → see risks (tile font drops to 16 px when the measured tile widths exceed 596 in ≥ 2 lanes; measurement = chars × 9.6 + 26 at 18 px, chars × 8.6 + 24 at 16 px).
- Tile `.ws-tile`: `inline-flex; height 40px; padding 0 12px; background white; border 2px solid teal; border-radius 10px; box-shadow 0 2px 0 #C8BFAE (grid); font Nunito 800 18px ink;` `data-lcs-tile="<index in canonical>"`. The row order is the shuffled order; the canonical index is the hidden ground truth.
- Icon: `fileUri(theme, noun)` 64×64, `data-lcs-noun`.
- d1: 3 lanes (lane 660×200: icon 80, tiles 46 px / 20 px font, ruling h 78 glyphH 30). d3: 4 lanes, tiles 38 px / 17 px font, ruling h 58 glyphH 24, no picture hint? — keep the picture (it is the theme signal), but drop capital + period.

### 3. Difficulty ladder
| | lanes | tokens | first tile shows capital | end mark on a tile | child must add |
|---|---|---|---|---|---|
| d1 | 3 | 3..4 | yes | yes (attached to last word) | order only |
| d2 | 4 | 4..6 | yes | **no** — stripped from the tile | order + end mark |
| d3 | 4 | 5..7 | **no** — all tiles lowercase (names stay capitalised) | no | order + capital + end mark |
Frames: `simple` with `uses ∋ unscramble`, distinct frames per page, each frame's `{noun}` = a distinct theme noun (`rng.sample(labelSafeNouns, lanes)`), `{name}` distinct per lane when present. Shuffle = Fisher-Yates until `order ≠ canonical` **and** `order[0] ≠ 0` (the first tile must not be the true first word — otherwise d1 is solved by reading left to right).

### 4. Answer-hiding + uniqueness
The canonical order is never on the page: only the tiles (shuffled) and empty ruling. verify():
- `[data-lcs-item]` count == lanes; each has `data-lcs-frame`, `data-lcs-canonical` (the filled canonical sentence), one `[data-lcs-prim="writing-row"]`, one `[data-lcs-noun]` img.
- tiles: `tokens(canonical)` multiset == the tiles' visible texts (after the d2/d3 transforms: d2 = last token minus end mark; d3 = every token lowercased except tokens whose canonical index ∈ `caps`); tile order (visible sequence of `data-lcs-tile` indices) ≠ `0..k-1`; `visible[0] ≠ 0`; tile count within the d range; **no two tiles carry the same text** (case-insensitive).
- no visible element's textContent equals `canonical` (the answer is not printed).
- at d2 no tile ends with `.?!`; at d3 no tile starts with an uppercase letter unless its canonical index ∈ `caps` (i.e. names); at d1 exactly one tile starts uppercase and exactly one ends with the end mark.
- every tile's `font-size ≥ 16`.
Uniqueness of the natural order is a **bank property** (`uses:['unscramble']` is the panel's certificate); the machine-checkable proxy is "no repeated token".

### 5. Primitives / components
Reuse: `writingRow` (via new `rulingBlock`), `fileUri`, `labels`. New component `wordTiles({tokens, order, size})` in `templates/components.js` → the `.ws-tilerow` HTML above (no SVG needed; text measures itself). `rulingBlock({rows, w, h, glyphH, starters?})` → stacked `writingRow` SVGs, optional starter text (see #18). CSS additions `.ws-lane .ws-tilerow .ws-tile` in `page.css`.

### 6. Locale slots
`simple` frames: `{noun}` in `sg` (needs an invariant article or a curated `sgDef` table), or `pl`; `{name}` from the bank. de: V2 word order is the teaching point — the de panel authors frames where the verb-second position is the ONLY grammatical order (`"{name} füttert die {noun}."` ✓; avoid frames where a fronted adverb is also grammatical — `"Heute spielt {name} …"` vs `"{name} spielt heute …"` are BOTH fine, so such a frame fails "one natural order" and must not carry `unscramble`). fr: `endSpace` handled by the tokenizer (the `?` merges into the last tile). fi: free word order is real — the fi panel picks frames with a case-marked object so only one order is neutral, or ships #13 with 3-4-word frames where the alternatives are marked; the panel may refuse → fi drops G1-249 (substrate-honest).

### 7. Alternatives
- **A — tiles in a numbered "cut-out strip" at the top of the page + all four rulings below** (a real scissors-and-glue page). Loses the per-sentence picture, and cut-outs do not survive the PDF-on-screen use case. Rejected.
- **B — tiles with a small dashed "slot row" to WRITE each word into a box** (word-per-box). Fine for 3-4 words but the boxes fight long de/fi words. Rejected.
- **Recommendation: lane = picture + tile row + school-line ruling** — writing the full sentence on a real rule is what L.1.1.j asks and what teachers photocopy.

### 8. Risks
- Tile overflow in long locales (de 6 tokens × 12 chars): the tile row wraps (allowed, 1 extra row = +48 px); the build measures tile widths and drops font to 16 px if ≥ 2 lanes would wrap; lints catch the rest.
- Ambiguous orders (fi, de adverb fronting, en "The cat sees the dog" ↔ "The dog sees the cat" with two nouns): the contract allows ONE `{noun}` per frame, and the panel certifies. verify also rejects a frame with two identical tiles.
- A child who cannot decode: the picture is the safety net (shows the noun).

## #14 — G2-274 Fix the Sentence (`capitals-punctuation`, L.1.2.a/b · L.2.2.a)

### 1. Page concept
Six "broken" sentences, each on its own lane like a line from a notebook someone forgot to edit: *emma feeds the cat every day* — no capital, no end mark, the name in lowercase. Under it, a school-line rule. The child plays editor: rewrites the sentence correctly. A tiny checklist banner at the top (three coral circles: **A** capital · **a→A** names · **.?!** end mark) reminds them what to look for without a paragraph of instruction. Delight = the "I found the mistakes" feeling; the page reads as a mini editing desk.

### 2. Layout (d2)

- `[data-lcs-scene] img` count within 5..8; the SET of `data-lcs-noun` on scene imgs == the SET of `[data-lcs-bank]` keys (bijective — every pictured thing is in the bank, nothing in the bank is absent from the picture); bank size == d; bank words == `labels(noun, lang)[0]` after the bank's `nounCase`; no duplicate bank words.
- scene imgs pairwise non-overlapping by ≥ 4 px (bounding boxes) and fully inside the stage; one img has `width ≥ 140` (the hero); ground ellipses count == img count.
- `[data-lcs-prim="writing-row"]` count == rows; `[data-lcs-starter]` count == d.starters, each non-empty and ≤ 22 chars, and each starter's text is NOT itself a complete sentence (no terminal `.?!`).
- no other visible text in the body (the page must not print a model sentence).

### 5. Primitives / components
Reuse: `writingRow` (via `rulingBlock`), `fileUri`, `labels`, `.ws-scene-banner`. New: `sceneStage({theme, nouns, w, h, rng})` in `templates/components.js` (the 3-band placer + ground-ellipse SVG layer, returns imgs with `data-lcs-noun`) — reusable by #20's picture and by future picture-prompt types; `rulingBlock` gains `starters`.

### 6. Locale slots
`data/b2/sentences.js` is NOT used. Starters live in the type's per-locale strings: `SENTENCES[loc].starters` — hmm, keep them out of the frame bank: `data/b2/picture-writing.js[loc] = { starters: { d1:[3], d2:[2] }, nounCase }` (≤ 22 chars each, no end mark, panel-authored: de `Ich sehe` / `Auf dem Bild`; fr `Je vois` / `Sur l'image`; es `Veo` / `En la imagen`; fi `Näen` / `Kuvassa`). Bank words = vocab singular (`nounCase:'lower'` except de `keep`). Nothing else is authored.

### 7. Alternatives
- **A — comic strip: 3 small scenes in a row + 3 short rulings** (sequence writing). Stronger W.2.3 (event sequence) but needs 3× the scene composition and the "story" between panels is invented by the generator → asset-blocked in spirit. Rejected (backlog).
- **B — picture + fill-the-frame sentences** (`There are ___ cats.`) — closer to a cloze than to writing; makes the page language-heavy per locale. Rejected.
- **Recommendation: scene + labelled word bank + starter-seeded ruling** — the classic Schreibanlass / production d'écrit page; word bank removes the spelling barrier, starters remove the blank-page barrier.

### 8. Risks
- A scene of transparent objects on white can still look like a catalogue: the ground ellipses + size bands + one hero + repeats are the four devices that make it a scene; the visual critic must confirm on 3 themes (vehicles is the hardest — vehicles at 3 sizes read as perspective, good).
- Bank labels that are multi-word (pt `caixa de areia`) wrap under a 44 px icon — entry width 100, 2 lines allowed (bank 90 px) — absorbed.
- Rows at glyphH 17 (d3) are the G2-3 minimum for the house (K-239's smallest is 44 lane / 22 glyph at K); a G2 child writes 5-7 mm — 17 px x-height ≈ 4.5 mm; acceptable but the pedagogue may lift d3 to 7 rows × 52.

## #20 — G3-370 Multiplication and Division Word Problems (`word-problems` REUSE, 3.OA.A.3)

### 1. Page concept
Two generous story cards (G1-213's shape, which teachers already know from the G1 page). *Leo has 4 boxes with 5 apples in each box. How many apples?* — and under the story the picture RESTATES it: four little box outlines each holding five apples. For sharing: *Mia shares 12 apples equally among 3 friends* — twelve apples in a strip and three empty dashed boxes the child can deal them into. For grouping: a strip of apples the child can ring in groups of 4. Then the dot panel to work in, the answer box, and a ruled line to write the answer sentence. The child can solve from the text OR from the picture — and the picture is one they can act on with a pencil.

### 2. Layout (d2)
```
┌────────────────────────────────────────────────────────────────┐
│ Leo has 4 boxes with 5 apples in each box. How many apples     │  sentence 18 px, 2 lines (54)
│ does Leo have in all?                                          │
│ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐                            │  groups: n1 boxes 100×58 (tealSoft border)
│ │🍎🍎🍎│ │🍎🍎🍎│ │🍎🍎🍎│ │🍎🍎🍎│                            │  n2 icons 22 px, ≤3 per row
│ │🍎🍎  │ │🍎🍎  │ │🍎🍎  │ │🍎🍎  │                            │
│ └──────┘ └──────┘ └──────┘ └──────┘                            │
│ [ · · · · · · · working dots · · · · · · ]   [ answer 84×64 ]  │  dot panel 92
│ ____________________________________________ (answer sentence) │  writingRow 600×36 glyphH 16
└────────────────────────────────────────────────────────────────┘   card 660 × ~352
× 2, gap 26
```
- Card = G1-213 problem block verbatim (cream, `18px 20px` padding, gap 12): `<p data-lcs-sentence>` → picture box (white, `#F0E4CB` border, r12, padding 10) → `thinkPanel` (dot grid 92 px + `answerBox 84×64`) → `rulingBlock({rows:1, w:600, h:36, glyphH:16})` with a faint 3-line rule (`data-lcs-sentenceline`).
- Picture box contents by op:
  - **mul** (`n1` groups of `n2`): `n1` group boxes in a flex row, gap 10, each `roundedRect` w = min(120, (600 − (n1−1)·10)/n1), h = n2 ≤ 3 ? 44 : 72, r 10, fill white, stroke tealSoft 2.5 — rendered as a `<div>` with the border (no SVG needed) containing `n2` `<img>` 22 px in `flex-wrap`, ≤ 3 per row; `data-lcs-group` on each box, `data-lcs-g` on each img.
  - **share** (`n1` total ÷ `n2` friends): strip of `n1` icons 26 px (`data-lcs-g1`) then, 8 px below, `n2` **empty dashed coral boxes** (`border:2.5px dashed coral`, r 10, h 44, equal widths, `data-lcs-slot`) — the child deals. (n2 ≤ 6 → boxes ≥ 92 wide.)
  - **group** (`n1` total, groups of `n2`): strip of `n1` icons 26 px only (`data-lcs-g1`) in ONE row when n1 ≤ 20 (20×26+19×4 = 596 ✓), two rows otherwise — the child rings groups.
- Heights: 54 + 12 + (10+72+10=92) + 12 + 92 + 12 + 36 + 36 pad = **346**; 2 × 346 + 26 = **718 ✓**. Share/group pictures are ≤ 92 tall by construction (icons 26 + 8 + 44 = 78).
- d1: 2 cards, mul only, `n1 ∈ 2..4, n2 ∈ 2..5` (≤ 20 icons), icons 28, dot panel 104.
- d3: 3 cards compact (sentence 16 px, picture icons 20, dot panel 56, **no answer-sentence line** — the answer box sits beside the dots as in G1-213): 3 × (12+46+8+70+8+56+12) = 3×212 = 636 + 2×14 = **664 ✓**. Types: mul + share + group, one each, shuffled.

### 3. Difficulty ladder
| | cards | ops | ranges | icons per problem |
|---|---|---|---|---|
| d1 | 2 | mul, mul | n1 groups 2..4 × n2 2..5 | ≤ 20 |
| d2 | 2 | mul + share | mul: n1 2..6 × n2 2..6, product ≤ 36; share: total = q·n2, n2 friends 2..5, q 2..6 (total ≤ 30) | ≤ 36 |
| d3 | 3 | mul + share + group | mul as d2; share as d2; group: total = q·n2, n2 2..6, q 2..6, total ≤ 30 | ≤ 36 |
Rejection rules: answer ∉ {n1, n2} (a 4 shared among 2 = 2 gives the answer away as a printed digit); product/total not a printed digit in the sentence (verify); distinct nouns per card; distinct frames per page; every problem keeps its picture (G1-213 critic lock) — that is why products stop at 36 even though 3.OA.A.3 allows 100: a picture-less problem under a "use the pictures" instruction is a broken scaffold. (d3 is honest 3.OA.A.3 at "within 36 with equal-groups models"; the pedagogue may push d3's mul to products ≤ 50 with two-row group boxes — the layout has 20 px of slack.)

### 4. Answer-hiding + uniqueness
Stamped: `data-lcs-problem data-lcs-op="mul|share|group" data-lcs-a="n1" data-lcs-b="n2"`; `[data-lcs-sentence]`; picture: `[data-lcs-group]`/`[data-lcs-g]`, `[data-lcs-g1]`, `[data-lcs-slot]`; `[data-lcs-answer]` on the box. verify():
- answer = mul: a·b; share: a / b (assert `a % b == 0`); group: a / b (same); answer ∈ 2..36, answer ∉ {a, b}.
- sentence contains digits `a` and `b` (G1-213's `(^|\D)n(\D|$)`), does NOT contain the answer as a digit, no `{` left.
- picture: mul → `[data-lcs-group]` count == a, each with exactly b `[data-lcs-g]`; share → `[data-lcs-g1]` == a and `[data-lcs-slot]` == b, every slot empty (no img inside); group → `[data-lcs-g1]` == a and NO slots and NO group boxes (the child draws the rings).
- box `data-lcs-answer == answer`; a `[data-lcs-prim="writing-row"]` per card at d1/d2 (none required at d3); problems ≥ 2.
- no visible text equals `String(answer)` anywhere in the card (including inside SVGs).

### 5. Primitives / components
Reuse: G1-213's block (`thinkPanel` → lifted `dotPanel`), `answerBox`, `writingRow`/`rulingBlock`, `fileUri`, `labels`, `FRAMES.fi.nounForms` (partitive) shared. New: `equalGroups({op, a, b, iconSrc, iconPx, w})` in `templates/components.js` — the three picture shapes above (div/flex + borders, no SVG). CSS: `.ws-groupbox` (white, 2.5 px tealSoft border, r10) and `.ws-groupbox--empty` (2.5 px dashed coral).

### 6. Locale slots
`data/b2/wp-muldiv-frames.js[loc] = { nounForm:'plural'|'partitive', nounCase, nounForms? (fi: share the G1-213 table object), names (reuse), frames:{ mul:[≥3], share:[≥3], group:[≥3] } }`, slots `{name}{n1}{n2}{noun}` exactly as G1-213 (`fillFrame` reused verbatim). Semantics fixed by op: **mul** `n1` = number of groups, `n2` = per group; **share** `n1` = total, `n2` = number of recipients; **group** `n1` = total, `n2` = group size. The container noun (boxes/bags/friends/plates) is authored inside the frame (invariant plural in every locale: de `Kisten`, fr `boîtes`, fi `laatikossa` with `{n2} {noun}` partitive ✓). All locales repeat `{name}` (nt20 gender rule — no pronouns). fi: `"{name} jakaa {n1} {noun} tasan {n2} ystävälle"` — the numeral + partitive pattern already proven in G1-213; the panel extends `partitive` to vehicles/toys nouns (the validator lists the gaps).

### 7. Alternatives
- **A — array picture (rows × columns dots)** instead of group boxes. Cleaner for mul, meaningless for share/group. Rejected as the sole picture; could be a d3 mul variant later.
- **B — three problems per page always (mul / share / group)**. Fits only in compact form; the G1-213 lesson was that two generous problems are the best page. Rejected for d2, adopted for d3.
- **Recommendation: G1-213 shape with op-specific equal-groups pictures** — proven layout, and each picture is *actionable* (deal into boxes / ring groups), which is what separates 3.OA.A.3 from a bare fact.

### 8. Risks
- de/fi sentence length (3 clauses + container noun): 2 lines at 18 px on 620 px ≈ 110 chars — the validator caps mul/share/group frames at 105 chars after filling with the longest wave noun; else the locale's bank sets `compact` (16 px, 3 lines reserved: +22 px, still ✓ at 2 cards).
- Share pictures with n1 = 30 icons at 26 px need two rows (15 per row = 15×26+14×4 = 446 ✓) — the picture box grows to 60+8+44 = 112 (+20 px, absorbed).
- A share problem whose quotient equals the divisor (e.g. 9 ÷ 3 = 3): rejected by `answer ∉ {a,b}`.
- Container nouns that also exist in the theme (en "boxes" is not a vocab noun of animals/fruits/vehicles/toys; but toys has "box"? — the validator checks the frame's fixed words against the theme's vocab plurals so a frame never says "4 boxes with 5 boxes").
