## 2. Concept & creative hook
The child is the **switchman** at Chuffer's railway yard. A load of **N discrete crates** rolls in; ahead, the track forks at a brass switch into a **Left car** and a **Right car**. Chuffer can't haul the load as one heavy car — it must be **split across the two cars**. The child distributes the crates, **reads each car**, states the split (`5 = 2 + 3`), and pulls the coupler — *CLUNK* — Chuffer hauls off, and the route is logged. But the hill-track can only carry the same split once, so Chuffer needs **every distinct way to share N crates** — the child fills Chuffer's **route-book** (the manifest), discovering how MANY ways one number can break apart.
- **The crates are DISCRETE + MOVED, never a length cut (the pedagogy's drift guard):** N countable crates start split between the two cars; the child MOVES crates between cars (drag >360px, steppers ≤360px). `a+b=N` is **unbreakable** — there is NO target sum to hunt (every state is a valid decomposition; trial-and-error is structurally meaningless). The verb is *distribute discrete cargo*, never *cut track*.
- **THE CENTER — the child STATES the parts, the engine never prints them (the critical rework):** the route-card shows **`5 = ☐ + ☐`**; the child READS each car (counts the crates) and **fills both parts**; pulling the coupler banks it ONLY when the stated parts match the actual car-counts (a mismatch → a warm "let's count again — how many crates in the blue car?", never a fail). This is the K.OA.A.3 / K.CC.B.4 cognitive act: **the decomposition is the child's NAMED CLAIM** (the recording requirement), not an equation the engine auto-prints from fiddling. A child who doesn't understand can't bank by moving alone — they must count + state.
- **The switch won't throw for a repeat (Designer A's fight-for) = the dedup:** banking an already-logged unordered way → a warm **mirror-celebration** (not a rejection — see §4) for a commutative swap, or "Chuffer already knows that route — find a NEW way!" for an exact repeat; no new rung, no advance. This makes "more than one way" load-bearing.
- **THE SWITCH-WIGGLE — covariation in the thumb (Designer B's fight-for, the premium soul):** nudge ONE crate across the fork → the child PREDICTS the new split ("if I move one from blue to red…?") → confirms by recounting → sees **left-down, right-up, same N**. This walks the staircase (5+0→4+1→3+2→2+3→1+4) and makes the conservation/covariation insight felt — the structural idea the free single-bond activity can't teach.
- **THE STAIRCASE / route-book (the manifest = the staircase, merged):** the banked ways order themselves so left climbs / right descends — the covariation made visible; the route-book filling is the "so many ways!" abundance.
- **Anti-generic statement:** NOT the free number-bond + a train — (a) the child STATES each decomposition (the cognitive commitment; the engine never prints it); (b) systematic multiplicity (the full family, not one bond) + the switch-wiggle covariation; (c) count-not-length (discrete crates); (d) the coupler is a theatrical, committed act (CLUNK + Chuffer hauls + the rung slides in with a chime); (e) a board ships only if a **one-way solver**, a **re-submit solver**, a **commutative-only solver**, a **zero-padding solver**, an **engine-fill solver**, AND a **mindless-nudger (no-stated-parts) solver** ALL fail the gate while a genuine state-the-parts decomposer passes (§8).

## 3. Core loop & the ≥7 distinct experiences
**Loop:** a load of N rolls in (pre-split, e.g. 1 + (N−1)) → the child **distributes crates** between the two cars (move-not-create; a+b=N always) → reads each car + **states the split** in `N = ☐ + ☐` → pulls the **coupler** → if stated===actual: *CLUNK*, Chuffer hauls forward, the route-card slides into the staircase with a chime, a rung lights → if stated≠actual: warm "let's count again" (no fail) → repeat to find the next distinct way → the round completes when the **full route-book** for that N is filled (all unordered non-zero ways, ordered as the staircase) → Chuffer reaches the station, whistle, `ctx.correct()`. **No fail, no timer, no score, no Check button.** Mis-distributions slide back freely.

**The ≥7 distinct experiences — HONEST re-derivation (the critic's catch: move-crates is ONE act, not three): distinct = the CHILD'S ACT, NOT a crate-move-variant or a different N.** Each carries an **act-type tag** (gate-keyed, §8). The genuinely distinct acts:

|---|---|---|---|
| 1 ★ | **Decompose-and-record** (`decompose-record` — the core) | distribute crates → READ each car → STATE `5 = ☐ + ☐` → coupler banks a distinct way; repeat for the next way | the part-part-whole act + the recording requirement; the multiplicity comes from doing it for distinct ways (the switch won't throw for a repeat) |
| 2 ★ | **Predict-the-covariation** (`predict-covariation` — the switch-wiggle) | nudge ONE crate across → PREDICT the new split BEFORE recounting → confirm left-down/right-up, same N | the conservation/covariation insight in the thumb — predict, not passively watch (the premium soul) |
| 3 ★ | **Hunt-the-missing-rung** (`hunt-rung`) | the staircase shows a GAP (the unordered way not yet found) → construct that specific split | read-then-target / systematic set-completion — distinct from free exploration |
| 4 ★ | **Make-ten / find-the-partner** (`make-ten` — the K.OA.A.4 anchor) | one car is SEALED at k; the child loads the OTHER car to reach N=10 (counts out the partner) | find-the-partner-to-make-ten — the downstream-fluency anchor; a distinct setup (sealed car) + the make-10 strategy |

Full-pass keepsake = the climbed hill + the route-book → cross-game `GameCollection`. ## 5. Pedagogy
- **K.OA.A.3 instantiation:** the child decomposes a fixed whole N into two parts MULTIPLE distinct ways, **stating each decomposition** (the recording requirement), holding N invariant (the part-part-whole schema) and feeling the covariation (one part up → other down) via the switch-wiggle.
- **THE KEYSTONE RULES (non-guessability):** (i) **THE CHILD STATES THE PARTS** — the equation never auto-prints; banking requires the child to READ each car + state `a + b` matching the actual car-counts (the cognitive commitment; a mindless-nudger that never states parts can't bank). (ii) **DISTINCTNESS BY UNORDERED PARTITION** — `{2,3}` and `{3,2}` are ONE for the counter (the commutative cheat closed); both orders may display. (iii) **MOVE-NOT-CREATE** — a+b=N is unbreakable (no target to hunt; trial-and-error meaningless) — but the cognition is restored by (i). (iv) **COUNT-NOT-LENGTH** — discrete countable crates moved between cars; never a length cut (the 1.MD drift guard). (v) **MULTIPLICITY IS THE COMPLETION** — the round completes at the full unordered non-zero set (≥2 minimum, but the GAME target is ALL the ways — if one decomposition completes a round, it's the free activity).
- **Number ranges (pedagogy):** wholes ramp **4 → 10, foregrounding 5 and 10**; **N≤4 are explicit on-ramp/tutorial** rounds; the **graded premium content centers N=6–10** (more ways → real systematic hunt). Zeros (0+N, N+0) are **optional-not-floor** (may display if produced; never count toward the ≥2 floor; both parts ≥1 for the floor). The completion target per N = the full unordered non-zero set (N=5→2, N=6→3, N=8→4, N=10→5), ordered as the staircase.
- **Distinctness from the FREE activity:** the free E18 number-bond does ONE bond (a partner for a given part); this owns the **SYSTEMATIC family + the covariation** (the manifest of all ways + the switch-wiggle + the staircase). The single-bond completion is REJECTED.
- **No-shame:** mis-distributions slide back; stated≠actual is a count-again self-check (never a fail); the mirror is celebrated (not rejected); the coupler is the intrinsic reward. **§20.8 demonstrate-don't-touch:** the catalog pattern-mechanic was the textbook violation; the corrected game ENACTS decomposition (the child states each split) — the gate is the structural proof.

## 6. Interaction & UX
- **Runtime: the move-not-create distribution + the state-the-parts commitment (the one primitive).** `rail-decompose-core.js` holds `{ whole (immutable), a, b (a+b===whole ALWAYS — the child MOVES crates, never creates/destroys), manifest (canonical UNORDERED keys of banked ways), trace[] (append-only child-produced provenance) }`. Mutators: `load(car, ±1)` (move one crate between cars; a,b clamp ≥1), `stateParts(a,b)` (the child's claim), `record()` → `'recorded' | 'duplicate' | 'mirror' | 'mismatch'` (banks ONLY when `stateParts` matches the actual car-counts AND the unordered key is new). **No pair-generator in the public API** — the manifest grows only via `record()` after `stateParts`, which only changes via child `load`/state. Steppers primary ≤360px (`±` per car, ≥44px, kbd-operable); drag enhancement >360px (`pointer-capture`, `touch-action:none`, `getScreenCTM().inverse()`, rAF).
- **State separation (anti-cheat):** `snapshot()` exposes `{ whole, a, b, manifest, complete, universe, statedParts }`; `trace[]` tags every event `{via:'load'|'state'|'record', actType, statedA, statedB, t}` — so the gate can prove the child STATED the parts (not auto-printed) + the act-type distinctness.
- **The cars + the crates (count-not-length, ten-frame array):** each car holds its crates in a **ten-frame-style count-array** (wrap to a 5-wide grid — NOT a horizontal row; 10 crates in a row is impossible at 280px AND the ten-frame reinforces cardinality). The route-card `N = ☐ + ☐` is real DOM `<text>` the child fills; the car-counts appear only AFTER the child states (the confirm), so reading-and-stating is the act.
- **The coupler:** a big brass lever (≥44px); pulling it = `record()`; the *CLUNK* + haul + chime + rung-slide is the committed theatrical moment.
- **Mobile @280px (truth-tested, budget reworked):** vertical stack — whole readout / **the two cars (crates wrap to ten-frame arrays)** / the steppers / the `N = ☐ + ☐` route-card + coupler / **the route-book = the staircase (ONE merged ledger, NOT two panels)**. Below ~360px the staircase/ledger **scrolls below-the-fold** while the cars + steppers + coupler stay above (the active play area). N=10 worst case (2 cars of crates + a 5-rung route-book) fits via the ten-frame wrap + the merged scrollable ledger. `audit-game-mobile.js` 280-768 empty + filled (N=10-full): assert ≥44px steppers + coupler at 280px, no overflow/clip/overlap, the active controls above the fold.
- **Accessibility:** TTS speaks "five is two and three" (`_NUMBER_WORD_HELPERS`) on each banked way; `ctx.announce()` mirrors the distribution ("blue car has two, red car has three"), the state-and-bank, the mirror-celebration, the route-book filling; keyboard path = steppers (±) + the route-card fields + the coupler are all focusable/operable (no pointer needed); ≥44px; reduced-motion (instant coupler/haul); mute-safe (the stated equation + staircase carry it); not color-only (cars differ by position + count, not hue).
