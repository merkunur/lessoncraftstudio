## 2. Concept & creative hook
**Pip the forager builds a Stacking Fence — a bar graph made of slatted pickets, one slot per gathered thing.** The meadow creatures lose track of who gathered how many; Pip (the child) builds the fence + reads the answer right off it.
- **THE CHILD BUILDS THE GRAPH BY HAND (REPRESENT — the binding runtime):** a data set arrives as a TALLY sheet (`||||`) or a scatter of survey-slips; the child reads it and places one unit per data point into its category column — the bar grows by the child's hand (the graph starts EMPTY; nothing auto-files). Correctness = the exact per-category count (a column-swap or an off-by-one fails). **Build-from-tally is the load-bearing form** (decode the count → reproduce the height); loose-labeled-token rounds are a sparse on-ramp (≤1/3 — the critic's F2 kills trivial label-match).
- **THE INTERPRET QUESTION IS RELATIONAL, NEVER "WHICH IS MOST" (the load-bearing read):** "how many MORE leaves than berries?" / "how many acorns and pinecones TOTAL?" / "how many FEWER?" / "is the claim 'leaves beat berries by 2' true?" — the answer is a quantity the child reasons from ≥2 bars (perceiving the tallest bar earns nothing; compare-bars are kept CLOSE in height + a third bar is tallest so eyeballing fails).
- **THE ANSWER IS A DELIBERATE COMMIT, NOT A BRUTE-TAP (the critic's deepest fix):** the child selects an integer chip, then COMMITS ("Pip, that's my answer"); a wrong commit doesn't just beep — it **routes through a guided re-read** (the two referenced bars highlight + Pip speaks "Berries has 7, acorns has 4 — count up from the acorn bar") before the rail re-enables. So tap-until-advance is replaced by read-the-graph-every-time (warm, not punitive).
- **THE DATA IS A GIVEN SURVEY/VOTE (the standard's native context):** "the bunnies voted for their favorite fruit." A spinner appears only as a "we already spun 10 times — here's the record" (a GIVEN completed tally), NEVER a live spin (probability is off-grade).
- **THE PAYOFF:** a correct read → the creatures hop happily, a gathered thing drops into Pip's Harvest Basket (a non-numeric abundance vessel). `ctx.correct()`. Wrong build → the token springs back ("that one's a berry — berries live in the red row"); wrong read → the guided re-read.
- **Anti-generic statement:** NOT spin-tally-read-the-tallest — (a) the child BUILDS the graph (build-from-tally, exact-count; no auto-tally); (b) the interpret is RELATIONAL (more/fewer/total, not which-most; close bars defeat eyeballing); (c) the **deliberate-commit + guided-reread + the `BRUTE_TAPPER` gate solver** kill the brute-tap-the-chips cheat (the critic's deepest, program-wide fix); (d) INTERPRET operands live ONLY in the graph (the pile cleared — no graph-as-decoration); (e) the gate proves read-tallest + auto-tally + count-one-bar + **brute-tapper** solvers ALL fail while the build-and-read-relationally oracle passes.

## 3. Core loop & the ≥7 experiences (REPRESENT + INTERPRET, distinctness in the COGNITION)
**Loop (`stage`: read-the-data → BUILD the graph → INTERPRET):** a tally/survey arrives → the child builds the fence (one unit per point; exact per-category count) → the source data is CLEARED (the graph is now the only data surface — the critic's F3) → a RELATIONAL question → the child selects + COMMITS an integer (or taps the two bars / a true-false verdict) → a wrong commit → guided re-read; a correct one → Harvest Basket + `ctx.correct()`. **No timer/score/streak/countdown/fail/attempts/"X of Y".** Order-only reshuffle.

**The ≥7 distinct experiences (the critic's F9 — REPRESENT forms + INTERPRET cognitions counted SEPARATELY; distinctness in the cognition, NOT the skin):**
| # | Experience (`cog`) | Verb | The child's act | Why genuinely distinct |
|---|---|---|---|---|
| 1 ★ | **build-from-tally** (`build-tally`) | REPRESENT | decode `||||` → place that many into the column (height = count) | symbolic→quantity (the load-bearing REPRESENT) |
| 2 | **picture-graph build** (`build-picture`) | REPRESENT | one ICON per data point (iconic 1:1) | a distinct representational form (icon vs scaled bar) |
| 3 ★ | **how-many-more** (`more`) | INTERPRET | read two bars, find the gap | the signature relational compare (close bars; not tallest) |
| 4 ★ | **how-many-fewer** (`fewer`) | INTERPRET | the gap from the SHORTER bar (parse "fewer") | opposite direction + word-parsing |
| 5 ★ | **how-many-total** (`total`) | INTERPRET | sum two bars (put-together) | relational addition across categories |
| 6 ★ | **is-the-claim-true** (`verify`) | INTERPRET | a stall claims "X beat Y by 2" — true/false from the graph | relational verification (a distinct judgment shape) |
| 7 ★ | **fix-the-wrong-graph** (`fix`) | META | a bar is off-by-one / a token mis-sorted — find + correct | error-detection over the data↔graph correspondence |
| 8 | **match-the-graph** (`match`) | META | given a data set, pick the graph that represents it (among foils) | validate a representation (no build) |
- **Honest framing (pedagogy + critic F9):** REPRESENT forms (build-tally, picture-graph) and INTERPRET cognitions (more/fewer/total/verify) are counted SEPARATELY — NOT "2 forms × 2 questions = 6". The genuinely-fresh ones (verify, fix-the-graph, match-the-graph) carry the meta-cognition. **CUT for v1 (the critic's Fork B): which-two-make-the-third** (too hard + ambiguous-answer at K-2; filed v2). **"Which is most" capped ≤1/3 (on-ramp only).** §A.13.60 ≥7 distinct-to-the-child via these cognitions; order-only reshuffle.
- **Free slice = build-from-tally + how-many-more + how-many-total** — proves both verbs + the relational read; the read-tallest + auto-tally + count-one-bar + brute-tapper solvers all fail.

## 4. Win-states & juice (no competition)
No timer/score/streak/countdown/**fail-state**/attempts/"X of Y". **THE HARVEST BASKET (signature):** a correct read → the creatures hop, a gathered thing drops into Pip's basket (`GameCollection` — a growing bountiful heap; NEVER a count). **Warm wrong-handling (no-shame, the critic's F1):** a wrong BUILD placement → the token softly springs back to the pile ("that one's a berry — berries live in the red row"); a wrong INTERPRET commit → NOT a bare beep — the **guided re-read** (the two referenced bars highlight + Pip speaks the scaffold "Berries 7, acorns 4 — count up from the acorn bar"), then the rail re-enables (the chip ORDER reshuffled so positional memory gives no signal). NO red, NO buzzer, NO attempts-counter — infinite warm tries, each routed THROUGH the graph-read. Discovery beats (the first build, "help a friend read theirs") use `ctx.advance()`. `ctx.correct()` only on a correct deliberate commit → auto-advance. CSS/SVG + TTS; reduced-motion → units appear instantly + the guided-reread is text; mute-safe (the table-mirror + announcements carry everything).

(vii) **given survey/vote data** (no probability).
- **§20.8 demonstrate-don't-touch (the critic's headline):** as a brute-tappable-chip / auto-tally / read-tallest design it TOUCHED 2.MD.D.10 (a child enumerates the answer chips + label-matches the build — zero graph-reading; the gate blind to the enumerator). As a deliberate-commit + build-from-tally + relational-read + operands-only-in-graph design it DIRECTLY INSTANTIATES both verbs (building the graph + reading it relationally is the only path). The line is exactly: the answer is committed (not enumerated) + the operands live only in the graph. The gate (brute-tapper + read-tallest + auto-tally + count-one-bar all FAIL; the build-and-read oracle PASSES) is the machine-checked proof.

- **Grade fit:** Grade 2; single-unit integer scale; 2-4 categories; bars ~3-10; compares/totals within ~10-20 (easy — the difficulty is the read). Given survey/vote; picture + bar both.
- **No-shame:** the bountiful basket is the reward; wrong builds spring back; wrong reads get a guided re-read (never a fail); Pip never red-X'es the child.

## 6. Interaction & UX
- **Runtime: read-data → BUILD → (clear pile) → INTERPRET (commit).** `graph-it-core.js` holds the round `{ id, cog, kind ('build'|'interpret'), data:{cat:count}, source ('tally'|'survey'|'icons'), built:{cat:0...}, question:{type ('more'|'fewer'|'total'|'verify'|'fix'|'match'), a, b}, expectedAnswer (recomputed from live counts, NEVER stored) }` + `placeOne(cat)` + `builtMatchesData` (EXACT per-category) + `commitAnswer` (deliberate) + `expectedAnswer`. **The answer = `f(build the graph + read it relationally)`, never `f(read the tallest)` / `f(auto-tally)` / `f(count one bar)` / `f(tap chips till accepted)`.**
- **State separation (anti-cheat):** `snapshot()` exposes `{ cog, kind, graph (built counts; at interpret the source pile/tally CLEARED), question, answerRail }`. `facts()` exposes per-round `{ childBuildsGraph (built starts empty, only placeOne mutates), builtIsExactPerCategory, representRequiresDecode (build-tally; trivial-1:1-labeled capped ≤1/3), interpretIsRelationalNotTallest, barsCloseOnCompareRounds, interpretDataOnlyInGraph (pile cleared), answerFromGraphNotStored, interpretRequiresDeliberateCommit (===true), wrongCommitRoutesGuidedReread (===true), interpretResistsBlindEnumeration (===true), answerDistributionSpread, singleUnitScale, integerCounts, whichMostCapped (≤1/3) }`.
- **Build + commit:** BUILD = tap a category source-chip → `built[cat]+=1` + a unit appends + announce "Star bar is now 3" (drag is an enhancement, never the only path); BUILD auto-advances on `builtMatchesData` (placement is self-evidently a move). INTERPRET = select an integer chip (or tap two bars / a true-false verdict) → a deliberate **commit** (NOT a forbidden Check button — the Games-38/41/46 deliberate-commit; the only feedback is the warm result or the guided-reread, never a retry-checker).
- **Mobile @280px (the critic's F6):** **PHASE the UI** — BUILD phase = graph + source-chips + basket (no answer rail); INTERPRET phase = graph + answer rail (source-chips hidden — needed anyway per F3). **Horizontal bars at the narrowest breakpoint** (categories as rows, bars grow rightward, axis along the bottom — kinder to 280px + maps to the table-mirror 1:1); ≥44px chips/bars; the integer rail wraps. `audit-game-mobile.js` empty/mid-build/interpret at 280-768.
- **Accessibility (the critic's F7 — proven equivalent for BOTH verbs):** the accessible graph = a visually-hidden live `<table>` mirror (category+count rows; the SVG plot `aria-hidden`). SR/keyboard child BUILDS via source-chip `<button>`s (each placement updates the table cell + a polite-live announce "Star bar is now 3"); READS via the table rows + a tabbable integer answer rail (real `<button>`s, `aria-label`=the integer); "how many more" = read two rows + commit the difference. The **guided re-read** is emitted to the same live region (the two bar counts spoken). Reduced-motion → instant. Mute-safe. Not color-only (categories differ by shape+label, never hue alone).

## 8. Runtime mapping + MEASURED build-gate + PER-LOCALE
- **Round descriptor (DATA; answer recomputed from graph counts, NEVER stored):** `{ id, cog, kind, data:{cat:count}, source, built, question:{type,a,b}, whichMostCap, barsCloseOnCompare }`. `makeRounds`: build-from-tally the load-bearing REPRESENT (trivial-1:1-labeled ≤1/3); interpret RELATIONAL (which-most ≤1/3); compare-bars close + a third tallest; INTERPRET operands only in the graph (pile cleared); answer-distribution spread; which-two CUT (v2); single-unit scale 2-4 cats; order-only reshuffle.
- **`verify-graph-it-core.js` (MEASURED — drives the REAL core under the window shim, the `verify-array-core` idiom; HALTS build) — the critic-armed solver set:**
  1. **BUILD-AND-READ ORACLE PASSES 100%:** builds the graph to the exact per-category count, reads the relational answer from the live counts → correct on every round.
  2. **READ-TALLEST solver FAILS:** answers the tallest category/height → wrong on every relational question (close bars; the tallest is never the answer); assert `interpretIsRelationalNotTallest` + `barsCloseOnCompareRounds`.
  3. **AUTO-TALLY-READER solver FAILS:** assumes the graph pre-built → BUILD starts empty, `builtMatchesData([])` false → cannot complete; assert `childBuildsGraph` + `representRequiresDecode`.
