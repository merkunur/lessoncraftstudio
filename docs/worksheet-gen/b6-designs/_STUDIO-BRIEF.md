## The six faces — the variation doctrine (each rule cost a real defect in nt20-B-VAR / nt20-C)

1. **A theme swap is never a face.** Themes are fanned by the wave as an orthogonal axis. A face must change what the child DOES or LEARNS.
2. **A face must differ from the base in its RESOLVED config at the shipped level** (`tools/gate-variation-distinct.js` compares `difficulty[2]` of the face against the base's published d2 — identical config = the published base deck with a new title = REJECTED). Re-labelling the base's unpublished d1 or d3 as "a variation" is allowed ONLY if that level is a genuinely different teaching move (it usually is not; say so).
3. **Demand-weighted, honest ceiling.** Design exactly 5 variations, but if a face cannot be filled by a locale's data (e.g. pool too small, grammar makes it a non-task), the face is REFUSED for that locale — recorded, never faked with fillers. A face that is unbuildable in ≥4 locales is not a face; propose another.
4. **Each face owns a distinct QUERY FACE** (a range, a scaffold level, a sub-skill, a notation, a step) so landing pages do not cannibalise: the base owns the bare genre head; each variation adds ONE distinguishing element to the head. Never two faces whose titles differ only by an adjective.
5. **PARAM before CODE.** A PARAM face = `{...base.difficulty[src], ...overrides}` with no new build code (near-zero regression risk). A CODE face = a named additive knob on `build()` + a `verify()` branch, stamped ONLY when declared so the base stays byte-identical. Say which each face is.
6. **A guard is keyed on the CONFIG, never on the level index** (a face re-points d1's config into d2 — a guard on `difficulty === 1` is blind).
7. **Quote numbers from the resolved config or the render, never from the base's table**, and check the locale POOL can reach a configured bound (sv frames never reach 6 tokens even if `maxTok:6`; a permitted bound a locale's data never reaches is a false claim).
8. **The description window is two-sided:** the meta description = `"Free printable {TITLE} … {LEVEL}. {MIDDLE}. …"` where MIDDLE is the LONGEST candidate that fits 120–170 — the face's instruction competes with the family skill sentence; too long overflows, too short loses. The instruction must say what is different about THIS page.
9. **The instruction is the child's sentence** — one clear imperative a 5–8-year-old understands; the meta is a side effect, never the master. **It names only apparatus that is ON the page** (nt20-C shipped "letter boxes" in 7 locales for a page with none, and "tick" for a page the child circles).
10. **Boundary first.** Every type file opens with a load-bearing **Boundary** paragraph naming the existing ids it must not duplicate (`_SUBSTRATE.md` anti-duplication list) and what the type therefore owns; every face is checked against it.

## Native-rebuild rules (every panel will be held to these; design the SLOTS so they can)
- Titles = the GENRE NAME a teacher in that country types into Google (Lückentext, tangram, Mülltrennung, de fem sinnena…); never contain the locale's worksheet-word (the engine appends it); ≤70 chars; unique in the band. ⚠ A type head that is ALSO a theme slug in `topics-taxonomy.json axes.theme` (`weather`) must be a compound head ("Weather Symbols"; the K-322 `seasons` validator precedent).
- The locale panel may REFUSE a face or re-target it to the locale's own teaching point (fi has no gendered pronoun → number; es `su` is invariant → no possessive face; es-MX sorts waste into 2 bins). Design each face so that refusal or re-targeting is a data decision, not a code change.
- Traps to design around: de nouns keep the capital; fi case (a fixed nominative token dropped into a sentence is usually ungrammatical — the panel writes the inflected form out); sv/da/no definite forms (sv `bana`→`banan` = banana); nl de/het + IJ digraph; es/pt/it/fr agreement with an unknown picture noun (prefer frames that never agree with it); vocab adjectives (`weather/sunny` "Sonnig") are capitalised citation forms, never a sentence word; vocab gender is GRAMMATICAL, not depicted (de Krankenschwester f / Arzt m; en nurse none) — a pronoun page tags the DEPICTED person after opening the picture.
- **No visible copy may claim "free"** (sheet title/instruction, landing h1/eyebrow/body, hub cards). The SEO metadata lead (`seo.words.free_printable`) is another surface and not yours (operator ruling 2026-09-14).
