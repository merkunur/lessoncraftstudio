## 1. Header
- **Standard-facing:** Build It Like Mine · **kid-facing:** Twinsies · **id:** mimic-copy-01 · **family:** mimic-copy (the platform's **FIRST** mimic-copy game — OPENS the family)
- **PRIMARY standard:** **K.CC.B.5 (Kindergarten) — COUNT to answer "how many?" for up to 20 objects arranged in a line, rectangular array, or circle, and up to 10 objects in a scattered configuration; given a number 1–20, COUNT OUT that many objects.** TWO welded halves: (a) **count-the-model how-many** (count a given set), (b) **count-out-N** (produce a set of a stated size). The standard is the two halves together — the spec instantiates BOTH, separately assessed.
- **also_teaches:** K.CC.C.6 (compare two sets — the **count-both-then-judge** slice ONLY; a longer-row-is-more perceptual judgment is a TRAP, never the success predicate) · K.NBT.A.1 (compose/decompose 11–19 as ten-and-ones — the teens rounds) · K.CC.B.4.C (one more — the count-on round).
- **engine:** new `engine-count-twin.js` + `count-twin-core.js` (0 lines to any protected core; the reusable primitive = *a "counted placement event" — one tap → one object → the readout ticks n→n+1 → TTS speaks "n+1"*; generalizes to a mimic-copy / count-and-produce family) · **runtime:** SIMPLE · **per-locale CHEAP (math — numerals universal; reuses `_NUMBER_WORD_HELPERS` TTS)**
- **The cardinality-fidelity call (the pedagogy's emphatic ruling):** K.CC.B.5 is two welded halves and the game must require the COUNTING act in both — counting the model (half a) AND counting out the twin (half b). Subitizing 1–4 is an ON-RAMP scaffold ONLY, **never** assessment-bearing. The build surface is NEUTRAL + LONGER than any N (a fill-everything≠N capacity), so the child can never win by topping-off a pre-sized container.
- **Distinctness — spine = REPRODUCE A MODEL'S CARDINALITY across DECORRELATED arrangements (count the model + count out a matching twin) + the count-out-N-from-a-numeral half.** vs the LIVE **E1 ten-frame** (fills a pre-structured 10-frame — the cells ARE the silhouette; here the build surface is neutral and longer than N, so the count is the only bridge); vs Game 14 Copy-the-Bead-String (K.CC.B.4 — owns ORDER/SEQUENCE; here CARDINALITY, and decorrelated shapes make order irrelevant); vs build-a-buddy (open-ended, no correctness). **The genius constraint: match the MANY, not the picture** — the child's plate is ALWAYS a different SHAPE than the model, so shape-copying yields the wrong count; only the NUMBER bridges.

## 2. Concept & creative hook
A lonely **Twin-Sprite** has made something — a little pile, a string of beads, a ring of stones — and longs for a **TWIN**: not the same *picture*, just the same *many*. The child counts what the Twin-Sprite made, then **builds a twin that has the same number** on their own neutral plate. When the count matches, the two creations **TWIN** — a synchronized wiggle, and a **light-thread snaps taut between them** (the count-bridge the decorrelated shapes hid → "fair twins shine as one").
- **The genius constraint — "match the many, not the picture" (fix #1, #6 reframe):** the child's build plate is ALWAYS a *different arrangement family* than the model (scattered pile of 7 → build a line/ten-frame of 7; a circle of 6 → build a line of 6). **The child does NOT need to understand WHY the shapes differ** — they can't; arrangement-invariance is the exact concept being taught. It teaches by FRICTION: round 1 (the on-ramp) is SAME-shape (line→line) so the child wins by copying and bonds with the mechanic; round 2 BREAKS the shape → shape-copying fails → the recount succeeds → the lesson lands by contrast. Decorrelation is experienced, not comprehended.
- **Win on DONE, never on auto-match (fix, the non-guessability keystone):** there is **NO live "green-on-contact"**, NO `count===n → win` code path. The child must HOLD a target count and DECIDE to stop — tapping **"We're twins!"** (the STOP gesture). That deliberate stop IS the cardinality act ("this many is enough"). The match signal comes ONLY after the declare.
- **Gertie-can't-count — the misconception PERSONIFIED, confined to ONE experience (fix #1, #6):** a clumsy bird, Gertie, grabs a wing-full, copies the model's *shape*, miscounts, and beams obliviously. The child counts properly to fix it. **Gertie appears ONLY in experience 9 (and as the agent of the corrector re-teach) — never a persistent narrator.** She carries the no-shame load for the *fix-the-miscount* act: a wrong count there is GERTIE'S, never the child's.
- **Anti-generic statement:** NOT a count-the-dots + count-out drill in a twinning skin — (a) win-on-declare (the child decides "enough," the engine never signals match live); (b) decorrelated arrangements (shape-copy yields the wrong count → only the number bridges); (c) one-tap-one-object-one-number-word (the child counts, the engine never does); (d) every assessment round N≥6 (subitizing can't carry it); (e) a board ships only if a **silhouette-solver**, a **respond-to-the-nudge hill-climb solver**, a **skip-stage-0 trial-and-error solver**, and a **subitize-only solver** ALL fail the gate (§8).

## 3. Core loop & the ≥7 distinct experiences
**Loop (the flagship, experience 5):** the Twin-Sprite reveals its creation → **stage 0 — count the model:** the child taps each model object; each tap marks it (✓ + a small scale-pop, flies to the tally row; a scattered object MOVES into a counted tray so the un-caught pile shrinks → double-count structurally prevented); the readout ticks n→n+1; TTS speaks each number word. `state.caught` is a **Set** (double-tap a no-op; bulk-ops forbidden). When the child has caught them all, they **commit the count** (the tally → an asserted cardinal: "it's THIS many") — **this assertion is the GATE into stage 1** (no assertion → can't proceed). → **The model is COVERED** (fix #3 — slides under the Twin-Sprite's blanket; a small "peek" chip lets the child re-check, which IS the checking act) → **stage 1 — count out the twin:** on a neutral plate (capacity > N) the child places objects one tap at a time (same counted-placement primitive; the readout ticks; TTS speaks) and, when they judge they have the same many, taps **"We're twins!"** → on declare: placed===model.n → `ctx.correct()` (TWIN: synchronized wiggle + light-thread snaps taut + the tally bridges) ; placed≠model.n → **binary undirected** "not twins yet — let's count again" (fix #1: NO direction, NO magnitude, NO count revealed, NO pairing against the model; the thread simply doesn't form) → the child re-counts their own plate (and may peek the model) and re-declares. **No retry can converge by following a hint, because no directional hint exists.**

**The ≥7 distinct experiences — HONEST re-count (fix #4): distinct = a different CHILD-ACT or COUNTING-STRATEGY, NOT the same "tap to count" with the dots rearranged.** Line and circle are the SAME act ("count along") → collapsed into ONE on-ramp. The genuinely distinct strategies/acts:
| # | Experience (the distinct ACT / counting-strategy) | Render | Why it's distinct & non-guessable |
|---|---|---|---|
| 1 | **Count-along → same-shape twin** (the ON-RAMP — "shape works here") | a line (or circle) model → build a same-family twin; **N≤8, NON-assessment** | the only same-shape round; the child wins by copying → bonds with the mechanic → sets up round 2's contrast. Flagged on-ramp (not scored). |
| 2 ★ | **Count-scattered by MOVING** (distinct counting hygiene) | scattered model (≤8 on small viewports) → build in a track; **move-as-you-count** (caught object relocates → un-caught pile shrinks) | the relocate-to-a-tray strategy structurally prevents double-counting — a different counting hygiene than count-along; decorrelated build family |
| 3 ★ | **Count-array by ROWS** (distinct grouping strategy) | rectangular array (≤4×3) model → build a jar twin | counting by-rows is a grouping strategy, not count-along; decorrelated; N≥6 |
| 4 ★ | **Count-out by PLACING** (half b, model visible→then hidden) — the FLAGSHIP | the §3 loop: count the model, commit, model covers, count out the twin from the held number | requires BOTH halves; the cover (fix #3) forces the child to USE the count they committed; win-on-declare |
| 5 ★ | **Count-out from a NUMERAL — no model** | a bare numeral "7" (DOM) + a neutral plate → count out 7 | the source is a SYMBOL not a set → a genuinely different act; pure count-out-N; subitizing the symbol is impossible |
| 6 ★ | **Build from a HIDDEN number** (the sleepy-model, scaffold-removed) | count the model → COMMIT → the model sleeps under a blanket → build from the held number; peek = explicit "checking"; **N≤10** | memory/commitment IS the act; can't trial-and-error against a visible model |
| 7 ★ | **Fix Gertie's miscount** (the corrector act) | Gertie dumped a SHAPE-matched, WRONG-count pile → the child counts one-to-one + adjusts to make it a true twin | the child CORRECTS a displayed error (someone else's) — the honest one-to-one pairing lives HERE (fix #4b), not on the child's own wrong declare |
| 8 | **Compare two twins** (K.CC.C.6, count-both-then-judge) | two sets → which has more? **the judge answer is LOCKED until BOTH are fully caught/counted** | forces count-both (defeats longer-row-is-more); a genuinely different judgment act |
| — | **Count-on +1** (K.CC.B.4.C, a light later beat) | a partial twin pre-placed (e.g. 6 of them) → "one more to twin!" | count-on from a partial — distinct enough to keep as a closing beat, not a headline experience |

- **Honest framing (fix #4):** the variety is the **child-act / counting-strategy family** (count-along / count-scattered-by-moving / count-array-by-rows / count-out-by-placing / count-out-from-a-numeral / build-from-hidden / fix-a-miscount / compare-both / count-on), NOT arrangement-position re-skins. The variety gate asserts distinct by **(child-act OR counting-strategy)** and **REJECTS arrangement-position-only** as a distinctness source (line vs circle do NOT both count) (§8, §A.13.60). Decks span distinct N and arrangements; `makeRounds` procedural.
- **Free slice = on-ramp (1) + count-scattered-by-moving (2) + count-out-by-placing flagship (4)** — proves both halves + the counting act.

## 4. Win-states & juice (no competition)
No timer/score/streak/countdown/**fail-state**/attempts-counter. **Per-object counted-placement:** spring scale-in + `ctx.sound('pop')` + a rising pip + TTS the number word (the count is audible). **The TWIN payoff (signature):** on a correct declare, the two creations wiggle in unison + a **light-thread snaps taut** + the tally bridges the two → the count-bridge the decorrelated shapes hid. `ctx.speak()` states "Seven and seven — twins!" The **non-numeric vessel** = a **Friendship-Shelf** of twin-pairs holding hands, gaining one pair per round. **Negative signal = ABSENCE + an undirected re-count invite ONLY (fix #1):** a wrong declare → no thread, **binary** "not twins yet — let's count again," NO direction/magnitude/count/pairing-against-the-model revealed; the child re-counts their own plate (peek the model is allowed = the checking act). **`ctx.wrong()` is a soft, information-free state** (re-enable + recount), never a punishment, never a hint. **The counting-hygiene nudge (allowed, distinct from a count-hint):** a *double-tapped or skipped* object may glow as a count-the-act nudge ("you tapped this one twice") — this is about the ACT of counting, **never** "you need one more." **Erase is free:** tap a placed twin-object (≥44px) → it leaves, the readout ticks DOWN. **The corrector re-teach (Gertie only):** the honest one-to-one pairing — Gertie's unmatched object DANGLES with no partner — shown for GERTIE's pile (experience 7), where the child is the corrector, never for the child's own wrong declare. Full-pass keepsake = the filled Friendship-Shelf → cross-game `GameCollection`. CSS/SVG/WebAudio; reduced-motion; mute-safe.

## 5. Pedagogy
- **K.CC.B.5 instantiation — both welded halves, separately assessed:** half (a) count-the-model (the child tags each object, one-tap-one-object-one-number-word); half (b) count-out-N (place exactly N on a neutral plate, declared). The flagship (exp 4) and the hidden-number (exp 6) require BOTH in sequence; exp 1–3 lean half (a) feeding (b); exp 5 is pure half (b); exp 7–9 exercise counting in service of correction/comparison/count-on.
- **THE KEYSTONE RULES (non-guessability):** (i) **WIN ON DECLARE, NOT ON AUTO-MATCH** — no live match-indicator, no `count===n→win`; the child HOLDS a target + DECIDES to stop (the cardinality act). (ii) **DECORRELATED arrangements** — `family(build.arr) ≠ family(model.arr)` invariant on every assessment round → shape-copying yields the wrong count → only the number bridges (defeats shape-matching; NOTE it does NOT defeat subitizing → see iii). (iii) **EVERY ASSESSMENT ROUND N≥6** (fix #2) — subitizing reliably tops out at ~4; N≥6 forces counting in BOTH halves. N≤4 appears ONLY in flagged non-assessment/on-ramp rounds (exp 1). ≥1 round N∈[11,19] exercises ten-and-ones (K.NBT.A.1). (iv) **ONE-TAP-ONE-OBJECT-ONE-NUMBER-WORD + Set-dedup** — double-tap a no-op, bulk-ops forbidden, the count increments solely in the validated handler; the child counts, the engine never does. (v) **STAGE-0 IS LOAD-BEARING (fix #3)** — the model is COVERED before stage 1 and a COMMITTED count-assertion is required to proceed, so the child must build from the number they produced (no trial-and-error against a visible model).
- **No silhouette cheat:** the build plate is NEUTRAL + capacity > N (a ten-frame family tray that holds up to 20 → fill-everything ≠ N); the model's arrangement is never reproduced as a container.
- **Compare (K.CC.C.6):** ONLY count-both-then-judge — the answer LOCKS until both sets are fully counted; never reward a longer-row perceptual guess.
- **Subitizing:** 1–4 is an on-ramp/scaffold ONLY (exp 1), NEVER assessment-bearing.
- **No-shame (fix #1/#4b):** the child's own wrong declare → undirected "count again," the re-teach RE-RUNS the counting act (recount your plate; peek + recount the model) — no direction handed over. The honest one-to-one pairing (the dangling unmatched object) is reserved for GERTIE's miscount, where the child is the corrector of a displayed error. A double-tapped/skipped object may glow as a counting-hygiene nudge (about the act, not the magnitude).

## 6. Interaction & UX
- **Runtime: the ONE primitive — a "counted placement event."** Stage 0: tap a model object → it marks (✓ + scale-pop) and (scattered) MOVES to a counted tray → readout n→n+1 → TTS "n+1." Stage 1: tap the neutral plate → one twin-object materializes → readout ticks → TTS. The SAME primitive on two surfaces. `state.caught` / `state.placed` are Sets/counts incremented only in the validated handler (no bulk path).
- **WIN ON "WE'RE TWINS!" (the STOP gesture), never on contact** — a sticky-bottom coral pill; the only path to `ctx.correct()`/`ctx.wrong()`; there is no live match-channel.
- **Stage time-share is a HARD invariant (fix #5):** stage 0 (model, full size) and stage 1 (build plate, full size) are **NEVER both full-size simultaneously**; entering stage 1, the model collapses to a small **peek chip** (tap = re-check). This is a verified layout state, not a "leans" preference.
- **DOM/SVG — one shared viewBox (CSS-scaled):** L1 model objects (stage 0; scattered = randomized non-overlapping positions, caught objects fly out); L2 the neutral **build tray = ten-frame family** `grid-template-columns: repeat(5,1fr)` (the ONLY layout that holds 20 finger-objects at 280px AND reinforces base-10 for the teens rounds); L3 the **tally-trail readout** (sticky, between model + build) — a **grouped 5×4 / two-ten layout, NEVER a single 20-dot row** (fix #5; reinforces ten-and-some-more); L4 the **numeral** = the child's ASSERTED cardinal (real DOM, from the commit/placement count), NEVER a digit the engine feeds them. The Twin-Sprite + light-thread are SVG.
- **The counted-placement is the source of truth:** the round descriptor has NO `answer` field — `model.n` is the RENDER source for the model that HAPPENS to equal the validated value; there is NO `oninput→if(count===n)win` path. Validity = `placed === count(model the child produced)`.
- **Mobile @280px (truth-tested, fix #5):** vertical stack, never side-by-side. The build ten-frame at 280px ≈ 5 cols × ~44px (right at the floor) — **verify ≥44px filled+empty; for N>10 the second ten-frame SCROLLS rather than shrink cells below 44px.** The **scattered model** density is solved by move-as-you-count (the un-caught pile shrinks as you go → at any instant well below 10; cap scattered N≤8 on small viewports). The **tally-trail** wraps to the grouped 5×4 layout. Sticky readout + sticky-bottom "We're twins!". `touch-action:none`, `overscroll-behavior:contain`. Pass `audit-game-mobile.js` 280–768 empty+filled (incl. the 20-object teens state + the scattered-10 model + both stages).
- **Accessibility:** TTS speaks each number word as the child taps + states the twin equation on success; the tally is `aria-live`; ≥44px targets; not color-only (success = the twin ANIMATION + thread + the tally bridging [structural] + TTS + ✓, never a band tint); keyboard-operable place/erase; reduced-motion; mute-safe.

## 8. Runtime mapping + MEASURED build-gate + PER-LOCALE
- **Round descriptor (DATA; stores ONLY the model + type — NO answer/count digit):** `{ id, type, model:{ arrangement:'line'|'circle'|'scattered'|'array', n, rows?, cols? }, buildFamily (≠ model arrangement family on every assessment round), assessment:boolean (false for the on-ramp/N≤4), source?:'set'|'numeral' (numeral = exp 5, no model), preset?:[objects] (Gertie's wrong-count pile for exp 7), compare?:{a,b} (exp 8, judge locked until both counted), countOnFrom?:k (exp 9) }`. `model.n` is the RENDER source for the model only; the validated value is DERIVED = `count(model the child produced)`. `makeRounds` generates procedurally (arrangement, n; decorrelated build family; N≥6 on all assessment rounds, ≥1 teens).
- **`verify-count-twin-core.js` (MEASURED — drives the REAL core; HALTS build):**
  1. **SILHOUETTE-solver must FAIL:** decorrelation invariant (`family(build)≠family(model)` on every assessment round) + no pre-shaped N-cell container + build capacity > n → matching the model's shape/topping-off the tray cannot win.
  2. **RESPOND-TO-THE-NUDGE HILL-CLIMB solver must FAIL (fix #1 — THE headline, the Game-7/Game-10 analog):** a solver that declares any count, then on a wrong declare reads ONLY the feedback channel and adjusts in the indicated direction, repeating until correct (zero counting) — must be REJECTED. The gate asserts the wrong-declare feedback exposes **NO direction, NO magnitude, NO per-object pairing against the model, NO count** (binary "not twins yet") → the solver cannot converge.
  3. **SKIP-STAGE-0 TRIAL-AND-ERROR solver must FAIL (fix #3):** a solver that never attends to the model (ignores stage 0), then trial-and-errors stage 1 against a visible model — must be REJECTED. The gate asserts the model is COVERED before stage 1 AND a committed count-assertion is required to enter stage 1 → the child must build from the produced number, not trial-and-error.
  4. **SUBITIZE-ONLY solver must FAIL THE DECK (fix #2):** a solver correct for N≤4 and random for N≥5 must be REJECTED at the DECK level (not one round). Achievable only if EVERY assessment-bearing round has model.n≥6 (and a sufficient share that random guessing can't pass by luck). Assert: all `assessment:true` rounds N≥6; N≤4 appears ONLY in `assessment:false` rounds; ≥1 round N∈[11,19] exercises ten-and-ones.
  5. **Validity DERIVED + one-to-one is the child's act:** assert no stored `answer`; success === `placed === count(model the child produced)`; each model object tagged ≤once (double-tap a no-op); the count increments solely in the validated handler (no bulk path); build capacity > targetN (fill-everything ≠ N).
  6. **Decorrelation + on-ramp invariants:** every `assessment:true` round is decorrelated; exp 1 is same-family AND `assessment:false`.
  7. **Compare invariant (K.CC.C.6):** the judge answer is LOCKED until both sets are fully counted (count-both-then-judge; no longer-row shortcut).
  8. **Scattered + teens invariants:** scattered N≤10 (≤8 small-viewport) with move-as-you-count (caught object relocates → no double-count); ≥1 teens round renders ten-and-ones in the tally grouping.
  9. **≥7 distinct experiences by (child-act OR counting-strategy) (fix #4):** assert distinct ACTS (count-along / count-scattered-by-moving / count-array-by-rows / count-out-by-placing / count-out-from-a-numeral / build-from-hidden / fix-a-miscount / compare-both / count-on), **REJECTING arrangement-position-only as a distinctness source** (line vs circle do not both count); order-only reshuffle (pass-2 ≠ pass-1).
  - Plus standing gates: `audit-game-mobile.js` (the model + build ten-frame + grouped tally + sticky readout/pill, empty+filled, 280–768, incl. the 20-object teens + scattered-10 + the stage time-share collapse-to-peek-chip), `audit-game-variety.js`, `audit-no-competition.js` (lcs-shell 0-line; no timer/score/streak/match-indicator), SEO/JSON-LD §21.
