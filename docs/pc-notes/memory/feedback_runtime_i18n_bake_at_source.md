When a standalone deck.html displays runtime UI strings (titles, buttons, modal text, status messages), the canonical architecture is:

**Bake-at-source-time, NOT build-at-runtime:**

1. **STRINGS_ALL literal in INTERACTIVE_RUNTIME_LINES** — each app's source (`REFERENCE APPS/<app>.html`) contains a `var STRINGS_ALL = {en:{...},de:{...},...,fi:{...}};` literal in INTERACTIVE_RUNTIME_LINES with all 11 locales. Generated by `scripts/inline-all-locales-strings.js` (commit `30f21267`). The bake reads `REFERENCE TRANSLATIONS/translations-shared.js` (12 runtimeXxx keys × 11 locales) + per-app `translations-<X>.js` (runtimeTitle × 11 locales) + parses each app's existing English STRINGS dict to preserve key order + per-app keys.

2. **Runtime selects locale from DECK_BUNDLE.contentLanguage:**
   ```js
   var STRINGS = STRINGS_ALL[((DECK_BUNDLE && DECK_BUNDLE.contentLanguage) || "en").slice(0,2)] || STRINGS_ALL.en;
   function T(k){return STRINGS[k]||STRINGS_ALL.en[k]||k}
   ```

3. **Runtime init() force-sets every UI element from STRINGS** — never trust HTML template literals or `DECK_BUNDLE.title || T("title")` short-circuits. Generated by `scripts/fix-runtime-element-textcontent.js` (commit `691ac1c7`):
   ```js
   titleEl.textContent=T("title");
   if(typeof checkBtn!=="undefined"&&checkBtn){var _ck=STRINGS.checkAnswers||STRINGS.check;if(_ck)checkBtn.textContent=_ck;}
   if(typeof resetBtn!=="undefined"&&resetBtn)resetBtn.textContent=T("tryAgain");
   ```

**Element IDs canonical across all 29 apps:** `#lcs-title`, `#lcs-check`, `#lcs-reset`. Variable names: `titleEl`, `checkBtn`, `resetBtn` (wordsearch lacks `checkBtn`).

**Why:** Reads from `window.translations[contentLanguage]` at extractDeckBundle time are FRAGILE (multiple historical failure modes documented):
- Browser cache stale on per-app HTML / per-app translations / translations-shared.js
- translations-shared.js merge race with per-app translations-<X>.js (load-order dependent)
- `js/translations.js` 404 (5 apps reference a non-existent file: code-addition, chart-count, pattern-worksheet, sudoku, draw-and-color)
- HTML template literals like `escapeHtml(bundle.runtimeStrings.checkAnswers)` bake whatever the bundle had at gen time (English fallback when translations didn't load)
- `DECK_BUNDLE.title || T("title")` short-circuits on English bundle.title — `T("title")` never reached

**Why:** Bake-at-source eliminates the entire dependency chain. STRINGS_ALL travels with the deck.html literal — locale selection is purely DECK_BUNDLE.contentLanguage. Every UI element gets force-set in init(); no element relies on the deck.html generation having had translations loaded correctly.

**How to apply:**
- Future runtime UI surfaces (any new HTML element added to deck templates that displays text): include the surface's `id` and a STRINGS key; in init() force-set its textContent from `T(key)`. Never bake the English text as an HTML literal that the runtime won't overwrite.
- Future translation-key additions: add to `translations-shared.js` (≥2-consumer rule) OR per-app `translations-<X>.js`. Then re-run `scripts/inline-all-locales-strings.js` to refresh STRINGS_ALL bakes across all 29 apps. Bump `translations-shared.js?v=N+1` cache-buster as signal.
- TWO-STEP §14.6 deploy required: `deploy.sh` then `update-worksheet.sh` for all 29 served HTMLs (chattr +i protected).

Verified working across all 29 apps × 11 locales by operator on 2026-05-10.

Originating commits: `30f21267` (STRINGS_ALL bake) + `691ac1c7` (init() force-set).
